## 1. 포맷 추가: 이미지·오디오·Markdown·GitHub 저장소
- 날짜: 2026-10-22 · 근거: 합의 1c, 1c 추가(GitHub 저장소)
- 원본: 01절 확인된 요구 "PDF·EPUB·PPTX·웹·로컬 동영상", 05절 형식 표.
- 변경: 최종 범위는 원본의 포맷 + **이미지**(쪽 계열) + **오디오**(시간 계열, 튜터용 전사) + **Markdown**(가져온 `.md`, 재배치 계열) + **GitHub 저장소**(새 다섯째 계열인 코드 계열)다. 포맷은 계열로 설계하고, 계열마다 viewer 하나와 앵커 형 하나를 공유한다(쪽 / 시간 / 재배치 / 링크 / 코드, ADR-0009 2절).
- 코드 계열(GitHub 저장소):
  - 항목은 commit SHA에 고정한 저장소 스냅샷이다(revision = commit). 새 commit으로 갱신하면 새 revision이 생기고 앵커는 `ok/review/orphan`으로 재앵커된다.
  - 앵커: kind `code` `{commit, path, lineStart, lineEnd}` + 재앵커용 quote. precision은 `item`(저장소) 또는 `span`(파일·줄 범위). W3C 내보내기는 `#line=a,b`(RFC 5147).
  - 가져오기: GitHub URL → 확정한 commit의 tarball(git 불필요), 로컬 git 폴더 → HEAD commit의 스냅샷. 비공개 저장소는 나중에 사용자의 git·gh 자격 증명으로. 큰 저장소는 크기 경고, 바이너리와 LFS는 뺀다.
  - 범위: 읽기·튜터·코드 투어. 사이드바에 파일 트리, 가운데에 구문 강조가 있는 읽기 전용 코드 viewer, 열면 README와 개요(언어, 최상위 구조, 주요 파일), 줄 범위 하이라이트와 노트. 튜터는 저장소 도구 `list_tree`·`read_file(path, lines)`·`search_code`를 쓰고 `file:line` 칩으로 인용한다. 튜터 제안: 코드 투어(설명이 붙은 여러 앵커의 순서 있는 노트, CodeTour처럼 한 단계씩 넘긴다)와 구조 안내(노트). 심볼·의존성·호출 그래프(tree-sitter)는 나중의 확장이다.
  - **경계**: 저장소 코드는 불신 입력이다. 빌드·실행·설치하지 않고 글로만 다룬다. 튜터에게 셸이 없다. 프롬프트 주입은 AC19에 들어간다. 편집·PR·이슈는 없다. 공부 도구이지 GitHub 클라이언트가 아니다.
- 시점: 7절 로드맵 — 이미지 M7, 오디오 M8, 저장소 M11(README용 Markdown 렌더러 포함), Markdown·웹 스냅샷·EPUB M12, PPTX M14.

## 2. P3 재정의: ACP 우선 백엔드
- 날짜: 2026-10-22 · 근거: 합의 3a, 3e
- 원본: 07절 "Provider adapters → remote AI / optional local engine", 13절 P3 "provider interface, fake provider, streaming·취소, RAG·인용·대화", 15절 6 "ViewerAdapter, ProviderAdapter, repository 인터페이스를 분리하라", 16절 "AI 공급자·모델 | 교체 가능한 adapter, 사용자가 선택".
- 변경: "provider adapter → 원격 AI"는 **백엔드 인터페이스**가 된다. 첫 구현은 ACP 에이전트(사용자의 구독)이고, API 키 어댑터는 나중에 같은 인터페이스 뒤에 둔다. 가짜 백엔드는 그대로 둔다(fake provider). 맥락 만들기·범위 검사·인용 검증·기억은 백엔드와 무관하게 Learn이 한다. 자세한 것은 ADR-0010.
- 그대로인 것: P3의 나머지 작업(streaming·취소, RAG·인용·대화)과 종료 조건 문구. 여기서 provider는 위의 백엔드를 말한다.
- 명세 12절 "튜터는 파일 삭제·명령 실행·비밀 읽기 도구를 갖지 않는다"는 에이전트의 내장 도구를 끄고 Learn의 읽기 전용 MCP 도구만 여는 것으로 지킨다(ADR-0010 2절).

## 3. AC11 범위 재조정
- 날짜: 2026-10-22 · 근거: 합의 3e
- 원본: "AC11 | 선택 자료 밖의 비공개 자료와 제외 기억은 provider 요청에 없다. | request payload 검증"
- 변경: Learn이 검증할 수 있는 것으로 범위를 다시 잡는다. **Learn이 에이전트에 넘기는 모든 것(프롬프트와 도구 결과)이 허용 범위 안에 있고, 에이전트의 내장 도구와 사용자 설정이 꺼져 있음을 확인한다.**
- 이유: ACP 경로에서는 에이전트가 공급사로 가는 API 요청을 직접 만든다. Learn이 볼 수 있는 경계는 Learn → 에이전트(ACP 프롬프트와 MCP 도구 결과)다.
- 추적: [`acceptance.md`](acceptance.md) AC11 행.

## 4. 키체인은 나중의 API 키 어댑터에만 필요하다
- 날짜: 2026-10-22 · 근거: 합의 3e
- 원본: 08절 "비밀키는 OS keychain에만 저장한다", 12절 "키는 OS keychain", 15절 8 "키는 keychain에 저장하고 채팅·로그·저장소에 넣지 말라".
- 변경: ACP 경로에서는 Learn이 키·토큰을 보지도 저장하지도 않으므로 키체인을 쓰지 않는다. 키체인은 나중의 API 키 어댑터에만 필요하다. 그때도 원본 규칙(키체인에만, 채팅·로그·저장소에 넣지 않음)은 그대로다.
- 관련: ADR-0003("비밀키는 DB에 저장하지 않는다(OS keychain, P3)"), ADR-0007 §6("외부 서비스 키는 P3에서 OS 키체인").

## 5. Chrome 커넥터 (새 범위)
- 날짜: 2026-10-22 · 근거: 합의 4a, 4b, 4d, 4e, 저장소 구성
- 원본: 브라우저 확장·클리퍼·커넥터가 없다. 웹은 "사용자 지정 URL을 정적 스냅샷으로 보관"(05절)과 "로컬 파일과 URL 등록 우선"(16절)뿐이다.
- **연결(4a)**: Native Messaging이 주 경로다. `learn://`는 "Learn에서 열기"만 하는 보조 경로다.
  - 설정에 "브라우저 연결" 토글을 둔다. 켜면 브라우저별 host 매니페스트(Chrome, Edge, Brave, Arc, Chromium)를 쓰고, 앱 경로가 바뀌면 다시 쓴다.
  - 작은 relay host가 꺼져 있는 Learn을 깨운다.
  - `allowed_origins`는 우리 확장 id다. 주고받기는 양방향이고, 큰 자료(PDF, 스냅샷)는 나눠 보낸다: host로 64 MiB, host에서 1 MB 이내.
- **저장소 구성**: `apps/connector`(MV3 + Vite). 메시지 계약은 `packages/domain`의 zod 스키마로 두고 앱과 함께 쓴다.
- **첫 판이 담는 네 가지(4b)**, 우선순위 순:
  1. 웹 스냅샷 + 메타데이터 + 선택한 글의 하이라이트. 스크립트를 뺀 정적 HTML에 자산을 넣는다. 메타데이터는 title / author / date / site / canonical / DOI / `citation_*`. 앱 쪽에는 샌드박스 스냅샷 viewer(스크립트 없음, 원격 로드 없음, 명세 12절 / AC09)와 웹 앵커가 생긴다.
  2. 브라우저 PDF 저장. 확장이 브라우저 세션으로 바이트를 받고, 출처 URL이 있는 보통 PDF 항목이 된다.
  3. GitHub 저장소 가져오기. 확장은 URL과 branch/commit을 보내고 앱이 받아 온다(1절).
  4. 영상 링크 + 시간. 링크 항목 + 시간 앵커이고 내려받지 않는다. 오프라인에서는 "보관 안 됨"으로 표시한다(명세 05절의 표기는 "오프라인 미보관"이다. 화면 문구는 다음 마일스톤에서 정한다).
  - 팝업의 컬렉션·태그·메모 선택은 네 가지 모두에 공통이다.
- **"Learn에서 질문하기"(4d)**: 팝업에서 세션을 시작한다. 맥락은 저장한 항목 + 선택 앵커다. 튜터가 있어야 하므로 M13이다.
- **M13 첫 작업(4e)**: macOS에서 Native Messaging 스파이크 — relay, 브라우저별 매니페스트, 앱 깨우기, 나눠 보내기.
- 배포와 라이선스: ADR-0011(SingleFile·Zotero translators를 쓸 수 있게 됨).

## 6. 오픈소스 배포, AGPL

## 8. 검색: 메타데이터 빠른 검색(M4)과 본문 검색(M7 이후)
- 날짜: 2026-10-23 · 근거: M4 소유자 결정([`superpowers/specs/2026-10-23-m4-library-design.md`](superpowers/specs/2026-10-23-m4-library-design.md) 0절)
- 원본: 07절 "FTS5로 제목·본문·자막·노트를 검색하고 한국어 검색은 정규화·부분 검색 품질을 fixture로 검증한다", 13절 P1 "…컬렉션·검색·휴지통…", 14절 AC16 "10,000개 item 메타데이터 검색 p95 300ms".
- 변경: P1의 검색은 두 단계로 나눈다. **M4는 메타데이터 빠른 검색**이다: 제목·저자·연도·출판사·원래 이름·초록·메모를 렌더러의 메모리 색인으로 찾는다(FTS5가 아니다). 한국어는 NFC·소문자 정규화, 짧은 필드의 초성, 2글자 부분 일치까지 된다 — FTS5 트라이그램의 3글자 제한이 없다(next-session P1 후보 "한국어 2글자 검색"을 이것으로 닫는다). **본문 검색**(PDF 텍스트, 자막, 노트)은 앵커(ADR-0009)와 텍스트 추출이 생기는 M7(PDF)·M8(자막)·M9(노트)에서 FTS5로 한다. 본문 조각의 저장 형식을 앵커 설계보다 먼저 정하지 않기 위해서다.
- AC16의 "메타데이터 검색 p95 300ms"는 M4의 `@perf` 1만 항목 측정이 맡는다(판정은 원본대로 기준 장비). 첫 PDF 2초·MP4 3초는 그대로 P6.
- 추적: [`acceptance.md`](acceptance.md) AC16 행.
- 3.3·6절의 툴팁 "자료를 하나만 고르세요"는 M4에 자리가 없다. 선택 개수 때문에 꺼지는 앱 안의 컨트롤이 없고(메뉴는 항목을 기본 방식으로 회색 처리한다), 보여 줄 비활성 컨트롤이 없기 때문이다.

## 9. 정리: 컬렉션·태그·끌어 놓기·컨텍스트 메뉴(M5)
- 날짜: 2026-10-26 · 근거: M5 소유자 결정([`superpowers/specs/2026-10-26-m5-organize-design.md`](superpowers/specs/2026-10-26-m5-organize-design.md) 0절, 16절)과 그 뒤의 계획 판정
- 원본: 디자인 명세 6(표·트리·태그 칩·드롭 오버레이), 7.2(끌어 놓기), 7.3(메뉴 내용)과 M4 명세 3.1.
- **A. 디자인 명세를 바꾼 것**(본문도 고쳤다):
  1. 웹 팝업 "컬렉션에 추가 ▾"의 "새 컬렉션… ⇧⌘N" → "새 컬렉션 ⇧⌘N": 대화상자 없이 트리 안에서 이름을 고친다(Finder의 새 폴더).
  2. 태그 컨텍스트 메뉴의 "이름 바꾸기…" → "이름 바꾸기": 칩 안에서 고친다.
  3. 태그 선택기 "…" 메뉴에 "태그 선택 해제"(필터가 있을 때만, 구분선 다음).
  4. 컬렉션 컨텍스트 메뉴의 "휴지통으로 이동(M6)" → M5에서 "컬렉션 삭제…"(확인 시트 + 실행 취소), M6에서 휴지통이 생기면 "휴지통으로 이동".
  5. 드롭 오버레이: 제목 막대 아래 전체 → 사이드바가 보이면 사이드바 오른쪽 전체. 사이드바의 컬렉션 행과 "내 라이브러리" 행은 각자 드롭 대상.
  6. 표의 "마지막으로 연 날" 열을 M7이 아니라 M5에 더한다(M4 명세 3.1의 문장도 고쳤다).
  7. 7.2 "⌘ = 이동(현재 컬렉션에서 빼고 추가)"의 현재 컬렉션은 현재 컬렉션 범위(하위 포함)이고, 이동 변조키는 플랫폼의 것(macOS ⌘, 그 밖 Shift).
  8. (조건부) "옮기기 ▸" 메뉴는 RAC `Tree`가 남아 불필요 — 더하지 않았다. "컬렉션" 머리는 키보드 끌기에서 Tab으로 닿으므로 폴백 명령 "최상위로 옮기기"(`collection.moveToRoot`)도 없다.
  9. 비평이 정한 값을 디자인 명세 6에 옮겼다: 끌기 중 머리 칸(`--fill-pressed` + 2px `--accent-ring` 선, 유령 칸 없음)과 머리의 세로 스크롤 분리, 트리의 이름 필드(22)와 구역 머리(36), 태그 칩의 ×(자리는 늘, 보이기는 호버·포커스에서만)·편집 칩·고른 흐린 칩·추가 칸(22 알약 + 제안 목록)·컬렉션 경로 줄. 목업과 다른 앱 값 셋(개수 0을 쓰지 않음, 빈 컬렉션 간격 48, 태그 선택기 "…"의 자리)은 앱이 맞다고 적었다.
  10. 7.4 키 표에 ⌥→(컬렉션 행의 끌기 단추로 포커스).
  11. 드롭 대상 표시의 고리는 2px `--accent`가 아니라 `--accent-ring`이다(라이트는 같은 픽셀, 다크는 모든 면에서 3:1 이상). 끌기 미리보기와 드롭 표시(트리 행·"컬렉션" 머리·표 행·"자료 N개" 배지, 미리보기 테두리 `--border`)를 6의 한 행으로 더했다.
  12. 7.3 자료 메뉴의 "색 태그 ▸"는 줄마다 색 점을 그리고, macOS 메뉴 막대의 같은 하위 메뉴는 "1"…"8"을 보이지 않는다(AppKit이 ⌘ 없는 키를 웹 보기보다 먼저 메뉴에 준다).
  13. 9 문체: 줄을 바꿀 수 있는 "·" 목록은 각 "·" 앞에 U+2060(띄어 쓰는 목록은 "·" 앞 칸을 U+00A0), 항목 패널 통계 줄은 " · " 앞에 U+00A0. 닫는 따옴표 ’와 조사 사이에 U+2060(한 어절: 줄이 조사로 시작하지 않는다). 10.5: 팔레트 행의 오른쪽 보조 정보는 2차색(12px 정보 글자 4.5:1 — 목업의 3차색을 바꿨고 목업도 고쳤다).
- **B. 디자인 명세가 이기거나 문장이 그대로인 판정**(M5 명세만 고쳤다. 본문 정정은 M5 명세 끝 "계획 작성 중 정정"):
  - 제목 셀의 순서는 제목 · 연결 표시 · 색 점 · 상태 표시(승인된 목업이 이겼다, Q-61), 팔레트 컬렉션 행의 보조 정보는 "<상위 이름> 안 · N개"(승인된 목업이 이겼다, Q-106).
  - 확인 시트의 질문은 합니다체 의문형 "…하겠습니까?"(디자인 명세 9의 합니다체 그대로, 해요체 예외 없음).
  - 자동 스크롤 띠는 RAC의 20px(명세 8.2의 24px 정정, Q-32), 스프링 로딩은 RAC 고정 800ms, 컬렉션 행을 누르면 선택(Q-31), 태그 선택기의 Tab 순서는 "…" · 칩 · 필터 칸(Q-60), 중복 시트 "가져오지 않음"의 컬렉션 넣기는 렌더러 몫(Q-1), 그 밖의 계획 판정은 M5 명세 끝 절의 목록.
  - 태그 필터 결과 없음의 설명 한 줄(디자인 명세 6의 빈 상태 문법을 따른 것), 흐린 칩도 같은 정렬에 섞임, 키보드 끌기는 "컬렉션" 머리에 Tab으로 닿음, 놓은 뒤에도 보던 컬렉션이 보기로 남음, 메뉴 막대 "색 태그 ▸"의 체크(`selectionTagPositions`) — 구현 중 컨트롤러 판정, M5 명세 본문.
