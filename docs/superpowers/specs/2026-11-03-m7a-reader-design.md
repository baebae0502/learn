## 3. 앵커 스파이크와 ADR-0009 채택 (첫 작업)

### 3.1 시험 — ADR-0009 7절의 채택 조건
1. **선택 → 앵커 → 다시 표시**: 시험 PDF(4.12)에서 글을 고르면 `pdf` 앵커가 된다. 확대 4단계(50·100·200·400%) × 회전 4방향(0·90·180·270)에서 앵커를 다시 화면 사각형으로 그렸을 때, 같은 글의 pdf.js 글 조각 기하로 계산한 기대 사각형과 **PDF user space에서 2pt 안**이다(AC03). 여러 줄·두 단·한국어 줄을 포함한다.
2. **쪽 인용 → 앵커**: `{ pageIndex, quote }`(T1에서 에이전트가 보내는 형태를 흉내 낸 시험 인용 자료)를 그 쪽의 글에서 찾아 앵커로 만들고, 1과 같은 기준으로 위치가 맞는다. 줄바꿈·하이픈 줄넘김·연속 공백·NFC/NFD 차이가 있는 인용을 포함한다. 찾지 못하면 앵커를 만들지 않고 `NOT_FOUND`로 답한다(인용 검증의 실패 경로).
- 앵커를 만들고 그리는 코드는 도메인·렌더러 함수이고 화면 동작은 없다. 시험은 테스트 훅으로 선택을 만들고 결과를 읽는다(앵커를 만드는 화면 동작은 M9 필기·T1 인용에서 붙는다 — 가짜 금지).

### 3.2 스파이크로 정할 것 — 예상과 판정 기준
| 열린 질문 (ADR-0009) | 예상 | 판정 |
|---|---|---|
| `text.position`의 단위 | **UTF-16 코드 단위**, 쪽 안 오프셋(그 쪽 글 내용을 pdf.js 규칙대로 이은 문자열 기준). W3C 내보내기 변환기가 code point로 바꾼다 | 3.1의 두 시험이 이 단위로 통과하는가 |
| `pdf`의 `precision` | `span`(글 선택)·`region`(영역, M9 펜·M7b 이미지 영역). `item`은 쓰지 않는다 | — |
| `text` 필수 여부 | `span`은 `text.quote` 필수, `region`은 없음 | — |
| 기존 `quote`(locator 안)와 `anchors.quote` 열 | locator의 `quote`는 `text.quote`로 옮긴다. `anchors.quote` 열은 표시·검색용 `exact`의 사본으로 남긴다 | — |
| `'slides'`/`'slide'` | `anchors.kind`를 `'slides'`로 맞춘다(`items` 테이블 재작성보다 비어 있는 `anchors` 재작성이 싸다) | — |
| 새 kind의 CHECK 시점 | kind를 처음 쓰는 마일스톤이 좌표 zod와 함께 더한다(M7b `image`). M7a는 kind 목록을 바꾸지 않는다 | — |
- 결과가 예상과 다르면 ADR-0009를 먼저 고치고(명세 13절 규칙) 그 결과로 마이그레이션을 쓴다. 판정과 근거는 ADR-0009의 새 절 "M7a 스파이크 결과"에 적고 상태를 "채택"(스파이크를 마친 날짜)으로 바꾼다.

### 3.3 마이그레이션 003
- `anchors` 테이블을 다시 만든다(비어 있다 — `anchors`를 쓰는 코드가 아직 없다): `precision TEXT NOT NULL CHECK (precision IN ('item','span','region'))`, `text_json TEXT`(null 허용), `kind` CHECK의 `'slide'` → `'slides'`. 기존 열·FK·색인은 유지한다.
- 같은 마이그레이션에 번역 캐시 테이블(6.5)을 더한다.
- 마이그레이션 전 `.pre-v3.bak`(ADR-0003), v2 → v3 실데이터 시험(`migrate.test.ts` 방식), `LATEST_SCHEMA_VERSION`은 `MIGRATIONS`에서 유도된다.
- 백업 manifest의 `schemaVersion`과 복원 검증이 v3을 받아들인다(v2 백업의 복원은 열 때 마이그레이션된다 — 기존 규칙).

### 3.4 앵커 도메인과 저장소
- 도메인(`packages/domain/src/anchors.ts`): `pdfAnchor`를 ADR-0009 1절 모양(`precision`, `text { quote, position }`, `pageIndex`, `quads`, `coordinateSpace`)으로 바꾸고 `ANCHOR_SCHEMA_VERSION`을 2로 올린다. `toWebAnnotation(anchor)` 변환기(쪽: FragmentSelector `page=`, 글: TextQuote + TextPosition, code point 변환)를 둔다.
- 순수 함수: `anchorFromSelection(pageText, selection)`, `anchorFromQuote(pageText, { pageIndex, quote })`, `quadsToViewport(quads, viewport)`(회전·확대) — 렌더러와 시험이 함께 쓴다.
- 저장소(`packages/db`): `anchors.create`·`get`·`listByRevision`, zod 검증, 기존 저장소 패턴(prepared statement + 매퍼 + 변경 없으면 오류). **IPC 채널은 열지 않는다**(소비자가 생기는 M9·T1에서).

## 4. PDF 리더 v2

### 4.1 뷰어 부품
- `pdfjs-dist/web/pdf_viewer.mjs`의 `PDFViewer`·`EventBus`·`PDFLinkService`·`PDFFindController`를 React 구성요소 하나(`PdfDocumentView`)가 소유한다. 버전은 지금 그대로(6.4.299, 정확히 고정).
- `pdf_viewer.css`는 글 레이어·주석 레이어·쪽 배치에 필요한 규칙만 우리 CSS `@layer`로 옮기고 고지를 단다(Apache-2.0). pdf.js 기본 화면 요소(도구 막대 등)는 쓰지 않는다.
- 스크롤 모드는 세로로 이어서 하나다(M7b가 나머지). 쪽 사이 간격·그림자는 목업대로.
- `ViewerHost`·`ReaderToolbar`·`ReaderNotices`·`TrashedNotice`의 바깥 계약(열기, 휴지통 안내, 원본 없음, 다시 연결)은 그대로 둔다.

### 4.2 도구 막대 (목업 `reader-pdf.html`, 디자인 명세 10.3)
- 왼쪽부터: 사이드바 토글 · 쪽 필드("42 / 380", 입력 후 ↩로 이동, 범위 밖은 되돌림)와 이전·다음 셰브런 한 쌍 · 확대 필드(24/13, "125%") + 확대 메뉴 ▾ · 찾기 단추 · 보기 메뉴 ▾ · 인스펙터 토글. 탭 줄·뒤로·앞으로는 M7b.
- 확대 메뉴: 자동 맞춤 · 너비에 맞춤 · 한 쪽 전체 보기 · 실제 크기 ⌘0 · — · 75 / 100 / 125 / 150 / 200% · — · 확대 ⌘+ · 축소 ⌘−(디자인 명세 7.3 그대로).
- 보기 메뉴(M7a): 쪽 색(앱 테마 따르기 / 원본 / 세피아 / 어둡게) · — · 시계 방향으로 회전 ⌘R · 반시계 방향으로 회전 ⌘L. 스크롤·펼침 묶음은 M7b(14절).

### 4.3 확대
- 100% = pdf.js 배율 1 = scale × 96/72(A4 → 794px). 범위 25–400%. ⌘+/⌘−는 단계 [25, 33, 50, 67, 75, 90, 100, 110, 125, 150, 175, 200, 250, 300, 400]를 오가고, 맞춤 모드에서는 지금 배율에서 가까운 다음 단계로 간다.
- 트랙패드 핀치(Chromium의 ctrl+wheel)는 커서 위치를 고정한 채 연속으로 확대하고, 놓은 뒤 쪽을 그 배율로 다시 그린다.
- 창 크기가 바뀌면 맞춤 모드는 다시 계산하고, 숫자 배율은 그대로 둔다.
- `devicePixelRatio`가 바뀌면(다른 디스플레이) 보이는 쪽을 다시 그린다.

### 4.4 회전
- ⌘R / ⌘L로 문서 전체를 90° 돌린다. 회전은 위치 기억에 들어간다(5절). 쪽마다의 회전은 없다.

### 4.5 찾기
- 리더에서 ⌘F는 찾기 막대를 연다(라이브러리의 ⌘F는 빠른 검색 그대로). 막대: 입력란, "3 / 17", 이전·다음, 닫기(esc). ⌘G / ⇧⌘G 다음·이전, ⌘E 선택으로 찾기.
- `PDFFindController`: 대소문자 무시, 모든 일치 강조, 한국어는 입력과 쪽 글을 NFC로 맞춘 뒤 찾는다. 결과가 없으면 "찾을 수 없음"을 입력란 옆에 보인다. 문서 끝에서 처음으로 돌아갈 때 막대에 한 번 알린다.
- 찾기 막대가 열린 동안 쪽 이동 키(스페이스·←/→)는 입력란에 간다.

### 4.6 링크
- 문서 안 링크·목차 항목: 그 쪽(과 쪽 안 위치)으로 이동. 이동 기록(뒤로/앞으로)은 M7b.
- 바깥 링크: 올리면 주소를 툴팁으로 보이고, 누르면 main이 주소를 검사해(`http`·`https`·`mailto`만) 기본 앱으로 연다. 다른 스킴은 열지 않는다. 매번 묻는 시트는 두지 않는다(Preview·Zotero와 같다 — 14절).

### 4.7 사이드바: 썸네일 · 목차
- 왼쪽 사이드바가 리더에서는 쪽 탐색이 된다. 썸네일 / 목차 전환(⌥⌘2 / ⌥⌘3, 세그먼트 단추).
- **썸네일**: 가상화 목록, 폭 120 기준으로 그린 이미지를 LRU(최대 60장)로 둔다. 지금 쪽은 선택 표시(7.1 선택 모델), 누르면 이동, ↑/↓로 이동. 그리는 중에는 자리 상자(목업 "썸네일 불러오는 중", 복원할 쪽 주변부터 그린다).
- **목차**: `getOutline()`을 RAC Tree로(펼침 기억은 하지 않는다), 누르면 이동, 지금 위치의 항목을 표시. 목차 검색 입력란(NFC·대소문자 무시·초성 없음). 목차가 없으면 "이 PDF에는 목차가 없습니다"(목업 `nooutline`).
- 휴지통 자료: 사이드바에 "복원하면 쪽이 보입니다" 줄(목업 `trashed`, M6에서 넘긴 줄).

### 4.8 쪽 색
- 앱 테마 따르기(기본: 다크 모드에서 어둡게, 아니면 원본) / 원본 / 세피아 / 어둡게. 쪽 캔버스에만 필터를 건다(세피아: 따뜻한 곱하기, 어둡게: 반전 + 색상 회전으로 그림 색을 덜 깬다). 글 레이어 선택 색은 바뀌지 않는다.
- 라이브러리 설정 `reader.pageColor`(ADR-0007 — 이 라이브러리를 어떻게 보여 줄지).

### 4.9 암호 · 상태 화면
- 암호로 보호된 PDF: 도구 막대 대신 제목 줄 + 암호 입력란(목업 `locked`). 틀리면 "암호가 맞지 않습니다". 암호는 저장하지 않는다(ADR-0007 6절).
- 여는 중, 열기 실패(손상), 원본 없음, 휴지통: 지금의 상태 화면을 목업 10.3대로 맞춘다.

### 4.10 키보드
- 디자인 명세 7.4의 PDF 줄: ⌘F, ⌘G / ⇧⌘G, ⌘E, ⌘+ / ⌘− / ⌘0, ⌥⌘G(쪽 필드로 포커스), ⌘R / ⌘L, 스페이스 / ⇧스페이스(화면 단위), ← / →(이전·다음 쪽), ⌥⌘2 / ⌥⌘3. 리더 맥락의 ⌘+/⌘−/⌘0은 글자 크기가 아니라 확대다(레지스트리 맥락으로 나눈다).
- 글 선택 위 오른쪽 클릭: 네이티브 메뉴 "복사 ⌘C"(M9가 하이라이트 등을 더한다).

### 4.11 글 선택 · 복사
- pdf.js 글 레이어로 고르고 ⌘C로 복사한다. 줄 끝 하이픈과 줄바꿈은 복사할 때 그대로 둔다(번역 요청에는 6.4의 정리 규칙을 쓴다).

### 4.12 시험 PDF
- `fixtures/generate.mjs`에 더한다: 100쪽 영어 논문형(두 단·그림·각주), 한국어 글이 있는 쪽, 목차(중첩 3단), 문서 안 링크와 바깥 링크, 암호 PDF, 회전된 쪽이 하나 있는 PDF. 라이선스 문제가 없도록 생성한다.

## 5. 위치 기억과 진행률

- locator(`readingLocatorSchema`의 `pdf`)에 더한다: `zoom`(`'auto' | 'page-width' | 'page-fit' | 배율 숫자`), `rotation`(0/90/180/270), 쪽 안 위치(`top`·`left`를 PDF user space 점으로 — 확대와 무관). 기존 저장값(쪽만 있는 것)도 그대로 읽힌다(필드는 선택).
- 저장: 스크롤·확대·회전이 멈추고 300ms 뒤(지금의 디바운스), 닫기·종료 때 즉시. 복원: 첫 쪽을 그리기 전에 확대·회전을 정하고 그 위치로 간다(깜빡임 없음).
- **진행률** = 가장 멀리 본 쪽 / 전체 쪽 수(0–1, 줄지 않는다). 저장할 때 함께 쓴다.
- **알림**: 위치가 저장되면 `libraryChanged { reason: 'position', itemIds }`(자료마다 2초에 한 번 이하). M2부터 넘어온 "위치 저장·진행률 알림"을 닫는다.
- **진행 열**: 라이브러리 표에 "진행"(작은 막대 + 퍼센트, `tabular-nums`, 읽지 않은 자료는 비움). 정렬 가능. 기본 열 구성에 보이고, 저장된 열 구성에는 끝에 숨김으로 더해진다(열 선택기로 켠다 — 기존 사용자의 표가 갑자기 바뀌지 않게).

## 6. 선택 번역 (ADR-0012)

### 6.1 선택 팝업
- PDF에서 글을 고르고 마우스를 놓으면(또는 키보드 선택이 멈추고 300ms 뒤) 선택 끝 근처에 팝업이 뜬다. 공백뿐이거나 5,000자를 넘는 선택은 팝업 대신 "번역하기에 너무 깁니다"를 보인다.
- 팝업 내용: 번역문(최대 높이, 넘치면 스크롤), 상태(번역 중 · 결과 · 오류 · 오프라인 · 동의 요청), 단추 "복사"(번역문). 대상이 한국어이고 고른 글이 거의 한글이면 "이미 한국어입니다"를 보이고 요청하지 않는다(기기 안 판정). 그 밖에 엔진이 알려 준 원문 언어가 대상과 같으면 결과를 그대로 보인다.
- 닫힘: esc, 바깥 클릭, 새 선택, 스크롤로 선택이 화면 밖으로 나갈 때. 팝업은 포커스를 빼앗지 않는다(선택이 유지된다). 키보드로는 팝업에 Tab으로 들어간다.
- 번역을 끈 상태에서는 팝업이 없다.

### 6.2 인스펙터 "번역" 절
- 리더가 열려 있을 때 인스펙터 정보 모드의 **맨 위 절**. 머리: "번역" + 방향 단추("자동 → 한국어 ▾").
- 원문 칸(편집 가능, 고른 글이 들어온다)과 번역 칸(읽기 전용, 선택 가능)을 위아래로.
- 단추·토글: "선택하면 번역"(켜면 고를 때마다 자동 번역, 기본 켬) · "이어 붙이기"(켜면 새 선택을 원문 끝에 줄을 바꿔 잇고 전체를 다시 번역, 기본 끔) · 지우기 · 복사 ▾(원문 / 번역 / 둘 다) · 번역(자동이 꺼졌거나 원문을 고쳤을 때).
- 절의 내용은 자료마다 기억하지 않는다(리더를 닫으면 비운다). 팝업과 절은 같은 번역 결과를 쓴다(요청 한 번).

### 6.3 동의 · 설정
- 기기 환경설정(`preferences.json`, ADR-0007 — 이 기기에서 바깥으로 보내는지의 문제다): 필드 `translation { enabled: true | false | null`(null = 아직 묻지 않음, 기본)`, autoOnSelect: boolean`(기본 true)`, from`(기본 `auto`)`, to`(기본 `ko`)` }`. 필드별 검증 규칙(ADR-0007 2절)을 따른다.
- `null`에서 처음 고르면 팝업이 동의 요청이 된다: "선택한 글을 번역하려면 Google로 보냅니다." [번역 켜기] [사용 안 함]. 켜기 전에는 원격 요청이 없다. "사용 안 함"이면 팝업이 다시 나오지 않는다. 인스펙터 절도 같은 안내와 단추를 보인다.
- 설정 창에 "번역" 절: 켜기(설명 줄 "선택한 글이 Google로 보내집니다"), 선택하면 번역, 방향.
- 언어 목록(M7a): 자동(원문만), 한국어, 영어, 일본어, 중국어(간체), 독일어, 프랑스어, 스페인어.

### 6.4 엔진 · 네트워크 경계
- main의 `translation/` 모듈: `TranslationEngine { id; translate(text, { from, to }, signal) → { text, detectedFrom } }`. 첫 엔진 `google-web`(ADR-0012 2절의 키 없는 주소). 요청 형식은 스파이크(6.7)에서 직접 확인해 새로 쓴다 — 플러그인 코드를 보지도 가져오지도 않는다(AGPL).
- 요청은 **main만**, Electron `net.fetch`(시스템 프록시를 따른다), 시간 제한 10초, 취소 가능(새 선택이 이전 요청을 취소). 허용 호스트는 `translate.googleapis.com` 하나이고 목록은 `url-policy.ts` 옆 한곳(`net-policy.ts`)에 둔다. 다른 호스트로의 요청은 코드에서 막는다(단위 시험).
- 보내기 전 정리: 줄 끝 하이픈 + 줄바꿈은 붙이고, 나머지 줄바꿈은 공백으로, NFC. 4,500자를 넘으면 문장 경계에서 나눠 차례로 보내고 잇는다.
- 오류 분류와 문구: 연결 없음 "번역할 수 없음 — 인터넷에 연결되어 있지 않습니다", 한도 초과(429) "번역 요청이 너무 많습니다. 잠시 뒤 다시 시도하십시오", 막힘(그 밖의 4xx) "번역 서비스가 요청을 거부했습니다", 응답 없음(5xx·시간 초과) "번역 서비스가 응답하지 않습니다", 형식 바뀜(해석 실패) "번역 결과를 읽을 수 없습니다". 모두 [다시 번역] 단추가 있고, **자동으로 다시 보내지 않는다**(AC14).
- 렌더러 CSP는 그대로 `connect-src 'self'`.

### 6.5 캐시
- 마이그레이션 003의 `translation_cache(key TEXT PRIMARY KEY, engine, from_lang, to_lang, detected_lang, result TEXT, created_at, used_at)`. key = sha256(engine | from | to | 정리한 원문). 최대 2,000행, 넘으면 `used_at`이 오래된 것부터 지운다.
- 캐시에 있으면 요청하지 않는다(E2E가 요청 0회를 센다). 백업에는 DB와 함께 들어가지만 manifest 개수에는 넣지 않는다(설정처럼 자료가 아니다).

### 6.6 IPC
- `translation:translate`(렌더러 → main): `{ text, from, to }` → `Result<{ text, detectedFrom, engine, cached }>`; 오류 코드 `TRANSLATION_OFFLINE | TRANSLATION_RATE_LIMITED | TRANSLATION_BLOCKED | TRANSLATION_UNAVAILABLE | TRANSLATION_BAD_RESPONSE | TRANSLATION_DISABLED | TRANSLATION_TOO_LONG`. `translation.enabled !== true`이면 main이 `TRANSLATION_DISABLED`로 거부한다(렌더러를 믿지 않는다).
- `translation:cancel`(진행 중 요청 취소). 동의·설정은 기존 `prefs.set`.

### 6.7 스파이크와 시험
- 스파이크: 구현자가 시험용 영어 문장 두 개(소유자 자료 아님)로 실제 주소를 한 번 불러 요청·응답 형식을 확인하고, 그 응답을 시험 자료(`fixtures/translation/`)로 저장한다.
- 단위: 가짜 엔진, 응답 해석(저장한 실제 응답), 정리·나누기, 오류 분류, 호스트 허용 목록, 캐시 LRU.
- E2E: `LEARN_TRANSLATION_ENGINE=fake`(테스트 훅, E2E에서만)로 가짜 엔진과 요청 수 세기. 동의 전 0회, 끈 뒤 0회, 같은 글 두 번째 0회, 오프라인 표시와 재전송 없음.
- 실제 호출 시험은 `LEARN_TRANSLATION_LIVE=1`일 때만 도는 단위 시험(CI에서 돌지 않는다).

## 13. 계획의 Global Constraints에 들어갈 것
- 새 데이터 객체는 모두 앵커로 주소를 가질 수 있다(제품 방향 합의).
- AGPL 코드(Zotero reader, zotero-pdf-translate)는 보지도 가져오지도 않는다. pdf.js(Apache-2.0)의 CSS를 옮기면 고지를 단다. 런타임 의존성은 정확히 고정하고 새로 더하지 않는다(필요하면 계획에서 근거와 라이선스를 적는다).
- 원격 요청은 main만, 허용 호스트 하나, 동의 전·끈 상태에서는 0회, 자동 재전송 없음.
- 가짜 컨트롤 금지: 메뉴·팔레트·도구 막대는 레지스트리에서만, 핸들러 없는 항목은 그리지 않는다.
- 문체는 합니다체, 화면 문구는 `strings/` 영역 파일에. 한국어 조사는 `eulReul` 등 `josa.ts`.
- 시트 뒤 클릭은 `sheetReleased()` 뒤에(macOS 250ms).
- 구현자는 push·CI 실행·하위 에이전트 실행을 하지 않는다(컨트롤러가 한다).
- 커밋 꼬리말 두 줄(Co-Authored-By, Claude-Session).

## 15. 위험
- **pdf.js 뷰어 CSS와 디자인 토큰의 충돌**: 필요한 규칙만 옮기고 투어 기준 PNG로 고정한다.
- **Electron에서 글 레이어 선택의 어긋남**(확대 중, 두 단): 스파이크 E2E가 먼저 잡는다. 어긋나면 ADR-0009 판정 전에 원인을 본다.
- **비공식 번역 주소**: 막히거나 형식이 바뀔 수 있다(ADR-0012). 오류 분류 "형식 바뀜"으로 알리고, 엔진 인터페이스로 갈아 끼운다. 공개 출시(M14) 전에 다시 본다.
- **큰 PDF**(1,000쪽 이상)의 썸네일·찾기 비용: 가상화·LRU·pdf.js 찾기의 점진 처리. 측정은 100쪽 기준이고 큰 파일은 실기에서 본다.
- **M7a의 크기**: 중간 Mac `e2e`로 1024×768 차이를 일찍 만난다.
