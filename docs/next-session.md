## M3 셸 결과 (2026-10-22)

계획 [`superpowers/plans/2026-10-21-m3-shell.md`](superpowers/plans/2026-10-21-m3-shell.md), 브랜치 `m3-shell`. 검증 숫자는 [`acceptance.md`](acceptance.md) 머리말과 AC02·AC18. 결정은 [ADR-0004](decisions/0004-ui-stack.md)(채택)와 ADR-0005.

### M3에서 해결한 것
- **셸(레이아웃 B)**:
  - 전체 높이 사이드바: 240(180–360), 접기·기억, 좁은 창과 200% 확대에서 자동 접힘;
  - 사이드바 위 88px은 모든 화면에서 픽셀까지 같다(E2E. Linux는 정확히 같아야 하고, macOS는 반투명 재질 위라 불투명 색에 합성해 채널당 12까지, 그리고 런처 둥근 모서리의 앤티앨리어싱 픽셀은 두 장 모두 반투명이고 차이 48 이하인 것 8개까지 허용한다 — M4 Mac 실행에서 화면에 따라 모서리 6픽셀의 알파가 180 대 152로 달랐다);
  - 52px 통합 도구 막대;
  - TopBar와 튜터 자리표시는 없앴다.
- **키맵**:
  - 메뉴·팔레트·툴팁·⌘/ 시트의 가속기와 ⌘ 표기는 모두 명령 레지스트리 하나에서 나온다;
  - 렌더러 키맵은 F6 / ⇧F6 패널 이동이다. IME 조합 중과 편집 중에는 무시하고, 가져오는 중에도 막지 않는다;
  - 실행기는 `aria-keyshortcuts`를 단다.
- **명령 상태**:
  - 가용성 판정은 하나(`isCommandAvailable`)이고, main 메뉴·컨텍스트 메뉴·렌더러가 같이 쓴다;
  - 렌더러는 `ui:reportContext`로 상황을 알린다;
  - 비활성 명령은 이유를 툴팁으로 보인다;
  - ⌘/ 시트를 요청하면 명령은 그때부터 거절되지만, 창이 흐려지는 것은 시트가 화면에 뜬 뒤다.
- **설정 창(⌘,)**:
  - 따로 뜨는 600폭 창이다: 테마, 밀도, 글자 크기, 라이브러리 위치;
  - 라이브러리 위치(R4)는 main이 고르고 검사하고 확인한 뒤 재시작한다. 렌더러는 경로를 보내지 않는다;
  - 테마를 바꾸면 페이지가 먼저 바뀌고, 각 창의 크롬과 네이티브 테마가 따라온다. 보고가 없으면 250ms 뒤에 따라오고, 늦게 온 이전 변경의 보고는 무시한다.
- **시트**:
  - 중복 확인 시트와 ⌘/ 단축키 시트. macOS에서는 네이티브 시트다;
  - 시트가 닫힌 뒤 창이 다시 키가 될 때까지 크롬은 흐려지지 않는다.
- **그 밖**:
  - ⌘K 팔레트: 초성 검색, IME 안전, 자체 콤보박스(ADR-0004 M3 편차);
  - 드롭 오버레이(⌥는 외부 연결), 토스트;
  - 창 크롬: 신호등, 비브런시, 창 상태 기억, About. Linux·Windows는 `titleBarOverlay`;
  - CSS `@layer` 체계(`styles.css` 폐기), 의존성 정확 고정;
  - 데모 오버레이(`LEARN_DEMO_OVERLAY`)와 장 목록이 있는 macOS 데모 녹화;
  - `@perf`: 냉시작, 렌더러 번들, 시트·설정 창 열기 지연, 테마 전환 순서.

- **시트의 부모가 다른 창이 키일 때도 "메인"으로 남는다**(최종 리뷰 m5, M3에서는 고치지 않음): 메인 창에 중복 확인 시트나 ⌘O 패널이 떠 있을 때 설정 창을 누르면 AppKit은 설정 창을 키로, 메인 창을 메인으로 만들어 흐리게 한다. 우리 크롬은 흐려지지 않는다. 반대로 설정 창의 폴더 패널이 떠 있을 때 메인 창을 눌러도 같다(`main/window-state.ts`의 `windowStateOf` 32–36행과 `renderer/src/shell/useWindowState.ts` 13행 — M3 7334c19 기준. 처음 적었던 132–136·87은 틀린 행 번호였다, 계획 P-13). 고칠 방향: `sheetOpen`을 메인으로 세는 것은 포커스된 창이 그 부모의 시트일 때(네이티브 패널이면 우리 창이 아무것도 아닐 때)뿐이게 하고, 우리 창 어느 것에 포커스가 와도 상태를 다시 보낸다. 드문 경우이고 병합 직전의 창 상태는 민감해서 M4로 넘겼다. → **M4에서 해결**(Task 11): 시트가 뜬 메인 창은 우리 창 가운데 자신도 자신의 시트도 아닌 다른 창이 키일 때만 메인이 아니다(네이티브 패널도 같은 규칙, 판정 Q-1).
- **main 프로세스의 남은 인라인 문구**(재검토 범위 밖 관찰): m6에서 옮기지 않은 것이 남았다. 열기 패널 제목 `'파일 가져오기'`, `'원본 파일 다시 연결'`(`ipc/library.ts`), `'잘못된 요청입니다.'`(`ipc/register.ts`), `item-availability.ts`, `prefs.ts`, `index.ts`의 문구, 메뉴 레이블. 전역 제약("문구는 모두 strings/ 모듈에")대로 `main/strings.ts`로 옮긴다. → **M4에서 해결**(Task 11): `main/strings.ts`로 옮겼고 인라인 한글 검사가 지킨다.
- **오래 걸리는 첫 복사에 진행 표시가 없다**(재검토 범위 밖 관찰): APFS가 아닌 라이브러리의 관리형 항목과 다른 볼륨의 이름이 맞지 않는 외부 연결 파일은, 첫 기본 앱으로 열기나 Finder에서 보기 때 통째로 복사된다. 큰 동영상이면 몇 초 동안 아무 반응이 없다. 300ms가 지나면 진행 표시(명세 6)를 보이거나, 복사를 미리 해 둔다. → **M4에서 해결**(Task 8): 300ms가 지나면 바쁨 토스트(P-12, P-29).

### M4에서 해결한 것
- **자료 표**: TanStack Virtual 3.14.22 + 자체 `role="grid"`(스파이크에서 react-aria `Table`이 Linux와 Mac 모두 예산을 넘어 탈락 — ADR-0004 "M4 표") 가상 표, 열 9개(제목은 늘 보임):
  - 머리를 눌러 정렬(빈 값은 맨 뒤, 같은 값은 추가일 → id), 경계를 끌어 폭(놓을 때 저장), 네이티브 열 머리 메뉴(열 목록·되돌리기);
  - `library.columns`·`library.sort`로 다시 시작해도 남는다;
  - 1만 항목에서 예산 안(`library-perf.json`, ADR-0004 "결과와 위험"). Mac 러너의 스크롤 프레임 p95 18.7ms만 예산 16.7ms를 넘는데, 그 러너는 가만히 있어도 p95가 약 33ms다.
- **선택**: Finder식(클릭·⇧·⌘·⌘A·화살표·Home/End), 오른쪽 클릭은 먼저 고른다, 더블클릭·↩ 열기, esc는 선택을 비운다, type-ahead 없음. 선택은 저장소 하나(`useLibrary`)가 갖고, 사라진 id와 검색으로 가려진 id는 그 자리에서 빠진다. 리더에 갔다 오면 선택이 남고 마지막으로 연 행이 보인다. 포커스는 커서 행의 롤링 `tabindex="0"`이고 정렬 단추·열 경계는 Tab·F6 밖이다.
- **명령**: 맥락에 라이브러리의 수와 선택의 수(평평한 수, P-2), 메뉴 막대의 자료 명령(⇧⌘R Finder에서 보기, 사본 내보내기…, 기본 앱으로 열기), ⌘F 빠른 검색(편집 › 빠른 검색), ⌥⌘I 항목 패널, 팔레트의 자료 명령(P-15), ⌘/ 시트의 자료 묶음(P-14). 개발 빌드의 개발자 도구는 ⌥⌘J(P-1).
- **빠른 검색**: 도구 막대의 240 필드. 정보만 찾는다(제목·저자·연도·출판사·원래 이름·초록·메모): NFC·소문자, 짧은 필드의 초성, 2글자 부분 일치, 낱말 AND. 제목의 일치 강조, "N개 / M개", 결과 없음 상태, IME 안전, esc·↓.
- **항목 패널(인스펙터, 정보 모드)**:
  - 모드를 담는 그릇(전환 UI 없음), 폭 320(260–480) 기억, 좁은 창에서 먼저 접힘, F6 네 패널(사이드바 → 표 → 항목 패널 → 알림);
  - 머리(종류·쪽수·길이, 열기·Finder에서 보기, 파일이 없으면 다시 연결… — P-8), 정보 절 보기와 편집(검증 문구, 선택이 바뀔 때 저장·막기·버리기, 창 닫기 막기);
  - 파일 절(보관·크기·원래 이름·위치, SHA-256 앞 8자 + 전체 복사 — P-6·P-11), 선택 없음 통계, 여럿 요약;
  - 불러오는 중에는 도구 막대의 오른쪽 묶음과 항목 패널이 (비활성으로) 남아 목록이 도착해도 아무것도 튀지 않는다.
- **사본 내보내기**: 메인 창의 시트로 뜨는 저장 패널, 임시 이름 → rename, 결과 토스트의 Finder에서 보기. 목적지가 원본이거나 라이브러리 안이면 거절한다. 300ms를 넘는 복사는 바쁨 토스트(P-12·P-29).
- **팔레트 자료 결과**: 자료 묶음(최대 5, 제목 일치 → 다른 필드 → 마지막으로 연 시각), "라이브러리에서 ‘…’ 검색 ⌘F", 최근 실행 가중치, "검색 및 명령".
- **창과 IPC**: 창마다 preload와 채널마다 허용 창 종류(P-5), 설정 창 미리 만들기와 시트 측정 겹치기(P-4. 미리 만든 설정 창의 정리는 편집 flush 관문 뒤에 돌고 거절된 종료는 건너뛰며, 죽은 창은 새로 만들고, 보이기 전에는 느리게 돈다), 두 페이지가 같은 순간에 바꾸는 테마, 시트 부모 판정(m5). 창 닫기·⌘Q의 flush는 거절이면 곧바로 'invalid'로, 시간 초과는 따로 기록한다.
- **검증**: M4 키보드 전용 여정(명세 1절 조건 4), M4 상태마다 axe, 명령 전수 실행에 M4 명령 7개, 시각 투어의 M4 상태(라이트·다크), Mac `all` + 데모(M4 장 16개).
- **코드 규칙**: 주석에는 이유를 말로 쓰고 계획 번호는 커밋 메시지에 둔다(명세 8절의 "실행·비평 id"보다 엄격하다). 마일스톤 이름(M5…)은 로드맵 참조라 남는다.

### M4에서 나온 M5 입력 (M5에서 처리 — 결과는 아래 "M5 정리 결과")
- **컬렉션·태그**: 표의 색 점 열, 1–8 키(레지스트리에 `key`만 더하면 렌더러 키맵이 처리한다 — ADR-0005 §3), 항목 패널의 태그·컬렉션 절, 다중 선택의 공통 태그·컬렉션 절과 "컬렉션에 추가 ▾", 팔레트의 컬렉션 묶음과 결과 없음 제목 "‘…’와 일치하는 자료·컬렉션·명령이 없습니다", 검색 자리표시 "제목, 저자, 태그 검색", 검색 결과 없음의 둘째 동작 "내 라이브러리 전체에서 찾기". → **M5에서 해결**(Task 6·7·10): 표의 색 점(제목 셀: 제목 · 연결 표시 · 색 점 · 상태), 1–8 키(`tag.color1`–`8`), 항목 패널의 태그·컬렉션 절, 여럿 선택의 공통 절과 "컬렉션에 추가 ▾", 팔레트의 컬렉션 묶음과 결과 없음 제목, 검색 자리표시 "제목, 저자, 태그 검색", 결과 없음의 둘째 동작.
- **선택**: 컬렉션을 바꾸면 표 선택을 비우고 항목 패널은 "선택한 자료 없음"(디자인 명세 7.1, M4 명세 3.3). → **M5에서 해결**(Task 3·5): 보기를 바꾸면 표 선택과 태그 필터를 비우고 검색어는 남긴다.
- **DnD**: 표 행 → 컬렉션(⌘ = 이동, "자료 N개" 배지), 열 머리 끌기로 열 순서(`library.columns.order`는 이미 저장 형식에 있다), 사이드바 행의 드롭 대상(M3 비평 T3 minor 7: `ForcedState`에 `'drop'`, 상태 보드에 행). → **M5에서 해결**(Task 5·8·9): 행 → 컬렉션(복사, 이동 + 실행 취소, "자료 N개" 배지), 컬렉션 → 컬렉션, 태그 → 행, Finder → 창·사이드바 행, 열 머리 끌기(`library.columns.order`).
- **사이드바**: 컬렉션 트리, 최근 연 자료·미분류·중복 항목 보기(내용이 있을 때만), 빈 컬렉션 상태(표·항목 패널, 목업 `library.html?state=empty-collection`). → **M5에서 해결**(Task 5): 컬렉션 트리, 특수 보기 셋(내용이 있을 때만), 빈 컬렉션 상태.
- **측정**(Mac 러너 값이 목표를 넘었거나 실기에서 다시 볼 것): → **M5에서 해결**(Task 11): 드롭 뒤 멈춤·⌘/ 시트 열기·스크롤 p95는 바꾸지 않았다 → 아래 "실기에서만 확인할 것 (M5)"와 `mac-verification.md`의 M5 값(최종 run 41024983289: ⌘/ 시트 중앙값 288ms, 스크롤 p95 18.3ms — 둘은 목표를 넘었다. 드롭 뒤 최장 프레임 간격은 33ms로 목표 안이다. 앞선 run 40708161452는 550ms).
  - 드롭 뒤 멈춤: 러너에서 페이지 최장 프레임 간격 132–202ms(목표 100)와, 스크립트·스타일·레이아웃 귀속이 없는 1.1–1.7초 긴 프레임이 고치기 전·후 코드 모두에서 보였다(run 40136585407 · 40136294230 · 40136618624). 러너의 효과로 판단했다. 최종 run 40162034858은 34ms. 실제 Mac에서 확인한다(긴 프레임 자료는 `drop-import.json`).
  - ⌘/ 시트 열기: 러너 중앙값 약 290ms(목표 250). 기억한 높이가 거기서는 이득을 보이지 않는다 — 실제 Mac에서 재고, 시트 창을 만드는 비용을 본다. 설정 첫 열기는 30–50ms(목표 300 안).
  - Mac 러너의 스크롤 프레임 p95 18.7ms(예산 16.7ms)는 러너가 60Hz를 못 지켜서다(가만히 있어도 p95 약 33ms). 실제 Mac에서 확인한다.
  - 미리 만든 설정 창의 메모리는 `open-latency.json`에 기록한다(렌더러 작업 집합 약 125 MB, 메인 창 렌더러 약 146 MB — Mac run 40162034858).
- **레거시(마우스만 쓰는) 스크롤 막대**: 트랙패드가 없는 Mac에서 표의 세로 스크롤 트랙이 머리 행을 가로지른다(Task 3 비평). 머리를 세로 스크롤러 밖으로 옮기는 것을 고려한다. → **M5에서 해결**(Task 9): 머리 띠를 세로 스크롤러 밖으로, Mac "스크롤 막대 항상 보기" 캡처로 확인.
- **Linux의 역할 `<select>`**: 정보 편집기의 역할 칸이 Chromium 기본 화살표를 그린다(Task 7 비평). → **M5에서 해결**(Task 7): 자체 화살표.
- **키보드만의 열 정렬·폭**은 M4에 없다(계획 때부터의 M5 입력): "보기 › 정렬 기준" 하위 메뉴 또는 머리 행 진입. → **M5에서 해결**(Task 4): 보기 › 정렬 기준 ▸(열·방향). **열 폭·순서를 키보드로 바꾸는 길은 없다**(마우스 전용 꾸밈, 열 메뉴의 "되돌리기"가 남는다).
- **팔레트의 자료 순위**는 키 입력마다 일치 전부를 정렬하고 일치 종류(초성 대 글자)를 보지 않는다. 바꾸기 전에 1만 항목에서 잰다. → **M5에서 해결**(Task 10): 점수 한 번 + 상위 5 부분 선택(글자 일치 > 초성 > 다른 필드).
- **`library:searchTexts`**는 페이로드에 상한이 없다(모든 자료의 초록 + 메모). → **M5에서 해결**(Task 10): 필드마다 4,000 UTF-16 단위, 페이로드 크기를 `library-perf.json`에 기록.
- **M4 최종 검토에서 넘긴 것**(고치기 전에 1만 항목에서 잰다): → **M5에서 해결**(Task 4·7·9·10·11): 컨텍스트 메뉴 질의 한 번(`getItems`, 1만 개는 `targetFacts`), 쪽 수 탐침 디바운스, `MainWindow` 다시 그리기(렌더 계수기), `isComposingKey` 하나, 열 폭 기록 상한 64. 편집 flush 관문·로그아웃은 바꾸지 않았다 → 실기 목록.
  - 표의 오른쪽 클릭 메뉴는 main이 선택된 id마다 `getItem`을 한 번씩 부른다 — 1만 개 선택에서는 한 번의 질의로 바꾼다.
  - 항목 패널의 쪽 수 탐침은 선택이 바뀔 때마다 돈다 — 디바운스하거나 공유 워커 하나로 모은다.
  - 편집 flush 관문이 모든 창 닫기·종료를 붙잡는다 — macOS 로그아웃·재시동에서 종료가 막히지 않는지 실기에서 확인한다.
  - 빠른 검색에 한 글자 칠 때마다 `MainWindow` 전체가 다시 그려진다 — 검색 상태를 표와 도구 막대로 좁힌다.
  - 팔레트의 `rankItems` 정렬 키(위의 자료 순위와 함께), IME 조합 검사의 중복, 열 폭 기록의 개수 상한.
- **튜터 목업**은 그대로 M5와 병행한다(위 "튜터 목업"). (M5 동안 `tutor-mockup` 가지에서 진행)
- **RAC를 올릴 때**: 위 M3 항목(토스트 F6, 토스트 타이머)에 더해 M4 표 관련 항목은 없다(가상 표는 RAC 밖이다). M5: ADR-0004 "M5 끌어 놓기"의 "RAC를 올릴 때".

### 소유자 결정 (2026-10-26, M4 병합 뒤 후속 PR)
1. 같은 필드의 이름은 "원래 이름" 하나로 한다(열 머리·열 메뉴·항목 패널·검색 결과 없음 문구).
2. 선택 없음 항목 패널의 통계 줄은 2차색이다(목업 렌더와 같고, 12px에서 대비 4.5:1 이상).
3. 팔레트에서 저자 · 연도로만 맞은 자료 행은 그 부분을 강조한다.

## M5 정리 결과 (2026-10-28)

계획 [`superpowers/plans/2026-10-26-m5-organize.md`](superpowers/plans/2026-10-26-m5-organize.md), 명세 [`superpowers/specs/2026-10-26-m5-organize-design.md`](superpowers/specs/2026-10-26-m5-organize-design.md), 브랜치 `m5-organize`. 검증 숫자는 [`acceptance.md`](acceptance.md) 머리말과 AC02·AC16·AC18, Mac 실행은 [`mac-verification.md`](mac-verification.md) "M5 정리". 결정은 [ADR-0004](decisions/0004-ui-stack.md) "M5 끌어 놓기", [ADR-0005](decisions/0005-commands-menus-shortcuts.md) 1·3·4·5절, [ADR-0007](decisions/0007-settings-and-preferences.md)(새 키). 명세 정정은 [`spec-amendments.md`](spec-amendments.md) 9절.

### M5에서 해결한 것
- **정리 데이터와 보기 모델**: `library:organize` 스냅샷(컬렉션·태그·소속·붙임·중복 묶음) + 렌더러의 순수 계산(범위 → 태그 AND → 검색 → 정렬, 보기 전환에 IPC 없음), `library:getItems`(500개씩), 좁은 다시 받기, `opened` 알림, 가져오기의 `collectionId`, 컬렉션 복원 수정, 색 태그 자리 가로채기.
- **사이드바**: 특수 보기(최근 연 자료·미분류·중복 항목, 내용이 있을 때만) + 컬렉션 트리(RAC `Tree` in `Virtualizer`, 이름순, 펼침·보던 곳 기억, 하위 포함 개수), ⇧⌘N 이름 칸(IME 안전), 이름 바꾸기, 컬렉션 삭제 + 실행 취소(`ui:confirm`), 빈 컬렉션·빈 특수 보기 상태.

Finder 끌기를 컬렉션 행 위에 두고 esc → 창 밖으로 끌기 → ⌘-Tab 뒤 고리가 남지 않는지(창을 떠나는 정리는 CDP가 신뢰된 `dragleave`를 보낼 수 없어 단위 테스트만 있다).
- 끌기가 창을 떠날 때(검토 m-18, `dnd/events.ts:57`): Finder 파일이나 행을 끌고 있다가 창 밖에 내려 두고 가만히 있을 때 — 창 안의 드롭 고리가 사라지는지(창을 떠나는 판단이 `dragleave`의 `relatedTarget`에 기댄다). 창 안에서 행 사이를 지날 때는 고리가 깜박이지 않는지.
- 취소한 Finder 끌기(검토 m-19): esc로 취소한 뒤 포인터를 움직이지 않고 마우스를 누르거나 키를 누를 때도 드롭 표시가 지워지는지(포인터 이동은 E2E가 있다).
- IME: 실제 한글 IME로 새 컬렉션 이름 쓰기·칩 이름 바꾸기·태그 필터 칸·태그 추가 칸·팔레트에서 컬렉션 행 고르기(조합 중 ↩가 조합만 끝내는지).
- VoiceOver: 트리(구역·수준·펼침·개수), 태그 칩 묶음(도구 모음, "눌림", 흐린 칩의 "이 보기에 없음"), 항목 패널의 태그 칩과 경로 줄, 네이티브 메뉴 하위 메뉴의 체크, ⇧F10과 VO-⇧-M으로 컬렉션·칩 메뉴. 트리에 포커스가 있을 때 Finder 파일을 트리 행에 놓으면 "선택 안 됨"/"선택됨"을 한 번 읽는다(미분류가 보기를 가져가지 않게 선택을 잠시 비우는 값이다. 앱 안의 끌기는 이 안내를 내지 않는다).
- VoiceOver 놓은 뒤(af807d6, dnd (i)): VO-Space로 키보드 드롭을 한 뒤 VO+화살표가 곧바로 보기를 움직인다. 놓은 뒤의 붙잡기는 React Aria의 늦은 이동(드롭 렌더, 50ms 기다림과 놓은 것이 그려지기 중 늦은 쪽, 렌더, 프레임, runAfterTransition)이 지나면 끝나야 한다(m5-followup: main이 느려 옮긴 것이 늦게 그려져도).
- 키보드·화면: 실제 키보드의 숫자 1–8(한국어 입력 소스에서도), 컬렉션 범위에서의 실제 ⌘O 패널(컬렉션에 들어가는지 — 같은 패널이 컬렉션 id를 들고 돈다), Retina에서 12px 펼침 화살표의 대비.
- 네이티브 메뉴: 색 지정 줄의 색 점 아이콘, 메뉴 막대 다시 만들기가 열린 메뉴를 닫거나 깜박이게 하지 않는지, 1만 개 선택에서 오른쪽 클릭이 머뭇거리지 않는지(OS가 메뉴를 그리는 시간은 자동 측정에 없다).
- 편집 flush 관문과 macOS 로그아웃·재시동, M4 러너 측정 셋(드롭 뒤 멈춤, ⌘/ 시트 열기, 스크롤 p95)을 실제 Mac에서.

## M6 P1 게이트 결과 (2026-11-02)

### M6에서 해결한 것
- **P1 게이트**: 가져오는 도중 SIGKILL → 다시 켜면 점검 시트 → 정리·되살리기 → 백업 → 빈 폴더에 복원 → 그 폴더로 띄운 앱에서 해시·개수·컬렉션·태그·소속·휴지통이 같다(`p1-gate.spec.ts`, AC15).
- **가져오기 큐**: 메인이 큐와 작업 줄(가져오기·백업·복원이 한 줄)을 맡고, 창은 계속 쓴다. 작업마다 제자리 갱신 진행 토스트(앞의 작업을 기다리는 중 포함, 오래된 것이 위), 취소(지금 파일은 안전하게 멈추고 남은 것은 버림, 결과 "N개 중 M개를 가져왔습니다"), 중복은 끝에 모아 한 번 묻고 체크박스로 같은 선택(시트 창 안, 켠 채 열림), 가져오는 중 종료 확인. 500개를 넘는 드롭은 500개씩.
- **휴지통**: ⌘⌫로 바로 옮기고 실행 취소 토스트(5,000개씩), 사이드바 휴지통 행과 보기(컬렉션 행, 삭제한 날짜, 읽기 전용 패널), 복원(같은 표시의 하위만), 영구 삭제·휴지통 비우기(앱 시트, 참조 계산, DB 먼저·파일 나중, 외부 원본과 수정본은 지우지 않음), 리더의 휴지통 안내, 파일 메뉴 ⇧⌘⌫.
- **중복 정리·수정본**: "하나만 남기고 휴지통으로"와 "중복 N묶음 모두 정리"(가장 먼저 가져온 것을 남기고 소속·태그를 합침, 실행 취소), 항목 패널의 "다른 앱에서 고친 수정본" 줄(새 자료로 가져오기 · Finder에서 보기).
- **라이브러리 점검**: 시작 검사는 창을 만든 뒤 백그라운드, 정리할 것이 있고 목록이 바뀌었을 때만 자동 시트, 파일 › 라이브러리 점검…. 줄: 임시 파일, 쓰이지 않는 사본(되살리기·정리), 사라진 사본·외부 연결(다시 연결…), 손상된 사본, 주인 없는 수정본, 확인 줄.
- **백업·복원**: 폴더 백업(외부 연결은 위치만, 진짜 복사, 다시 읽어 해시 확인, 전부 아니면 전무), 새 폴더에 복원 + 교차 확인 + `quick_check`, 결과 시트, 전환 후 재시작, 설정의 마지막 백업, 치명 화면의 Finder에서 보기.
- **강화**: fsync, 오류 문구 매핑, NFC, HEIC·m4a 구분, 절대 경로, 재연결 itemId, 시작 지연 제거, DB 핸들 누수, 명령 파일 분리(E1), 같은 밀리초 복원(m-4), 부분 실패의 실행 취소(m-6).
- **검증**: 키보드 전용 여정(M6)과 M6 화면마다 axe, 명령 전수 실행에 M6 명령 9개, 시각 투어 M6 상태(기준 PNG 187장), vitest 2153개, 기능 E2E 4덩이 모두 통과(349개 통과, 건너뜀 4개), 증거 67개 통과 · 8개 건너뜀(macOS 전용), Linux CI run 41364707255(a59d135) · 최종 41465141441(1de7f19), 작업별 Mac `p1` 12회와 `perf` 1회, Mac `all` + 데모 run 41465193458(1de7f19, 성공 — 증거 73/0, 기능 E2E 348/0; 그 앞 0dca24e는 run 41392677791로 성공), 최종 Linux CI run 41465141441. ### M6에서 나온 M7 입력
- **성능 항목**(명세 2절의 M7 몫): M5의 E2·E6·m-1·m-8·m-9와 Mac에서 예산을 넘은 줄 — ⌘/ 시트 열기 중앙값 288ms(목표 250), 스크롤 프레임 p95 18.3ms(16.7), `library:organize` 60.7ms(50), `1` 키 하나의 붙임 119.1ms(100), 검색 입력 p95 57ms(50), `library:organize` 페이로드 2,001,990 B.
- **토스트 그리기 p95**: 예산 16.7ms를 한 프레임쯤 넘는다(Linux CI 17.0ms, Mac 18.1ms; 수정 뒤 CI 한 번은 16ms). 통과로 보지 않는다. 기준 장비에서 다시 재고, 넘으면 원인(갱신 경로, 그리기 비용)을 본다.
- **중단된 작업의 재개 화면**: `jobs`의 `interrupted`를 보이거나 다시 돌리는 화면은 없다. 추출 작업을 처음 소비하는 마일스톤이 만든다(지금은 아무도 `jobs`를 소비하지 않는다).
- **Dock·Finder "다음으로 열기"로 가져오기**(`open-file`): M14(패키지 앱의 문서 형식 등록 `CFBundleDocumentTypes`가 있어야 macOS가 보낸다).
- **자동 백업·보관 개수**: 없다(소유자 결정, 수동만). 필기·대화 인용·기억의 manifest 확장은 각 단계(M9·T1·M10).
- **치명 화면의 "백업에서 복원…"**: 없다(승인한 설계는 Finder에서 보기만 더한다). 필요하면 소유자 결정이 먼저다.
- **리더의 쪽 사이드바 줄**("복원하면 쪽이 보입니다", 휴지통 자료): 목업에만 있고 M7에서 그린다.
- **필기가 생기면**: 점검 시트의 확인 줄 "자료 기록"을 "자료와 필기"로, 영구 삭제의 앵커 규칙(자료별)을 ADR-0006 3절의 메모대로 다시 정한다(M9).

### 소유자 결정 (M6, 2026-10-31)
[M6 명세 0절](superpowers/specs/2026-10-31-m6-p1-gate-design.md)의 표가 정본이다(한 마일스톤으로, ⌘⌫는 바로 옮기고 실행 취소, 휴지통은 컬렉션과 자료를 함께, 가장 먼저 가져온 것을 남기고 합침, 백그라운드 큐, 취소는 남은 파일만, 남은 중복에 같은 선택, 가져오는 중 종료는 물어보고 멈춤, 점검은 정리할 것이 있을 때만 자동, 백업은 폴더·수동만·외부 연결은 위치만, 복원은 새 폴더 + 전환 후 재시작). 목업 승인(f4eaaac, 2026-10-31)의 소유자 판정 ①–⑦: ① 휴지통 항목 패널은 [복원] + 안내 한 줄 "휴지통에 있습니다 · <시각>에 옮김"(편집 단추 없음) ② 휴지통 보기 머리에 가져오기 단추 없음 ③ 컬렉션 행의 "자료 N개"와 삭제한 날짜 ④ "쓰이지 않는 사본" ⑤ 영구 삭제·비우기는 앱 시트(위험 단추 왼쪽, 기본 단추 취소) ⑥ 점검 시트는 할 일 줄이 먼저·목록만 스크롤(높이 상한) ⑦ 복원 결과는 "손상 없음"·"내용이 손상된 파일 N개"("해시" 말 금지). 같은 승인에서 소유자가 고친 것: 남김 표시는 2차색, 삭제 시트의 "외부 연결 원본"은 한 줄.

  1. 단일 행 영구 삭제의 시트 제목: "‘제목’을 영구히 삭제하겠습니까?" / "‘이름’ 컬렉션을 영구히 삭제하겠습니까?"(여럿·섞임은 그대로, 긴 제목은 두 줄에서 끝 "…").
  2. 복원 토스트: "‘제목’을 복원했습니다" / "‘이름’ 컬렉션을 복원했습니다" / "자료 N개를 복원했습니다"(섞이면 "자료 N개와 컬렉션 M개를").
  3. 휴지통의 선택 없음 통계 줄: 컬렉션이 있으면 "휴지통 · 자료 3개(PDF 1 · 동영상 2) · 컬렉션 1개 · 4.5 MB"(자료가 없으면 "휴지통 · 자료 0개 · 컬렉션 N개").
  4. 점검 시트의 열기 단추: "정리…" 대신 "지우기…"(확인 동사 "지우기"와 같다).
  5. 중복 정리 토스트: "중복 항목 N개를 휴지통으로 옮겼습니다".
- 설정 창의 라이브러리 위치(가운데 줄임)와 점검 시트의 "주인 없는 수정본" 줄의 이름·크기 사이 간격(Task 9 C-6 nit)은 Linux에서 바뀐 기준 PNG가 없다. Mac `all`의 PNG(`m6-07` 설정 창)로 본다.

### 실기에서만 확인할 것 (M6)
- 입력란에 포커스가 있을 때 메뉴로 들어온 ⌘⌫·⇧⌘⌫가 무시되는지, 표에 포커스가 있을 때는 실제로 동작하는지(Q-6e — Mac `p1`은 합성 키만 본다).
- 열기 패널을 점검 시트 위에 붙이는 "다시 연결…"(시트 위 시트): 실제 Mac에서 패널이 시트 위에 뜨고 취소하면 시트로 돌아오는지(Q-8g).
- `F_FULLFSYNC`의 실제 디스크 비용: 러너 VM의 import당 fsync는 1.3ms(Mac)·4.9ms(CI)로 실제 디스크를 대표하지 않는다. 대용량 폴더 가져오기에서 체감하는지(Q-2c).
- 백업 사본의 복사 속도와 취소 대기: 백업은 APFS 복제가 아니라 스트림 복사다(Q-9g). 러너는 79.4 MB에 86–132 MB/s다. 외장 디스크·다른 볼륨에서의 속도와, 큰 파일을 복사하는 도중 취소가 얼마나 빨리 멈추는지.
- 외장 디스크를 뺀 채 시작(외부 연결이 있는 라이브러리의 시작 지연이 없는지, 점검 시트가 자동으로 뜨지 않는지), 실제 전원 차단 뒤 0바이트 파일이 없는지.
- 미리보기에서 고친 PDF의 수정본 흐름: 읽기 전용 복사본을 열어 잠금을 풀고 저장한 뒤 "다른 앱에서 고친 수정본" 줄이 나타나고 새 자료로 가져와지는지.
- VoiceOver: 진행 토스트의 진행 알림, 점검 시트의 줄(이름 목록과 "외 N개"), 영구 삭제 시트의 위험 단추와 기본 단추 읽기, 휴지통 항목 패널의 안내 줄.
- 진행 토스트의 갱신이 깜빡이지 않는지(실제 Retina에서 1,500개 가져오기), 토스트 그리기 p95(위 "M6에서 나온 M7 입력").
- 종료 확인: 가져오는 중·백업 중 실제 ⌘Q의 문구와 기본 단추(끝내기), 취소했을 때 Linux·Windows처럼 메인 창이 다시 열리지 않는지(macOS).
- 라이브러리 전환의 실제 재시작(N-1): 설정의 "다른 폴더 선택…"과 복원 뒤 "전환"에서 앱이 끝나고 새 폴더로 다시 열리는지, 가져오는 중 종료 확인에서 "취소"하면 폴더가 그대로이고 다음 ⌘Q에 재시작하지 않는지.

### 소유자 결정 (M7a, 2026-11-03)

### 실기에서만 확인할 것 (M7a)
- **Retina 앵커 위치**: Mac 러너는 1024×768 @1x라 DPR 2를 잴 수 없다. 오차는 1/DPR로 줄기만 하므로 안전 쪽이지만, 실기에서 50% 확대의 앵커 어긋남이 2 pt 안인지 한 번 본다(ADR-0009).
- **실제 1440×900 Mac에서 ⌘/ 시트가 맞는지**: 자연 높이는 754(상한 770)이고 러너는 1024×684로 줄어 스크롤이 맞게 동작한다. 실기에서는 스크롤 없이 들어가야 한다(R-10, R-14).
- **VoiceOver로 선택 팝업**: 팝업은 포커스를 가져가지 않고 Tab으로 들어간다. 동의·결과·오류가 읽히는지, 찾기에서 돌아갈 때 "처음부터 다시 찾았습니다"가 읽히는지.
- **트랙패드 핀치 확대**: 시험은 합성 입력뿐이다.
- **트랙패드 Mac(오버레이 스크롤 막대)**: 시험과 러너는 고전 스크롤 막대다. 오버레이 막대에서 찾기 막대가 무대 오른쪽 끝에서 16, 썸네일이 가운데인지 본다(R-24).
- **실제 번역 한 번(R-17)**: 시험은 실제 엔진과 `remoteFetch` → `net.fetch` 경로를 돌리지만 번역 주소의 답은 시험 처리기가 준다. 앱에서 영어 문장 하나를 골라 번역 켜기 → 번역이 나오는지, 같은 문장을 다시 고르면 바로 나오는지(캐시) 한 번 본다.

### M7b에서 해결한 것
- **탭**: 자료 하나에 탭 하나(Zotero식). ↩·더블클릭은 그 자료의 탭으로, ⌘↩는 뒤에서 연다(여러 개 열기, 11개 이상은 확인 시트). 라이브러리 탭은 줄 맨 앞에 고정되고 리더 탭만 가로로 스크롤한다. ⌘1…⌘9 · ⌃⇥ · ⌘W · ⇧⌘T, 탭 컨텍스트 메뉴(네이티브), 끌어서 순서 바꾸기와 ⌥⇧←/→, 포커스된 탭의 Delete/Backspace. 탭 줄은 손으로 쓴 tablist다(R8).

### PR 남은 것 (M7b 브랜치 전체 검토, 고치지 않고 넘김)
컨트롤러가 브랜치 전체 검토 뒤에 고친다. 작업 검토에서 나온 minor 가운데 이후 고치지 않은 것의 초안이다.
- 리더 store(Task 2·5): 효과 하나의 의존성에 `scope`가 없음, main의 `translation.cancel()`이 전역인데 요청 상태는 scope별이라 탭을 내릴 때 `reset()`이 진행 중인 전역 번역을 취소할 수 있다(아주 좁은 창).
- `PdfDocumentView`(Task 3): `jumped`가 같은 쪽의 `textlayerrendered`로만 지워져, 나중 다시 그리기가 낡은 값으로 스크롤을 당길 수 있다. `widestShown`/`widestPage`의 이중 swap이 읽기 어렵다.
- 세션 복원(Task 4·R6): SIGKILL이 300ms 묶음 안이면 마지막 탭 변경을 잃는다(명세 3.6의 "마지막 묶음까지"와 같은 계약). reload 표본기는 진짜 재실행이 아니다(재실행은 `tabs.spec`의 종료·SIGKILL 시험이 지킨다).
- 탭 줄(Task 5·6): 탭 패널 연결 없음(위 M7c 입력), 리더 가린 뒤 선택 팝업 닫힘·같은 크기 무재맞춤·`jumped` 회귀에 시험이 없음, ⌘W를 편집 폼이 열린 라이브러리 탭에서 시험하지 않음, reduced-motion 끌기 시험 없음.
- 뒤로/앞으로(Task 7): 썸네일 ↑/↓는 기록하지 않는다(R14 — 썸네일을 키로 멀리 넘기면 시작한 자리로 돌아갈 길이 없다). 찾기가 만든 이동은 80b795b부터 `leaveLink`가 포기한다(착지에서 2px보다 멀리 스크롤하면 찾기의 것도) — 남은 것은 R29의 같은 프레임 잔여뿐이다. `holdTextLayers`가 prototype 가로채기를 되돌리지 않고 모든 쪽을 붙든다(앱이 시험마다 새로라 무해).
- 번역(Task 11): 빠르게 두 번 `saveTranslationPrefs`를 다른 필드로 부르면 하나를 잃을 수 있다(이전부터). 시작이 `setHandle` 뒤에 던지고 효과가 이미 취소된 경우 `catch`가 핸들을 남긴다(`cancelled`가 새 핸들 지우기를 막는다). M7a 입력의 낡은 핸들 줄은 이 좁은 경우를 뺀 나머지만 해결한 것이다. 쪽 색·찾기 막대 보호 시험은 고치기 전에 실패한 적이 없는 안전망이다.
- 성능 시험(Task 12): 종료 사건 기다림이 시험 한도로만 끊긴다, `seed()`가 파일을 제목 앞부분으로 찾는다, rAF 끝은 화면 표시 시각이 아니다(앞 시험과 같은 약속), 0으로 채운 기록과 인덱스 거름이 약하다. 내려간 탭으로의 전환(~350ms)은 작은 리더의 1쪽이고 대부분 문서 열기다. 살려 둔 탭 전환의 최댓값 85.1ms는 예산 100과 15ms 차이다.
- 데모(Task 13b): 8장의 장 프레임(3초 지점)이 종료·재실행 중이라 검다(영상은 정상). Mac에서 ⌘↩·⌃⇥는 `nativeKeyCode` 36/48, 탭 끌기는 `glide()`가 시스템 커서를 옮기는데 모두 Mac에서 시험하지 않았다.
- 투어 `tab-states-light`의 호버 선택자(Task 13a M4)는 그대로 뒀다. 데모 증거가 다시 열기 뒤 쪽 20|21을 모두 받아들인다(`demo.evidence.ts`, Task 3). 120 폭 비활성 탭이 숨은 닫기 칸 24px을 비워 둔다(R5, 비평 n5 — M1 승인 사항). `Boot`가 `reader.pageColor` 읽기를 하나 더 기다린다(Task 11).
- 같은 프레임의 잔여(R29)와 목차 현재 표시 스크롤(위 M7c 입력).
