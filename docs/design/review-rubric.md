# 디자인 비평 기준 (Learn)

디자인 비평 에이전트와 사람이 **목업 렌더(M1)** 와 **구현 스크린샷(M3 이후, Linux 투어 + macOS 증거)** 을 같은 기준으로 판정한다. 기준 문서는 `docs/design/design-spec.md`, 수치의 원천은 `tokens.ts`.

## 입력
- 렌더: `docs/design/renders/<화면>-<테마>-<레이아웃>.png`(1440×900 @2x), 변형 `<화면>--<상태>-…png`, 대조표 `docs/design/contact-sheet-*.jpg`, macOS 증거 `evidence/mockups/*.png`.
- 상태 확인: `components.html?part=1|2` 렌더, 마일스톤 표시 `?ms=1` 렌더.
- 세부는 원본 PNG를 1:1로 잘라 본다(대조표만으로 판정하지 않는다).

## 점검 항목

### 1. 격자와 간격
- 모든 간격·크기가 4px 격자(반 단계 2·6은 아이콘-글자 간격만). 패널 머리 44, 도구 막대 52, 표 머리 28, 행 `--row-height`.
- 같은 종류의 요소는 같은 세로선에 맞는다(사이드바 섹션 머리 = 행 아이콘, 표의 첫 열 머리 = 아이콘 왼쪽 끝이고 나머지 열 머리 글자 = 셀 글자, 항목 패널 섹션 안쪽 16, 팔레트 안의 모든 왼쪽 끝 = 행 아이콘 열).
- 안쪽 여백은 4의 배수, 2·6은 아이콘-글자 `gap`에만.
- 레이아웃 B: 사이드바 위 88px(신호등·토글·⌘K 실행기)이 모든 탭에서 같고, 사이드바 폭과 탭 줄 시작점이 탭을 바꿔도 움직이지 않는다.
- 트리: 수준마다 정확히 16 들여쓰기, 하위 항목 아이콘이 상위보다 오른쪽.

### 2. 타입 스케일·위계·밀도
- 역할 밖의 크기·굵기가 없다(4절 표). 한 화면에 제목 위계가 3단을 넘지 않는다.
- 내용(자료 제목, 쪽, 영상)이 크롬보다 눈에 먼저 들어온다.
- 표·사이드바 밀도가 Zotero/Finder와 비슷하다(보통 28px, 한 화면 25행 안팎).

### 3. 한국어 타이포
- `keep-all` 줄바꿈, 어절 중간 끊김 없음, 한 단어 마지막 줄(고아) 없음, 숫자+단위·"G 단백질" 같은 묶음이 갈라지지 않음.
- 사용자·자료 텍스트(자막, 대본, 제목)에 `text-wrap: pretty` 금지, 자료 쪽 안은 음절 단위 줄바꿈.
- 사용자 문장에 내부 용어(SHA-256, 해시, staging, 관리형) 없음.
- 관형사+명사(이 컬렉션, 다른 낱말)·짧은 복합어(쪽 번호, 디스크 공간)가 갈라지지 않음. 렌더 보고의 `copyLint`가 0건.
- 한글 UI에 700 없음, 행간이 역할 값과 같음(문단 13/20, 14/22).
- 말줄임은 한 줄 셀에서만, 툴팁 또는 항목 패널에서 전체가 보인다.

### 4. 상태 완비
- 각 대화형 요소에 기본·호버·누름·포커스(링)·비활성이 정의되어 있고, 목록에는 선택(포커스/비포커스)·드롭 대상, 화면에는 빈 상태·로딩·오류가 있다.
- 한 화면에서 강조 채움 선택은 하나(포커스를 가진 곳)뿐.

### 5. 라이트/다크 대등
- 같은 화면의 두 테마에서 정보·위계가 같다. 다크에서 사라지는 경계·아이콘·점이 없다.
- 다크: 내용 < 사이드바 < 크롬 < 떠 있는 면 명도 순서, 떠 있는 면의 고리·안쪽 하이라이트.

### 6. Mac 관례
- 52px 막대, 신호등 (18,18) 근처와 84px 인셋, 신호등이 스크림·오버레이에 가려지지 않음(네이티브).
- 사이드바 비브런시 자리, 사이드바 아이콘 강조색, `⌘` 기호와 ⌃⌥⇧⌘ 순서, "…" 표기.
- 컨텍스트 메뉴·메뉴 막대는 네이티브(웹으로 흉내 내지 않음). 웹 팝업 메뉴는 버튼에 정렬.
- 대화상자는 도구 막대 아래에 붙는 시트(스크림 없음), 설정은 별도 창(완료·× 없음, 즉시 적용).
- 탭이 하나뿐이면 탭 줄 대신 통합 도구 막대.

### 7. 대비
- `tokens.test.ts` 통과가 전제. 화면에서 토큰 밖 색을 쓴 곳, 3차색을 정보성 본문에 쓴 곳은 지적한다.

### 8. 동작 없는 컨트롤 금지
- 현재 마일스톤에서 동작하지 않는 컨트롤이 구현 화면에 보이면 **blocker**. 목업에서는 10절 카탈로그에 마일스톤이 적혀 있어야 한다(없으면 major).
- 렌더 보고(`docs/design/renders/report.json`)의 `milestones.missing`이 0건이어야 하고, `milestones.txt`의 태그 목록이 10절 표와 같아야 한다. `?ms=1` 렌더의 배지는 요소 안쪽에 있고 다른 정보(개수, 손잡이)를 가리지 않는다.
- 모든 메뉴(팝업 단추, "…")의 항목이 명세 7.3에 있어야 한다. 없으면 그 단추는 그리지 않는다.
- 잠시 지나가는 상태(여는 중)는 컨트롤을 비활성으로 두고, 끝난 상태(열기 실패, 암호, 원본 없음)는 쓸 수 없는 컨트롤을 숨긴다.
- 빈 라이브러리의 검색 필드처럼 대상이 없는 컨트롤도 그리지 않는다.

### 9. 내용의 사실성
- 실존 인물·기관 사칭 없음, 숫자가 화면 사이에서 일관(쪽 42/68 = 62%, 18:20/52:10 = 35%).

## 심각도
- **blocker**: 기능·신뢰를 해친다. 동작하지 않는 컨트롤 노출, 읽을 수 없는 대비(<3:1 본문), 신호등과 내용 겹침, 데이터 손실을 암시하는 문구, 잘못된 단축키 충돌.
- **major**: 명세 위반이 눈에 띈다. 격자에서 4px 이상 어긋남, 트리 정렬 오류, 상태 누락, 테마 간 정보 차이, 한국어 어절 끊김, 토큰 밖 색.
- **minor**: 품질이 떨어진다. 2px 어긋남, 아이콘 크기·선 불일치, 말줄임 위치, 고아 줄, 여백 리듬.
- **nit**: 취향·미세 조정.

M1 완료 조건은 blocker·major 0건이다.

## 보고 형식
항목마다 한 줄 요약 다음에:

```
[major] 트리 하위 항목이 상위 아이콘보다 왼쪽에 있음
- 파일: docs/design/renders/library-light-A.png
- 영역: x 40–200, y 600–700 (CSS px; @2x 원본은 ×2)
- 기준: 명세 6절 트리 "모든 행에 16px 펼침 칸", 루브릭 1
- 수정안: .nav-row padding-left = 16 + indent×16, 펼침 화살표는 absolute left 2 + indent×16
```

여러 화면에 같은 문제가 있으면 하나로 묶고 파일을 나열한다. 칭찬이나 총평은 맨 끝 3줄 이내.
