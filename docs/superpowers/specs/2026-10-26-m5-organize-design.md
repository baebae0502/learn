## 0. 소유자 결정 (2026-10-26)

| 결정 | 확정 | 버린 안 |
|---|---|---|
| 상위 컬렉션을 고르면 | **하위 컬렉션의 자료까지 보인다.** 개수도 하위를 포함하고, "이 컬렉션에서 빼기"는 이 컬렉션과 그 하위에서 함께 뺀다(보던 자리에서 사라진다) | 직접 넣은 자료만(Zotero 기본 — 자료를 모두 장에 넣으면 과목이 비어 보인다), 보기 메뉴 토글(설정 하나와 두 가지 뜻이 생긴다) |
| 컬렉션 삭제 | **M5에서 삭제 + 실행 취소.** 컨텍스트 메뉴 "컬렉션 삭제…" → 확인 시트(하위 컬렉션도 함께, 자료는 남는다) → 토스트 "실행 취소". DB는 이미 감추기로 지우므로 M6에서 휴지통이 생기면 거기 나타나고 메뉴 이름이 "휴지통으로 이동"이 된다 | 디자인 명세 그대로 M6까지 삭제 없음(잘못 만든 컬렉션을 지울 수 없다) |
| M4 잔여 항목 | **모두 M5에 넣는다**(11절). 항목마다 M5가 어차피 고치는 자리(컨텍스트 메뉴, 검색, 팔레트, 열 머리, 항목 패널)에 있다. 성능 항목은 1만 항목에서 먼저 잰다 | 기능만 M5, 나머지 M6 |
| 컬렉션을 보는 중의 가져오기 | **보는 컬렉션에도 넣는다**(Zotero와 같다). ⌘O·창 드롭 모두. 드롭 오버레이 제목과 결과 토스트에 컬렉션 이름이 나온다. 내 라이브러리·특수 보기에서는 넣지 않는다 | 늘 내 라이브러리에만(컬렉션 보기에서 가져온 자료가 표에 안 보인다) |
| 보기별 거르기의 구조 | **정리 스냅샷 + 렌더러 계산**: main은 컬렉션·태그·소속·태그 붙임·중복 묶음을 한 번에 보내고(`library:organize`), 보기·태그 필터·사이드바 개수는 렌더러가 계산한다. 보기 전환은 IPC가 없고, 태그·컬렉션을 바꾸면 스냅샷만 다시 받는다 | main이 보기마다 id 목록(전환마다 IPC, 개수는 따로 질의), 보기마다 자료 목록 전체(전환마다 무거운 목록과 검색 색인) |

함께 정한 것(질문 없이, 근거와 함께 — 소유자가 3절 설계를 승인하며 같이 승인했다):
- 형제 컬렉션은 **이름순**이다(`Intl.Collator('ko', { numeric: true })`: 6장 < 7장 < 10장). 직접 끌어 정렬하는 순서는 없다 — 스키마에 순서 열이 없고(`collections-repository.ts`: "Name sorting is the renderer's job"), 디자인 명세 7.2의 컬렉션 끌기는 "하위로 옮기기"뿐이다.
- 트리에서 ↑↓로 움직이면 보기가 곧바로 바뀐다(Zotero·Finder 사이드바).
- ⇧⌘N은 Finder의 새 폴더처럼 트리 안에 새 행을 만들고 바로 이름을 고친다(대화상자 없음). 태그 이름 바꾸기도 칩 안에서 고친다. 그래서 두 이름의 "…"를 뺀다(16절).
- 태그 필터는 여러 태그를 고르면 **모두 가진 자료**(AND, Zotero와 같다 — 품질 계획의 M5 줄).
- 태그 삭제는 DB에서 지우므로 확인 시트만 있고 실행 취소는 없다.
- 보기를 바꾸면 표 선택과 태그 필터를 비우고 빠른 검색어는 남긴다.
- 중복 항목 보기는 M5에서 찾아보기만 한다. 정리하는 동작(하나만 남기고 휴지통으로)은 M6에서 휴지통과 함께 온다.

## 3. 보기와 사이드바

### 3.1 보기 모델
- 라이브러리 보기의 범위 `LibraryScope = { kind: 'all' } | { kind: 'recent' } | { kind: 'unfiled' } | { kind: 'duplicates' } | { kind: 'collection'; id: string }`. 범위는 `useShell`의 `View`가 아니라 라이브러리 저장소 `useLibrary`가 가진다 — 리더에 갔다 오면 같은 범위로 돌아와야 하는데 `View`를 만드는 곳이 여럿이라 범위를 거기 실으면 돌아올 때마다 다시 넘겨야 한다. `useLibrary.scope`는 사용자가 고른 값이고, 없어진 컬렉션은 읽을 때 `all`로 해석한다(P-1, Q-12).
- 지금 범위는 라이브러리 설정 키 `library.view`에 남겨 다시 시작해도 그 보기로 돌아온다. 그 컬렉션이 없어졌거나 특수 보기에 내용이 없으면 `all`로 연다.
- 표의 행 = 스냅샷(10절)으로 계산한 범위의 자료 → 태그 필터(4.3) → 빠른 검색(7.1) → 정렬. 범위·필터 계산은 메모이즈한 선택자이고 IPC가 없다.
- 컬렉션 범위는 **그 컬렉션과 살아 있는 모든 하위 컬렉션**의 자료(서로 다른 자료, 0절).

### 3.2 특수 보기 (디자인 명세 6 "트리": 내용이 있을 때만 나타난다)

| 행 | 아이콘 | 개수 | 나타나는 조건 | 내용 |
|---|---|---|---|---|
| 내 라이브러리 | `library-big` | 있음 | 늘 | 휴지통에 없는 모든 자료 |
| 최근 연 자료 | `clock` | 없음(목업) | 30일 안에 연 자료가 있을 때 | `openedAt`이 30일 안인 자료 |
| 미분류 | `inbox` | 있음 | 컬렉션이 하나 이상 있고 그런 자료가 있을 때 | 살아 있는 어느 컬렉션에도 직접 들지 않은 자료 |
| 중복 항목 | `copy` | 있음 | 그런 자료가 있을 때 | 같은 파일(SHA-256)을 쓰는 자료가 둘 이상인 묶음의 자료 전부 |

- 지금 보고 있는 특수 보기는 내용이 없어져도(예: 미분류의 마지막 자료를 컬렉션에 넣음) 떠날 때까지 행이 남고, 표는 그 보기의 빈 상태를 보인다(3.6).
- **최근 연 자료**의 정렬은 이 보기만 따로 기억한다(`library.sort.recent`, 기본 `openedAt` 내림차순). 이 보기에서는 새 열 "마지막으로 연 날"(5.1)이 제목 다음에 늘 보이고 열 메뉴에서 체크된 채 비활성이다.
- 리더에서 자료를 열면 main이 `libraryChanged { reason: 'opened', itemIds: [id] }`를 알리고, 렌더러는 그 자료만 다시 받는다(10.3). 그래서 리더에서 돌아오면 최근 연 자료가 맞다(M2에서 미룬 "열기 알림"을 닫는다).

### 3.3 컬렉션 트리
- "컬렉션" 묶음 머리(`.section-label`) 오른쪽에 아이콘 단추 "새 컬렉션"(`folder-plus`, 툴팁 "새 컬렉션 ⇧⌘N"). 그 아래 트리.
- 행(디자인 명세 6 "트리"): `--row-height`, 모든 행에 16px 펼침 칸, 수준마다 16 들여쓰기, 아이콘 `folder`(펼침이면 `folder-open`), 이름(끝 말줄임 + 전체 경로 툴팁), 오른쪽 개수(하위 포함 서로 다른 자료 수, footnote 3차색 — 선택 행에서 2차색). 개수가 0이면 숫자를 쓰지 않는다(목업 "학회 준비").
- 펼침 상태는 라이브러리 설정 키 `sidebar.expanded`(컬렉션 id 목록)에 기억한다. 처음 만든 하위 컬렉션의 부모는 펼친다.
- 컬렉션이 하나도 없으면 트리 자리에 안내(`.sidebar-empty-hint`, 목업 `library-empty.html`): "컬렉션이 없습니다. 자료를 묶으려면 새 컬렉션을 만드세요."
- 선택: 트리와 특수 보기는 한 번에 하나(지금 보기)다. 클릭·↑↓가 보기를 바로 바꾼다. 강조 채움 규칙은 M3 `.nav-row`와 같다(사이드바에 포커스가 있으면 `--accent`, 아니면 `--fill-selected`, 창이 비활성이면 중립).
- 키보드: ↑↓는 특수 보기와 트리를 이어서 움직인다. → 펼치기(펼쳐져 있으면 첫 하위로), ← 접기(접혀 있으면 상위로), ↩ 이름 바꾸기, Home/End, ⇧F10 컨텍스트 메뉴(9.1). 더블클릭은 펼치기·접기. type-ahead 없음(디자인 명세 7.1).
- 사이드바 안의 Tab 순서: 특수 보기·트리(하나의 포커스 정거장, 롤링 `tabindex`) → 태그 선택기의 "…" 단추 → 칩 묶음(하나의 정거장) → 태그 필터 칸(4.3, 승인된 목업의 순서 — Q-60). F6 순서는 그대로(사이드바 → 표 → 항목 패널 → 알림).
- 상태 보드(`Gallery`)의 "사이드바 행"에 드롭 대상(`ForcedState 'drop'`), 펼침 칸이 있는 행, 들여쓴 행, 편집 중인 행을 더한다(next-session "M4–M7로 넘기는 항목"의 M5 줄).

### 3.4 만들기 · 이름 바꾸기 · 삭제
- **새 컬렉션**(⇧⌘N, 파일 메뉴, 머리 단추, 팔레트): 사이드바가 가려져 있으면 보이고, 최상위에 "새 컬렉션" 행을 만들어 이름 칸으로 바꾼다(이름 전체 선택). ↩ 또는 칸 밖 클릭 = 만들기, esc = 만들지 않음. 만든 뒤 그 컬렉션으로 보기를 옮기지 않는다(Finder의 새 폴더와 같다 — 지금 보던 표가 그대로 남는다).
- **새 하위 컬렉션**(컬렉션 메뉴, 팔레트 — 팔레트에서는 지금 보는 컬렉션 아래): 부모를 펼치고 그 아래에 같은 식으로 만든다.
- **"컬렉션에 추가 ▸ › 새 컬렉션"**(자료 메뉴·다중 선택 단추): 같은 식으로 만들고, 만들어지면 그때의 대상 자료를 넣는다. esc면 아무것도 넣지 않는다.
- **이름 바꾸기**(트리의 ↩, 컬렉션 메뉴, 팔레트): 같은 행이 이름 칸이 된다. ↩ 저장, esc 취소, 빈 이름이나 공백만이면 원래 이름으로 돌아간다(오류 없음). 200자를 넘으면 칸 아래 footnote "컬렉션 이름은 200자까지 쓸 수 있습니다."로 막는다. 형제끼리 이름이 같아도 된다(DB 규칙, Zotero와 같다).
- 이름 칸은 IME 안전이다: 조합 중의 ↩·esc는 조합만 끝낸다(M4 검색 필드의 규칙).
- **컬렉션 삭제…**(컬렉션 메뉴 맨 아래, 팔레트 — 지금 보는 컬렉션): 메인 창에 붙는 네이티브 확인 시트(`ui:confirm` — 범용 채널 `{ message, detail?, confirm }` → boolean, 단추 [확인, 취소], 기본 단추 = 확인, Q-57. 확인 단추의 이름은 `confirm`(여기서는 "삭제")이고, 주의 아이콘은 `caution`일 때만 — 실행 취소가 있는 컬렉션 삭제는 앱 아이콘이다). 문구 "‘<이름>’을(를) 삭제하겠습니까?"(합니다체 의문형, 해요체 예외를 만들지 않는다)(와/과·을/를은 M4의 조사 규칙) + 하위가 있으면 "하위 컬렉션 N개도 함께 삭제합니다." + "자료는 내 라이브러리에 남습니다." 삭제하면 토스트 "‘<이름>’을(를) 삭제했습니다." + "실행 취소". 지금 보던 컬렉션(또는 그 조상)을 지웠으면 보기가 지운 컬렉션의 부모로(최상위였으면 내 라이브러리로) 옮겨 간다.
- **복원 수정**: `CollectionsRepository.restore`가 따로 먼저 지운 하위 컬렉션까지 되살리던 문제(next-session "M2에서 나온 후속 입력", M6로 미뤘던 것)를 지금 고친다 — 실행 취소가 이 경로를 바로 드러내기 때문이다. 루트와 **같은 `deleted_at`을 가진 하위**만 되살리고, 지운 조상은 지금처럼 되살린다(`softDelete`는 이미 먼저 지운 하위의 시각을 그대로 둔다). 마이그레이션은 필요 없다. 같은 `deleted_at` 문자열을 한 묶음으로 센다 — 같은 밀리초의 삭제는 한 묶음이다(Q-3).

### 3.5 보기를 바꿀 때 (디자인 명세 7.1)
- 표 선택을 비우고(항목 패널은 "선택한 자료 없음"), 태그 필터를 비우고, 표를 맨 위로 스크롤한다. 빠른 검색어는 남긴다 — 그래야 "내 라이브러리 전체에서 찾기"(7.1)가 보기만 바꾸는 동작이 된다.
- **예외** 하나: 항목 패널의 컬렉션 경로를 눌러 옮겨 가면(6.1) 그 자료를 고른 채로 두고 그 행이 보이게 스크롤한다.
- 리더로 갔다 오는 것은 보기 전환이 아니다(M4 규칙 그대로: 선택 유지, 마지막으로 연 행이 보이게).
- 도구 막대 제목 = 보기 이름(컬렉션은 이름만, 툴팁에 전체 경로). 선택 없음 항목 패널의 통계는 그 보기의 것("분자생물학 · 자료 48개(PDF 35 · 동영상 13) · 1.9 GB").

### 3.6 빈 상태
- **빈 컬렉션**(목업 `library.html?state=empty-collection`): 표 몸통에 `folder-open` 아이콘, "이 컬렉션은 비어 있습니다", "다른 컬렉션의 자료를 사이드바의 ‘<이름>’(으)로 끌어 놓거나, 파일을 바로 이 컬렉션으로 가져오세요.", 단추 "이 컬렉션으로 가져오기…". 항목 패널: `folder` 아이콘, 이름, "자료 0개 · <만든 날> 만듦"(디자인 명세 9절 날짜 형식). 하위에만 자료가 있으면 빈 컬렉션이 아니다(0절).
- **빈 특수 보기**(지금 보는 중에 비었을 때만, 3.2): 최근 연 자료 "최근 30일 안에 연 자료가 없습니다", 미분류 "모든 자료가 컬렉션에 들어 있습니다", 중복 항목 "중복된 자료가 없습니다". 동작 없음.
- **태그 필터 결과 없음**(검색어가 없을 때): "고른 태그를 모두 가진 자료가 없습니다", 설명 한 줄 "고른 태그 N개(이름 · 이름)로 거른 결과입니다."(이름은 고른 태그가 3개 이하일 때만, 넘으면 개수만 — 디자인 명세 6의 빈 상태 문법, 컨트롤러 판정), 단추 "태그 선택 해제". 검색어도 있으면 검색 결과 없음(7.1)이 이기고, 그 설명에 "고른 태그 N개로 거른 결과입니다."를 덧붙인다.
- 빈 라이브러리는 M3 `EmptyLibrary` 그대로(사이드바에는 "내 라이브러리"와 컬렉션 안내만, 태그 선택기 없음 — 목업 `library-empty.html`).

### 3.7 컬렉션으로 가져오기
- 가져오기 입력(`library.import`, `library.pickAndImport`)에 `collectionId?: string | null`을 더한다. main의 가져오기가 자료를 넣는 같은 DB 트랜잭션에서 소속을 넣는다. 그사이 컬렉션이 지워졌으면 소속만 건너뛴다(가져오기는 성공).
- **누가 `collectionId`를 넣나**: 컬렉션 범위에서의 ⌘O·⌥⌘O·창 드롭(0절), 컬렉션 메뉴·빈 컬렉션의 "이 컬렉션으로 가져오기…"(열기 패널, 사본 가져오기), Finder → 사이드바 컬렉션 행(8.4). 내 라이브러리·특수 보기 범위와 "내 라이브러리" 행 드롭은 넣지 않는다.
- 드롭 오버레이 제목: 컬렉션 범위면 "‘<이름>’(으)로 가져오기", 아니면 지금 문구 그대로. 결과 토스트: "‘<이름>’에 자료 N개를 가져왔습니다."(가져오기 결과 토스트의 나머지 규칙은 그대로).
- 중복 시트(AC02)에서 "가져오지 않음"을 고른 파일은, 시트가 닫힌 뒤 렌더러(`settleImport`)가 `collections.addItems`로 이미 있는 그 자료를 컬렉션에 넣는다 — main의 가져오기는 시트를 모르므로 가져온 자료만 넣고(`ImportReport.filed`), 건너뛴 자료는 `filedExisting`으로 센다. 결과 토스트에 "이미 있는 자료 N개를 ‘<이름>’에 넣었습니다."를 덧붙인다(Q-1, Q-59).

## 4. 태그

### 4.1 규칙
- 이름: NFC·앞뒤 공백 정리, 1–200자, 대소문자를 가리지 않고 하나뿐(DB 규칙 그대로).
- **이름 바꾸기**(칩 안에서 바로, 4.3): 이미 있는 다른 태그의 이름이면 네이티브 확인 시트 "‘<이름>’ 태그가 이미 있습니다. 두 태그를 합치겠습니까?"(기본 "합치기") → DB의 병합(붙임은 그 태그로 옮기고 이 태그는 지운다, 남는 태그의 색은 그대로).
- **색 N = 자리 N = 키 N**(Zotero와 같다). DB는 색과 자리를 따로 받지만 화면은 늘 함께 바꾼다: "색 지정 ▸ 3 초록" = `setColor(id, 'green', 3)`. 자리 3을 다른 태그가 쓰고 있으면 그 태그의 색과 자리가 함께 풀린다. 지금 DB의 `setColor`는 가로챈 태그의 자리만 풀고 색은 남기므로, 색도 함께 풀도록 고친다(이 앱에서 색과 자리는 늘 짝이다 — 호출 한 번, 트랜잭션 한 번). "색 해제" = 색·자리 모두 `null`. 색 8개 이름과 값은 디자인 명세 4절(`TAG_COLORS`).
- **태그 삭제…**: 확인 시트 "‘<이름>’ 태그를 삭제하겠습니까? 자료 N개에서 떼어집니다."(기본 "삭제"). 실행 취소는 없다(0절).
- 태그는 항목 패널에서만 만든다(6.1 "태그 추가"). 태그 선택기에는 만들기가 없다(목업).

### 4.2 1–8 키 (ADR-0005 §3)
- 레지스트리 명령 `tag.color1`–`tag.color8`(키 `Digit1`–`Digit8`, 9.3). 라이브러리 보기에서 선택이 하나 이상이고 글자를 입력하는 중이 아니면 자리 N의 태그를 붙이거나 뗀다(`togglePosition`: 고른 자료가 모두 가졌으면 모두에서 떼고, 아니면 모두에 붙인다).
- 자리 N에 태그가 없으면 토스트 "색 태그 N이(가) 없습니다. 태그의 컨텍스트 메뉴에서 색을 지정하세요."
- 한국어 조합 중(`isComposing`·keyCode 229), ⌘⌃⌥와 함께, 편집 칸 안에서는 무시한다(렌더러 키맵의 기존 규칙). 숫자 키패드의 1–8도 같은 키로 받는다(`Numpad1`–`8` → `Digit1`–`8`, 컨트롤러 판정). 표·트리·항목 패널 어디에 포커스가 있어도 표의 선택에 적용한다(보기를 바꾸면 선택이 비므로 대상이 헷갈리지 않는다).
- ⌘/ 시트에는 레지스트리에서 "1–8 · 색 태그 붙이기/떼기" 한 줄로 묶어 보인다(8줄로 늘어놓지 않는다). 팔레트에는 그 자리에 태그가 있을 때만 "색 태그 N · <태그 이름>"으로 나온다. 키는 자리가 비어도 돌고(처리기가 토스트를 띄운다), 팔레트에서만 그 자리에 태그가 있을 때 목록에 오른다(`paletteListed`, Q-62). ⌘/ 시트의 한 줄은 새 묶음 "정리"에 있다(Q-63).

### 4.3 태그 선택기 (사이드바 아래, 목업 `.tag-selector`)
- 자리: 사이드바 맨 아래. 높이는 내용만큼이되 사이드바 높이의 40%까지, 넘으면 자기 안에서 스크롤한다(위의 트리도 자기 스크롤). 태그가 하나도 없으면 그리지 않는다.
- 머리: "태그" + "…" 아이콘 단추(웹 팝업 메뉴, 디자인 명세 7.3): 표시 — 현재 보기의 태그만 ✓ / 모든 태그 · — · 정렬 — 이름순 ✓ / 많이 쓴 순 · (필터가 있을 때만) — · 태그 선택 해제. 표시·정렬은 라이브러리 설정 키 `tags.selector`(`{ show: 'view' | 'all', sort: 'name' | 'count' }`, 기본 `view`·`name`)에 기억한다.
- 칩(디자인 명세 6 "태그 칩"): 색 태그가 먼저 자리 순으로(8px 점), 나머지는 정렬 설정 순(이름순 = `Intl.Collator('ko', { numeric: true })`, 많이 쓴 순 = 지금 보기 안의 자료 수 내림차순). "모든 태그"에서는 지금 보기(범위 + 다른 필터 전)에 없는 태그가 흐린 칩(`.is-dim`)이다. 흐린 칩도 같은 정렬에 섞인다(끝으로 따로 모으지 않는다 — 컨트롤러 판정).
- **필터**: 칩을 누르면(또는 포커스 상태에서 Space) 필터에 넣고 다시 누르면 뺀다. 여러 개면 모두 가진 자료만(AND). 고른 칩 = 강조 채움(`.is-on`). 흐린 칩도 고를 수 있다(결과가 비면 3.6). 필터는 세션 동안만 남고 보기를 바꾸면 비운다(3.5).
- 개수: 빠른 검색과 같은 자리의 "N개 / M개"(M = 범위의 자료 수, N = 필터·검색 뒤).
- "태그 필터" 칸(목업): 칩 목록을 이름으로 좁힌다(NFC 소문자 부분 일치 + 초성, `matchKorean`). esc는 칸을 비운다. 표의 행은 거르지 않는다.
- 키보드: 칩 묶음은 하나의 포커스 정거장(롤링 `tabindex`), ←→·Home/End로 움직인다. Space = 필터 토글, ↩ = 이름 바꾸기(칩이 이름 칸으로 바뀐다), ⇧F10 = 컨텍스트 메뉴.
- 칩 컨텍스트 메뉴: 9.2.
- 칩은 끌 수 있다(8.3).

## 5. 표

### 5.1 열
- 새 열 `openedAt` "마지막으로 연 날": 디자인 명세 9절 날짜 형식, 시각 정렬(첫 누르기 내림차순), 기본 숨김, 기본 폭 132 / 최소 112. 최근 연 자료 보기에서는 늘 보인다(3.2). 열지 않은 자료는 빈 셀(빈 값 정렬 규칙 그대로).
- **색 점**(목업 `.tag-dots`): 제목 셀의 순서는 제목 · 외부 연결 표시 · 색 점 · 상태 표시(파일 없음)다 — 색 태그마다 8px 점(자리 순, 0.5px 안쪽 테두리). 승인된 목업 `tableRow`의 순서이고 점은 연결 표시 뒤에 선다(Q-61). 선택 행(강조 채움) 위에서는 흰 1px 고리(디자인 명세 4절). 점은 접근성 이름을 갖지 않고, 행의 접근성 설명에 "태그: 중요, 시험 범위"를 더한다.
- **열 순서**: 열 머리를 끌어 바꾼다(포인터 끌기 — 한 요소 안의 끌기라 HTML5 DnD를 쓰지 않는다). 끄는 동안 끼울 자리에 머리 전체 높이의 2px `--accent-ring` 세로선(라이트는 `--accent`와 같은 픽셀, 다크에서 3:1 이상 — 컨트롤러 판정), esc = 취소, 놓을 때 `library.columns.order`에 저장. 제목 열과 강제 열(최근 연 자료 보기의 `openedAt`)은 맨 앞에 고정이다(끌 수 없고, 그 앞에 끼울 수도 없다). 끌기는 4px 문턱 뒤에 시작하고 Esc는 끌기 중에만 삼킨다. 끄는 칸은 `--fill-pressed` 채움에 글자 `--text-primary`의 한 면이고(칸 안과 양옆의 구분선을 그리지 않는다), 누른 채움은 4px 문턱을 넘은 뒤에만 나온다. 포인터를 따라가는 유령 칸은 없다(소유자 결정 대기). 머리를 끄는 동안 열 경계는 `col-resize` 커서를 내지 않는다(Q-91–Q-93, 컨트롤러 판정). 열 메뉴의 "열 구성 되돌리기"가 순서도 되돌린다.

### 5.2 M4 잔여: 정렬과 스크롤 막대
- **보기 › 정렬 기준 ▸**(메뉴 막대, 키보드만의 정렬 — Q-49): 보이는 정렬 가능 열의 라디오 목록 · — · 오름차순 / 내림차순(라디오). 지금 보기의 정렬(최근 연 자료면 `library.sort.recent`)을 바꾼다. 메뉴 막대 라디오의 체크는 렌더러가 보고하는 맥락(9.4)으로 main이 그린다.
- **마우스만 쓰는 Mac의 스크롤 막대**(레거시 스크롤 막대가 머리 행을 가로지른다, M4 Task 3 비평): 머리 행을 세로 스크롤 영역 밖으로 옮긴다. 가로 스크롤은 머리와 몸통이 함께 움직인다. Mac `@evidence`에서 "스크롤 막대 항상 보기" 설정으로 캡처해 확인한다. 머리 띠는 세로 스크롤러 위에 따로 서고, 가로 스크롤은 스크립트가 머리 띠에 되비추며, 막대 폭은 `ResizeObserver`로 잰다(겹침 막대에서도 같은 픽셀 — Q-90). 증거 워크플로가 설정 "스크롤 막대 항상 보기"를 앱의 defaults 도메인에 쓰고(`-g` 아님) 잰 폭이 0이면 판정이 실패한다(Q-96). 스크롤 요소는 `library-scroller`이고 `library-table`은 바깥 grid다. 좁은 창에서는 가로 넘침이 정상이며, 행은 좌우 8 안쪽을 지키고(`scroll-padding-inline`) 머리가 본문을 따라간다(컨트롤러 판정).

## 6. 항목 패널

### 6.1 하나를 골랐을 때 (목업 `inspectorItem`)
- 절 순서: 정보(M4) · **태그** · **컬렉션** · 파일(M4). 읽기 절은 M7.
- **태그 절**: 머리 "태그" + 더하기 아이콘 단추("태그 추가"). 칩(색 태그 먼저 자리 순, 나머지 이름순). 호버·포커스에서 떼기 단추(×), 포커스 상태에서 ⌫로 떼기(디자인 명세 6 "태그 칩"). 끝에 "태그 추가" 칩(테두리만).
  - "태그 추가"(칩 또는 머리 단추): 그 자리가 입력칸이 된다. 입력하면 아래에 기존 태그 제안(최대 8, 이 자료에 없는 것만, NFC 소문자 부분 일치 + 초성). ↑↓로 제안 고르기, ↩ = 고른 제안 붙이기(없으면 입력한 이름으로 만들어 붙이기 — `tags.create`는 같은 이름이 있으면 그 태그를 돌려준다), esc = 닫기, 칸은 열린 채 다음 태그를 받는다(Zotero). IME 안전. 칸이 비었을 때 ⌫는 아무것도 지우지 않는다.
- **컬렉션 절**: 머리 "컬렉션". 이 자료가 **직접** 든 컬렉션마다 경로 한 줄(`folder` 14 + "분자생물학 › 6장 · 신호 전달", 목업 `.collection-path`, 트리 순서). 줄을 누르면 그 컬렉션 보기로 옮겨 가고 이 자료를 고른 채로 둔다(3.5 예외). 없으면 "컬렉션에 없음"(3차색).
- 정보 편집 중의 막기 규칙(M4 5.3)은 태그·컬렉션 절의 동작에는 걸리지 않는다(바로 저장되는 동작이다). 다만 편집 중에 컬렉션 경로를 누르는 것은 "다른 자료로 넘어가기"와 같아 M4 규칙(저장·막기·버리기)을 먼저 거친다.

### 6.2 여럿을 골랐을 때 (목업 `inspectorMulti`)
- M4의 머리·제목 목록 아래에 단추 "컬렉션에 추가 ▾"(웹 팝업 메뉴, 디자인 명세 7.3: 컬렉션 목록(트리 순서, 들여쓰기) · — · 새 컬렉션 ⇧⌘N). 고른 자료가 모두 이미 든 컬렉션은 체크 표시 + 비활성. 네이티브 하위 메뉴(9.2)는 macOS 하위 메뉴처럼 새 컬렉션을 맨 위에 두고, 이 웹 팝업은 트리 아래 맨 끝에 둔다 — 같은 명령의 두 순서는 의도한 것이다(컨트롤러 판정).
- **공통 태그 절**: 고른 자료 모두에 붙은 태그의 칩. 떼면 모두에서 뗀다. 끝에 "모두에 태그 추가" 칩(6.1과 같은 입력, 모두에 붙인다). 공통 태그가 없으면 "고른 자료에 함께 붙은 태그가 없습니다."
- **컬렉션 절**: 고른 자료가 모두 직접 든 컬렉션의 경로(누르면 6.1처럼 옮겨 가고 선택은 비운다 — 자료가 여럿이라 예외를 쓰지 않는다). 없으면 "고른 자료가 함께 든 컬렉션이 없습니다."
- 공통 계산은 스냅샷으로 렌더러가 한다(1만 개 선택에서도 IPC 없음, 12절 예산).

### 6.3 그 밖의 상태
- 선택 없음 통계는 지금 보기의 것(3.5). 빈 컬렉션은 3.6.

### 6.4 M4 잔여
- **쪽 수 탐침**: 선택이 바뀔 때마다 돌던 것을 150ms 디바운스하고, 탐침은 고른 자료가 하나일 때만 돈다(키보드로 행을 빠르게 지나갈 때 PDF를 열지 않는다).
- **Linux의 역할 `<select>`**: Chromium 기본 화살표 대신 자체 화살표(`chevron-down` 12, `appearance: none`). Mac은 지금 모양을 유지한다.

## 7. 빠른 검색 · 팔레트

### 7.1 빠른 검색
- 찾는 필드에 **태그 이름**을 더한다(짧은 필드 — 초성 포함, 자료의 태그 이름을 공백으로 이은 문자열). 자리표시 "제목, 저자, 태그 검색"(M4 4.1의 예고).
- 범위는 지금 보기(+ 태그 필터)다. 결과 없음 문구: 내 라이브러리면 "제목·저자·태그·출판사·원래 이름·초록·메모에서 찾았습니다.", 다른 보기면 앞에 "‘<보기 이름>’의 "를 붙인다. 동작: "검색어 지우기" + (내 라이브러리가 아닐 때) **"내 라이브러리 전체에서 찾기"**(레지스트리 `library.findEverywhere`: 보기를 내 라이브러리로 바꾸고 검색어는 남긴다).
- **M4 잔여 — 다시 그리기**: 검색어 한 글자마다 `MainWindow` 전체가 다시 그려지던 것을, 검색 상태를 구독하는 표·도구 막대(개수)·결과 없음만 다시 그리게 좁힌다. 렌더 계수기(`countRender` — 페이지가 `window.__learnRenders`를 만들 때만 돈다)로 1만 항목에서 한 글자 입력이 `MainWindow`를 다시 그리지 않음을 E2E가 확인한다(Q-100).
- **M4 잔여 — `library:searchTexts` 상한**: 긴 필드(초록·메모)를 필드마다 앞 4,000 UTF-16 단위만 싣는다(서러게이트 쌍을 가르지 않는다 — Q-108)(넘는 부분은 찾지 않는다). 1만 항목 픽스처에서 페이로드 크기를 `library-perf.json`에 기록한다.

### 7.2 팔레트 (ADR-0005 §5, 목업 `palette.html`)
- 질의가 있으면 묶음 순서 자료 → **컬렉션** → 명령. 컬렉션 묶음은 최대 5개: 질의의 모든 낱말이 이름에 맞는 컬렉션만, 첫 낱말의 위치(앞일수록 위) → 경로가 짧은 것 → 이름순(Q-104). 행: `folder` 아이콘, 이름(일치 강조), 오른쪽 보조 정보 = "<상위 이름> 안 · N개"(N = 그 컬렉션의 개수, 최상위는 "N개" — 승인된 목업 `palette.html`, Q-106). 보조 정보가 길면 상위 이름만 말줄임하고 개수는 자르지 않는다. 팔레트 행의 오른쪽 보조 정보는 자료의 저자·연도까지 모두 `--text-secondary`다(12px 정보 글자는 4.5:1 — 목업의 3차색 대신, 목업도 고쳤다 — 컨트롤러 판정). ↩ = `setScope`(리더면 라이브러리로 돌아간 뒤 — 창이 막혀 있으면 행을 보이지 않는다, Q-105).
- 결과 없음 제목 "‘<질의>’와 일치하는 자료·컬렉션·명령이 없습니다".
- **M4 잔여 — 자료 순위**: 키 입력마다 일치 전부를 정렬하던 것을, 점수(제목 일치 위치, 일치 종류 — 글자 일치가 초성 일치보다 위)를 한 번 계산해 상위 5개만 고르는 부분 선택으로 바꾼다. 고치기 전후를 1만 항목에서 잰다(12절). 순위는 글자 일치 > 초성 일치 > 다른 필드 일치, 그다음 위치다(Q-103). "라이브러리에서 ‘…’ 검색" 행은 범위가 `all`이 아니면 `all`로 바꾸고 검색어를 넣는다(Q-107). IME 조합 검사는 `isComposingKey` 하나이고, 소스 검사가 새 사본을 막는다(Q-109). IME 조합 검사(`isComposing || keyCode === 229`)가 팔레트·표 키(`gridKeys`)·키맵에 따로 있는 것을 공용 함수 하나로 모은다.

## 8. 드래그 앤 드롭 (디자인 명세 7.2)

### 8.1 구현과 스파이크
- ADR-0004가 고른 react-aria(`useDrag`·`useDrop`, 트리는 RAC `Tree`의 `dragAndDropHooks`)를 쓴다. **첫 작업은 스파이크**(60–90분): 1만 행 가상 표(자체 grid) 행의 `useDrag`, "자료 3개" 끌기 미리보기, RAC `Tree`에 내부 끌기와 Finder 파일 드롭, 창 드롭 오버레이와의 공존, 드래그 중 키맵 충돌, Linux·Mac 측정. 통과 기준은 12절 예산과 8.2–8.5의 동작 전부.
- 하나라도 안 되면 그 부분을 HTML5 DnD(`draggable`, `dataTransfer`의 우리 MIME `application/x-learn-items+json`)로 직접 만든다. 결과는 ADR-0004에 "M5 끌어 놓기" 절로 남긴다. 스파이크 결과: 행·칩은 RAC `useDrag`·`useDrop`, 트리는 RAC `Virtualizer` 안의 RAC `Tree`다(전부 펼친 200행이 Mac 257ms, `Virtualizer`로 44ms — Q-30). 근거는 ADR-0004 "M5 끌어 놓기".
- 문서 수준의 `guardDocumentDrops`는 우리 MIME을 받는 처리기가 있으면 그대로 두고, 아무도 받지 않는 드롭만 막는다(지금 규칙의 확장).

### 8.2 표 행 → 컬렉션 행
- 끌기를 시작한 행이 선택 밖이면 그 행만 먼저 고른다(오른쪽 클릭과 같은 규칙). 대상은 표 순서의 선택 전부. 컬렉션 행을 눌러 끌면 그 컬렉션이 선택된다(보기가 바뀐다 — Zotero와 같다, Q-31).
- 끌기 미리보기: 첫 행의 종류 아이콘 + 제목(최대 240, 말줄임) + 둘 이상이면 "자료 N개" 배지(`--accent` 채움 pill, caption, `--text-on-accent`). 목업이 없으므로 디자인 비평이 이 모양을 판정한다.
- 놓기 = 넣기(자료는 여러 컬렉션에 든다). **⌘를 누르고 놓기 = 이동**: 지금 보는 컬렉션 범위(그 컬렉션과 하위)에서 빼고 대상에 넣는다. ⌘ 이동은 컬렉션 범위에서만 뜻이 있다 — 다른 범위에서는 ⌘를 눌러도 넣기다. 끄는 동안 ⌘를 누르면 커서 배지가 이동(`move`)으로 바뀐다. 이동 변조키는 플랫폼의 것이다(macOS ⌘, 그 밖 Shift — RAC의 판정, Q-34).
- 드롭 대상 표시(디자인 명세 6 "트리"): 2px `--accent-ring` 안쪽 테두리 + `--accent-soft`(라이트는 `--accent`와 같은 픽셀, 다크는 모든 면에서 3:1 이상 — 컨트롤러 판정). 보던 컬렉션 행이 대상일 때도 이 표시가 선택 채움보다 앞선다. 표시하지 않는 곳: 지금 보는 컬렉션 자신(Finder에서 지금 폴더에 놓는 것과 같다), 특수 보기 행, 고른 자료가 모두 이미 직접 든 컬렉션(넣기일 때). 지금 컬렉션의 **하위는 대상이다** — 과목 보기에서 자료를 장으로 나눠 넣는 흔한 동작이고, ⌘ 이동이면 과목 범위에서 빼고 그 장에만 남는다.
- 접힌 컬렉션 위에 포인터가 가만히 800ms 머무르면 펼친다(RAC 고정, Finder의 스프링 로딩). 트리 위·아래 가장자리에서는 RAC의 자동 스크롤이 돈다(띠 20px, 우리 처리기 없음 — Q-32).
- 넣기는 조용하다(대상 행의 개수가 바뀐다). **빼기와 ⌘ 이동은 토스트 + "실행 취소"**: "자료 N개를 ‘<대상>’(으)로 옮겼습니다." 실행 취소는 바뀐 id만 되돌린다(`addItemsChanged`·`removeItemsChanged`가 돌려준 id).

### 8.3 컬렉션 → 컬렉션, 태그 → 표 행
- **컬렉션 행 → 컬렉션 행**: 그 컬렉션의 하위로 옮긴다. 순환이 되는 대상(자기 자신과 그 하위)과 지금 부모에는 드롭 표시가 없다. **"컬렉션" 묶음 머리에 놓기** = 최상위로. 옮긴 뒤 펼침 상태는 유지한다.
- **태그 칩(태그 선택기·항목 패널) → 표 행**: 태그를 붙인다. 놓은 행이 선택 안에 있으면 선택한 자료 모두에, 아니면 그 행에만. 행의 드롭 대상 표시는 트리 행과 같은 2px 안쪽 테두리 + `--accent-soft`. 모두 이미 가졌으면 표시가 없다.

### 8.4 Finder → 창과 사이드바
- **창 드롭 오버레이**(M3): 사이드바가 보이면 사이드바 오른쪽만 덮는다(디자인 명세 6 "드롭 오버레이"의 "제목 막대 아래 전체"를 바꾼다, 16절). 사이드바가 가려졌으면 지금처럼 전체. 오버레이 제목은 3.7.
- **사이드바 행에 놓기**: 컬렉션 행 = 그 컬렉션으로 가져오기, "내 라이브러리" 행 = 컬렉션 없이 가져오기(컬렉션 범위에서 그 컬렉션에 넣지 않고 싶을 때). 특수 보기 행에는 놓을 수 없다. ⌥ = 외부 연결은 오버레이와 같다. 행에 놓으면 오버레이 없이 행의 드롭 대상 표시만 있다.
- 시트가 창을 잡고 있는 동안 드롭은 무시된다(AC02 규칙 그대로).
- **렌더러는 놓인 파일의 경로를 본다**(M3부터): 프리로드의 `pathForFile`(Electron `webUtils.getPathForFile`)로 얻어 `library:import`에 보낸다(`dnd/fileDrop.ts`, 사이드바 행은 `dnd/treeDnd.ts`가 두 번째 호출자). main은 그 경로를 다시 검사하고 가져온다. "렌더러는 놓인 경로를 보지 않는다"는 검토 체크리스트의 전제는 틀렸고, M5는 이 경계를 바꾸지 않았다(브랜치 전체 검토 m-29).

### 8.5 공통
- 끌기 중 esc = 취소(네이티브). 드롭이 실패하면(IPC 오류) 원래 상태 그대로 + 오류 토스트(디자인 명세 7.2).
- 키보드 대안: 자료 → 컬렉션은 "컬렉션에 추가 ▸"(메뉴 막대·컨텍스트 메뉴·다중 선택 단추), 태그는 1–8 키와 "태그 추가", 컬렉션 옮기기는 RAC 트리의 키보드 끌기다 — 행마다 `slot="drag"` 단추(Tab 정거장 밖, 리프 행에서 →로 닿는다)에서 ↩ → ↑↓ → ↩(Q-35). 끌기 단추는 ⌥→로도 닿는다(펼칠 수 있는 행도 키보드로 끌 수 있다). 키보드 끌기는 "컬렉션" 머리(최상위로)에 ↑↓가 아니라 Tab으로 닿는다 — React Aria는 한 컬렉션 밖의 드롭 대상 사이를 Tab으로 옮긴다(컨트롤러 판정). RAC `Tree`가 남았으므로 "옮기기 ▸" 메뉴는 없다.
- 트리 행에 놓은 뒤(마우스·Finder 파일·키보드 모두) 보던 컬렉션이 그대로 보기다. 마우스로 놓은 뒤에는 키보드 링이 생기지 않고 트리가 스크롤되지 않는다. 키보드로 놓은 뒤에는 커서가 보던 행으로 돌아오고 그 행이 보이게 스크롤될 수 있다. 놓은 결과로 미분류 행이 나타나도 선택은 그리로 가지 않는다(컨트롤러 판정).
- 취소한 Finder 끌기는 드롭 표시를 남기지 않는다. 취소는 페이지에 아무 이벤트도 주지 않으므로 다음 포인터 이동·누름·키에서 지운다(컨트롤러 판정).
- E2E는 Chromium 합성 끌기(CDP `Input.dispatchDragEvent`, M3 `drop.spec`의 방식)로 확인한다. 실제 손 끌기는 실기 목록(13절).

## 9. 컨텍스트 메뉴 · 명령 · 메뉴 막대

### 9.1 기반 (ADR-0005 §4 갱신)
- `contextMenuEntries`·`popupCommandMenu`가 **하위 메뉴**(▸), **체크 표시**, 줄마다 붙는 **값**(컬렉션 id, 자리 N, 색, 정렬 열)을 지원한다. 하위 메뉴의 줄은 레지스트리 명령 하나에 값을 붙인 것이라, 처리기 없는 줄은 여전히 생길 수 없다(가짜 금지).
- 동적 하위 메뉴(컬렉션 목록, 색 태그 목록, 색 8개, 정렬 열)는 main이 DB(또는 보고된 맥락)에서 만든다. 레지스트리의 명령은 `submenu: 'collections' | 'tagColors' | 'sortColumns'`(줄마다 값을 붙이는 값 하위 메뉴)를 갖고, 색 태그처럼 명령 여럿을 한 하위 메뉴에 모으는 묶음은 별도 `SUBMENUS`다 — 키맵·⌘/·팔레트가 1–8을 명령마다 알아야 해서 명령을 하나로 합치지 않는다. 값 줄의 항목 id는 `cmd?k=v`, 묶음 머리는 `submenu.<id>`다(P-3, Q-24). 이름 속 `&`는 두 번 쓴다(Q-28).
- `ui:showContextMenu`의 결과는 `{ commandId, args? } | null`이다. 렌더러 처리기의 인자는 `itemIds`만에서 대상 `{ itemIds?, collectionIds?, tagIds?, args? }`로 넓힌다(`COMMAND_HANDLERS` 서명 변경). `kind: 'collection' | 'tag'`의 null 반환(`ui.ts`)을 없앤다.
- **M4 잔여**: 자료 메뉴를 만들 때 main이 고른 id마다 `getItem`을 부르던 것을 질의 한 번(`getItems(ids)`)으로 바꾼다. 체크 표시(컬렉션·색 태그)도 같은 질의의 소속·붙임으로 계산한다. 1만 개 측정 뒤 메뉴는 자료 전체 대신 판정에 쓰는 두 열만 읽는 `targetFacts`로 바꿨다(컨트롤러 판정, 12절).
- **키보드로 컨텍스트 메뉴**: 포커스된 표 행·트리 행·태그 칩에서 ⇧F10(그리고 Linux·Windows의 메뉴 키)이 그 요소 아래에 메뉴를 연다. VoiceOver의 VO-⇧-M도 같은 `contextmenu`로 온다. 같은 키가 `keydown`과 `contextmenu`로 두 번 오므로 500ms 안의 둘째는 무시한다(Q-29). `kind`를 어느 명령도 올리지 않은 메뉴는 DB를 읽기 전에 null을 돌려준다(Q-27). 메뉴 막대는 정렬·열·컬렉션·태그가 바뀌면 100ms 디바운스로 다시 만들고 네이티브 메뉴가 열려 있는 동안과 닫힌 뒤 100ms는 미룬다(Q-23).

### 9.2 메뉴 내용 (디자인 명세 7.3, 16절의 변경 포함)
- **자료**: 다시 연결…(파일 없음만, M3) · 열기 · — · Finder에서 보기 ⇧⌘R · 사본 내보내기… · — · 컬렉션에 추가 ▸ · 이 컬렉션에서 빼기(컬렉션 범위에서만) · 색 태그 ▸. (새 탭에서 열기는 M7, 휴지통으로 이동은 M6.)
  - **컬렉션에 추가 ▸**: 새 컬렉션 · — · 트리. 하위가 있는 컬렉션은 하위 메뉴가 되고 그 첫 줄이 자기 자신, 구분선, 그다음 하위다(Zotero). 고른 자료가 모두 이미 직접 든 컬렉션은 체크 + 비활성. 컬렉션이 없으면 "새 컬렉션" 한 줄.
  - **색 태그 ▸**: 색 태그만 자리 순으로 "<이름>"(앞에 색 점 아이콘 16px, 오른쪽 단축키 자리에 "1"…"8"). 고른 자료가 모두 가진 태그에 체크. 색 태그가 없으면 이 줄을 그리지 않는다. macOS 메뉴 막대의 "색 태그 ▸"에는 숫자를 쓰지 않는다 — AppKit이 ⌘ 없는 키를 웹 보기보다 먼저 메인 메뉴에 주므로 숫자를 보이면 그 키가 메뉴에 먹힌다. 컨텍스트 메뉴와 ⌘/ 시트는 1–8을 그대로 보인다(컨트롤러 판정).
  - **이 컬렉션에서 빼기**: 지금 컬렉션 범위(그 컬렉션과 하위)에서 뺀다(0절) + 토스트 실행 취소(8.2).
- **컬렉션**: 새 하위 컬렉션 · 이름 바꾸기 · — · 이 컬렉션으로 가져오기… · — · 컬렉션 삭제….
- **태그**(태그 선택기의 칩): 이름 바꾸기 · 색 지정 ▸ · 색 해제 · — · 태그 삭제….
  - **색 지정 ▸**: 8줄 "<N> <색 이름>"(앞에 색 점 아이콘 — 네이티브 메뉴 아이콘 16px 이미지), 이 태그의 색에 체크, 다른 태그가 쓰는 자리는 "— <그 태그 이름>"을 덧붙인다(고르면 그 태그의 색이 풀린다, 4.1). 색 해제는 이 태그에 색이 있을 때만 켜진다.
- 항목 패널의 태그 칩에는 컨텍스트 메뉴가 없다(떼기는 ×·⌫). 특수 보기 행에도 없다.

- 팔레트의 컬렉션 명령(새 하위·이름 바꾸기·가져오기·삭제)은 **지금 보는 컬렉션**이 대상이다(컬렉션 범위가 아니면 꺼진다). 그래서 컨텍스트 메뉴 없이 키보드만으로 모든 컬렉션 동작에 닿는다.
- 메뉴 막대의 "컬렉션에 추가 ▸"에는 체크가 없다(main이 선택의 소속을 모른다 — 맥락은 수만 보고한다). 컬렉션 체크는 컨텍스트 메뉴와 다중 선택 단추에만 있다. 메뉴 막대의 "색 태그 ▸"는 고른 자료가 모두 가진 색 태그에 체크한다 — 렌더러가 그 자리들을 비트 마스크(`selectionTagPositions`, 0–255)로 맥락에 보고한다(컨트롤러 판정).
- 메뉴 막대의 "색 태그 ▸" 줄은 "1"…"8"을 **표시만 하고 등록하지 않는다**(`registerAccelerator: false`). 등록하면 글자 칸의 숫자 입력까지 메뉴가 가로챈다 — 키는 렌더러 키맵이 처리한다(ADR-0005 §3). macOS 메뉴 막대에서는 `registerAccelerator: false`가 듣지 않아(⌘ 없는 키도 메인 메뉴가 먼저 받는다) 숫자를 아예 보이지 않는다(9.2, 컨트롤러 판정).
- 메뉴 막대는 컬렉션·태그가 바뀌면 다시 만든다(100ms 디바운스, 네이티브 메뉴가 열려 있는 동안은 닫힐 때까지 미룬다 — `nativeMenu { open }` 이벤트).
- ⌘/ 시트: 새 묶음 "정리"(컬렉션·태그: 새 컬렉션 ⇧⌘N, 색 태그 1–8)를 `sheets/shortcuts.ts` `ORDER`에 더한다. 시트 높이 기억(M4)의 요약값에 새 명령이 들어간다.
- 레지스트리 불변식과 `commands.coverage.spec`이 새 명령을 모두 실행한다(하위 메뉴의 값이 있는 명령은 대표 값 하나씩).
- 메뉴 막대 파일 메뉴 2묶음의 순서는 컬렉션에 추가 ▸ · 이 컬렉션에서 빼기 · 색 태그 ▸이고, 자료 컨텍스트 메뉴 3묶음도 같은 순서다(Q-70). 팔레트에서 컬렉션 명령의 이름은 `paletteLabel`을 따른다("컬렉션 이름 바꾸기", Q-56).
- `library.sortBy`는 라이브러리에 자료가 있어야 켜지고 팔레트에는 없다. 열을 고르면 방향이 그대로이고 방향을 고르면 열이 그대로다(Q-22).
- 1–8 키의 가용성은 "라이브러리 보기, 선택 ≥ 1"이다(P-13). 자리에 태그가 없으면 명령은 돌고 토스트가 말한다.

### 9.4 맥락
- `CommandContextState`에 평평한 필드를 더한다(M4 P-2 규칙: 객체 없음, 필드별 `Object.is`): `scope`(`'all' | 'recent' | 'unfiled' | 'duplicates' | 'collection'`), `collectionCount`, `tagPositions`(쓰는 자리의 비트 마스크 0–255), `tagFilterCount`, `searchActive`, `sortColumn`, `sortDirection`. `commandContextInput`(`.strict()`)도 같이 바꾼다. `columnsShown`(그려진 열의 비트 마스크 — 숨겼지만 정렬 중인 열도 체크로 보인다)도 평평한 필드다(Q-21). 메뉴 막대 "색 태그 ▸"의 체크를 위한 `selectionTagPositions`(고른 자료가 모두 가진 자리의 비트 마스크)도 같은 평평한 필드다(9.3, 컨트롤러 판정).
- 대상이 컬렉션·태그인 명령의 가용성은 대상 정보(`CommandTargetInfo`에 컬렉션·태그 변형)로 판정한다.

## 10. 데이터 · IPC · 설정

### 10.1 정리 스냅샷 `library:organize`
- 새 채널(메인 창 전용, `createHandle`): 결과 `OrganizeSnapshot = { collections: { id, name, parentId, createdAt }[]; tags: { id, name, color, position }[]; members: Record<collectionId, itemId[]>; tagged: Record<tagId, itemId[]>; duplicates: itemId[][] }`. 소속·붙임은 휴지통에 없는 자료만, 컬렉션은 살아 있는 것만. 개수는 싣지 않는다(렌더러가 계산). `members`·`tagged`는 비어 있지 않은 키만 싣고 소비자는 `?? []`로 읽는다(Q-2).
- 렌더러 쿼리 키 `['library', 'organize']`. 컬렉션 트리·하위 집합·사이드바 개수·미분류·중복·자료별 태그·자료별 컬렉션의 역색인은 스냅샷 하나에서 메모이즈해 만든다(`organize/` 모듈, 순수 함수 — 단위 테스트).
- 자료 목록(`library:list`)의 `LibraryItem.tagIds`를 뺀다(목록 IPC가 가벼워진다 — 12절). 자료의 태그는 스냅샷의 역색인에서 읽는다. `library.detail`의 `tags`·`collections`는 그대로 둔다(항목 패널은 스냅샷을 쓴다 — 상세 응답의 두 필드는 지우지 않고 남긴다).

### 10.2 쓰기 채널
- 있는 16채널(`collections:*`, `tags:*`)을 그대로 쓴다. 더하는 것: `library:organize`, `library:getItems({ ids })`(10.3), 가져오기 입력의 `collectionId`(3.7). `tags:setColor`는 채널은 그대로이고 가로챈 태그의 색도 푸는 동작만 바뀐다(4.1). `collections:addItems`·`removeItems`는 바뀐 자료 id 배열을 돌려준다(`Result<string[]>`, 개수가 아니다) — 실행 취소가 그 id만 되돌리고, 비어 있으면 되돌릴 것이 없다(Q-71).
- 이동(⌘ 끌기)은 빼기 + 넣기 두 호출이다. 둘 사이에 실패하면 실행 취소와 같은 경로로 뺀 것을 되돌리고 오류 토스트(디자인 명세 7.2 "원래 상태 그대로").

### 10.3 알림과 다시 받기
| 알림(`libraryChanged.reason`) | 렌더러가 다시 받는 것 |
|---|---|
| `collections`, `tags` | 스냅샷만 |
| `metadata`, `relink`, `availability`, `opened`(새) — `itemIds`가 있고 500개 이하 | 그 자료만(`library:getItems`로 받아 목록 캐시를 고친다), 검색 텍스트는 그 자료만 다시 만든다 |
| 같은 이유인데 `itemIds`가 없거나 500개 초과 | 목록 전체 |
| `import`, `trash`, `restore` | 목록 전체 + 스냅샷 |

- `reader.open`이 `opened`를 알린다(3.2). M7의 위치 저장 알림은 그대로 M7.
- `library:getItems({ ids })`는 SQLite 변수 한도를 피해 500개씩 나눠 한 트랜잭션으로 묻고, 모르거나 휴지통에 있는 id는 조용히 건너뛰며 처음 나온 순서로 중복 없이 돌려준다(P-8, Q-5).

### 10.4 설정 키 (ADR-0007 갱신, 모두 판별 규칙 (b) 라이브러리 KV)
- `library.view`(3.1, `LibraryScope`), `library.sort.recent`(3.2), `sidebar.expanded`(컬렉션 id 최대 2,000개), `tags.selector`(4.3). `library.columns`의 열 id에 `openedAt`(5.1). `library.sort`의 열에 `openedAt`.
- 모르는 컬렉션 id(`library.view`·`sidebar.expanded`)는 읽을 때 버린다.

### 10.5 앵커 규칙
- 컬렉션과 태그는 자료 안의 위치가 아니라서 앵커(ADR-0009)가 아니라 **고정 UUID**로 가리킨다. 튜터·링크가 컬렉션을 가리킬 때도 그 id를 쓴다. "새 데이터 객체는 모두 앵커로 주소를 가질 수 있다"(제품 원칙 1.1)는 M5에서 새 테이블이 없어 해당하지 않는다(컬렉션·태그 테이블은 M2부터 있다).

## 12. 성능 예산과 측정

픽스처: M4의 1만 항목 생성기에 컬렉션 200개(깊이 ≤ 4), 태그 50개(색 태그 8개), 소속 3만, 태그 붙임 2만, 중복 묶음 50개를 더한다. 중복 묶음은 `seedItems`의 한 파일 공유와 양립하지 않아 `seedOrganize`가 자료마다 자산을 따로 주고 묶음 50개만 나눠 쓴다(Q-110).

|---|---|---|
| `library:organize` IPC | ≤ 50ms | 이 문서 |
| 자료 목록 IPC(`library:list`) | M4 값(Linux CI 기록) 이하 — `tagIds`를 뺐으므로 | M4 9절(예산 150, M4 실측 269) (M4 기록 269ms는 보고값, CI 실패선은 M4와 같은 300ms — Q-111) |

| 컨텍스트 메뉴 열기, 1만 개 선택 | ≤ 150ms | 11절 (main의 `Menu.popup` 호출까지 — OS가 메뉴를 그리는 시간은 실기, Q-114) |
| 검색 입력 → 그리기 p95(태그 필드 포함) | ≤ 50ms | M4 9절 그대로 |
| 팔레트 입력 → 그리기 p95 | ≤ 50ms | 이 문서 |

- `@perf` spec이 5회 이상 재서 `organize-perf.json`에 남긴다(검색·목록은 `library-perf.json`에 이어서). Linux CI는 예산의 2배에서 실패하고, Mac 값은 보고한다. 단발 측정은 중앙값, 연속 입력은 p95로 판정하고 최댓값은 JSON에만 남긴다(Q-116). 1만 항목 정리 시험(`organize-perf`)의 Linux CI 시간 한도는 120초다: 한 세션이 시드까지 하는 시험이 바쁜 호스트에서 53–80초 걸려, 처음 정한 90초(Q-112)로는 멈춤이 아닌 느림도 끊었다(Task 11 검토 뒤 컨트롤러 판정). 한도는 멈춤만 막고, 예산과 2배 선은 그대로다.
- 측정 뒤 고친 것(Task 11): 정리 스냅샷의 소속·붙임 질의가 휴지통 집합을 `NOT IN`으로 빼고 중복 묶음을 `item_assets`에서 읽어 DB 읽기가 145ms에서 60ms로 줄었다. 자료 메뉴는 `getItems`의 자료 전체 대신 두 열만 읽는 `targetFacts`를 쓴다. 고치지 않은 구조(실측은 ADR-0004 "결과와 위험"): `1` 키가 정리 모델을 다시 만들고, 태그가 바뀌면 1만 항목 검색 색인을 유휴 콜백에서 다시 만든다.

## 13. 검증

- **단위**: 트리 만들기·이름순·하위 집합·하위 포함 서로 다른 개수, 범위 계산(최근 30일, 미분류, 중복), 태그 AND 필터, 칩 정렬·흐린 칩, 공통 태그·컬렉션, 복원 수정(따로 지운 하위는 남음), 메뉴의 하위 메뉴·체크·값, 명령 가용성(범위·선택·자리 마스크), 설정 파싱(모르는 id), 검색의 태그 필드, 팔레트 컬렉션 순위, 가져오기의 `collectionId` 트랜잭션.

## 14. 계획의 Global Constraints에 들어갈 것

M4 계획의 Global Constraints를 그대로 잇고, 다음을 더한다.
- 새 런타임 의존성 없음(react-aria-components 1.22.1에 DnD가 있다). 꼭 필요하면 허용 목록 검사를 통과하고 정확히 고정한다.
- 컬렉션·태그는 고정 UUID로 가리킨다(10.5). 새 테이블을 만들면 앵커 규칙을 다시 본다.
- 모든 메뉴 줄(하위 메뉴 포함)은 레지스트리 명령 + 값에서만 나온다(9.1). 디자인 명세 7.3(16절 변경 포함)에 없는 메뉴 줄은 그리지 않는다.
- 보기 계산은 스냅샷 위의 순수 함수로 두고 IPC를 부르지 않는다(0절).
- 사용자 문장의 조사(을/를, 이/가, 와/과, (으)로)는 사용자 이름(컬렉션·태그)에 맞춰 고른다(M4의 조사 함수).
- 주석에는 이유만, 실행·비평 id는 커밋 메시지에.
