### 0.1 레이아웃 A vs B (결정 근거 기록 — B 확정)

두 안은 1차 비평 뒤 **같은 조건**으로 맞췄다. 사이드바 폭은 모든 탭에서 하나(기본 240, 사용자가 바꾸면 모든 탭에 같이 적용)이고, 탭 줄의 시작점과 ⌘K 실행기 자리는 어떤 탭에서도 움직이지 않는다. 그래서 차이는 "제목 막대와 사이드바의 관계" 하나다.

| | A — Zotero식 | B — Codex / macOS 11+식 |
|---|---|---|
| 맨 위 52px | 창 전체 폭의 제목 막대: 신호등 → 사이드바 토글 → 탭(x 120부터) → 오른쪽 끝 ⌘K 실행기 | 왼쪽 240은 사이드바(신호등·토글), 그 오른쪽이 탭 줄(사이드바 끝 + 12부터) |
| ⌘K 실행기 | 제목 막대 오른쪽 끝, 232 폭 | 사이드바 y 52–80(사이드바 행 채움과 같은 8–232). 사이드바를 접으면 탭 줄 오른쪽 끝 |
| 사이드바 | 제목 막대 아래 | 창 높이 전체, 위 88px(신호등·토글·실행기)은 모든 탭에서 같음 |
| 탭 줄 폭(1440 창) | 약 1060px | 약 1176px(실행기가 사이드바에 있으므로 A보다 넓다) |
| 탭 하나(M3–M6) | 탭 줄 대신 제목 막대가 통합 도구 막대: 제목 + 가져오기 + 실행기 | 같은 규칙. 내용 열 머리가 제목 + 가져오기 |

- **디자이너 권장 B**: Finder·메일·메모·미리보기 등 macOS 11 이후의 기본 앱이 모두 전체 높이 사이드바다. 비브런시가 창 위끝까지 이어져 "Mac 앱"으로 보이고, 실행기가 탐색 영역에 붙어 있어 탭 줄이 넓다. 1차 비평의 구조 결함(탭마다 사이드바 폭이 달라 탭 줄이 80px 움직임, 리더 탭에서 실행기가 사라짐)은 위의 고정 규칙으로 없앴다.
- **비평가 권장 B(근소)** — 1차에는 A였고, 2차 렌더를 보고 바꿨다. (1) 1차의 근거였던 움직이는 크롬이 없어졌다: 라이브러리·PDF·영상·빈 라이브러리에서 사이드바 위 88px이 같고 탭 줄 원점이 고정된다. (2) "탭마다 바뀌는 탐색기"에는 선례가 있다: Xcode의 내비게이터와 미리보기의 썸네일 사이드바도 전체 높이이고 문맥에 따라 내용이 바뀐다. (3) 탭 줄이 약 116px 넓다. (4) 소유자가 처음 거부한 이유는 "웹페이지 같음"이었는데, 창 위끝까지 이어지는 사이드바 면이 첫인상에서 가장 Mac다운 신호다.
- **B에 남는 비용(= A의 장점, 크지 않음)**: 실행기가 사이드바 높이 36px(28 + 8)을 차지해 썸네일·대본이 그만큼 짧다. 사이드바를 접으면 실행기가 탭 줄 오른쪽 끝으로 옮겨 간다(A는 한 번도 움직이지 않는다). Zotero 사용자에게는 A가 더 익숙하다.
- **B를 고르면 불변 조건**: 사이드바 위 88px 고정, 사이드바 폭 모든 탭 공유, 접힘 시 실행기 위치(탭 줄 오른쪽 끝). M3에서 탭 전환 전후의 창 위 88px 스크린샷이 픽셀 단위로 같은지 E2E로 지킨다.
- 두 안 모두 출시 품질이고 차이는 크지 않았다. **소유자가 B로 결정했다(2026-10-21).** 위의 "B를 고르면 불변 조건"은 이제 M3의 필수 조건이다.
- 공통 사실: 두 안 모두 리더 탐색기는 왼쪽, 오른쪽은 항목 정보와 장차 튜터(P3) 자리다. 구현 비용은 거의 같다(같은 DOM, CSS 격자 영역만 다름).

## 1. 원칙

1. **절제** — 크롬은 중립 회색, 강조색은 하나(틸). 관심을 얻지 못한 요소는 경쟁하지 않는다. 그라데이션·빛 번짐·장식 그림자는 쓰지 않는다(드롭 오버레이의 흐림처럼 층을 구분하는 기능적 효과만 허용).
2. **내용 우선** — 자료(표의 제목, PDF 쪽, 영상)가 화면에서 가장 크고 밝다. 크롬은 내용보다 조용하다. 보조 패널의 제목은 내용 패널 제목보다 크지 않다.
3. **키보드 우선** — 모든 명령은 단일 명령 레지스트리(ADR-0005)에 있고 메뉴·팔레트(⌘K)·단축키·컨텍스트 메뉴로 닿는다. 포커스는 항상 보인다.
4. **Mac 네이티브** — 숨긴 제목 막대 + 신호등, 52px 도구 막대, 사이드바 비브런시, 13px 본문, 네이티브 메뉴·컨텍스트 메뉴, 도구 막대 아래에 붙는 시트, 별도 설정 창, `⌘` 기호 표기, 시스템 다크 모드.
5. **가짜 금지** — 동작하지 않는 컨트롤은 그리지 않는다. 내용이 정해지지 않은 "…" 메뉴는 두지 않는다. 목업의 모든 대화형 요소는 `data-ms`로 마일스톤을 갖고(렌더 스크립트가 빠진 것을 센다), 10절 카탈로그와 `?ms=1` 표시가 같은 목록이다.
6. **상태 기억** — 패널 폭·접힘, 열 구성·정렬, 밀도, 테마, 마지막 탭, 읽기 위치(쪽·시간)를 기억한다. 재시작하면 그대로 돌아온다.

## 2. 창과 패널 격자

### 2.1 공통
- 창: 기본 1440×900, 최소 960×600(`tokens.layout.windowMin*`). `titleBarStyle: 'hidden'`, `trafficLightPosition: {x: 18, y: 18}`(M3에서 macOS 러너로 확인), `vibrancy: 'sidebar'`. Linux/Windows는 `titleBarOverlay`(색은 `tokens.generated.ts`).
- 신호등: 12px 원 3개, 간격 8, 묶음 원점 (18, 20)에 그려 52px 막대 세로 가운데. 왼쪽 **84px**(`--traffic-light-inset`)은 신호등 전용이다. 신호등은 네이티브이므로 웹 내용(스크림, 드롭 오버레이)이 덮거나 흐리게 할 수 없다. 창이 비활성이면 회색.
- 도구 막대 52, 패널 머리 44, 표 머리 28, 컨트롤 28(작게 22·24, 크게 32), 아이콘 히트 영역 28.
- 패널 폭(px, 드래그로 조절·기억): 사이드바 **240** (180–360), 항목 패널 **320** (260–480). **사이드바 폭은 모든 탭에서 하나다**(라이브러리 컬렉션, PDF 썸네일, 영상 대본이 같은 폭을 쓴다). 창이 960에 가까워지면 항목 패널 → 사이드바 순으로 자동 접힌다(접힘 상태도 기억).
- 패널 경계는 1px `--separator`. 경계 위 ±4px가 크기 조절 핸들(커서만 바뀌고 선은 그대로).
- **탭이 하나뿐이면**(라이브러리만 열린 상태, M3–M6 내내) 탭 줄을 그리지 않는다. 제목 막대가 통합 도구 막대가 되어 현재 보기의 제목(15/20 600) + 개수 + 주요 동작(가져오기)을 담고, 내용 열의 패널 머리는 생략한다(`library-empty.html`).

### 2.2 레이아웃 A — Zotero식
```
┌──────────────────────────────────────────────────────────────┐
│● ● ●  [▯] [라이브러리][PDF 탭 ×][영상 탭]      [검색 및 명령 ⌘K]│ 52  --bg-window, 아래 구분선
├──────────┬──────────────────────────────┬────────────────────┤
│ 사이드바  │ 패널 머리 44                    │ 항목 패널           │
│ 240      │ 표 / 리더                       │ 320                │
└──────────┴──────────────────────────────┴────────────────────┘
```
- 제목 막대가 창 전체 폭. 84px 다음에 사이드바 토글(28), 8 띄우고 탭.
- 탭: 높이 28, 반경 6, 기준 폭 240(늘어나지 않고, 줄이 꽉 차면 최소 120까지 줄어든다), 간격 4. 활성 탭은 `--bg-control` + `--shadow-e0`, 비활성은 투명·`--text-secondary`, 비활성 탭 사이에 16px 높이 구분선. 닫기(18) 버튼은 활성·호버 탭에만. 라이브러리 탭은 닫을 수 없다(닫기 없음).
- 오른쪽 끝(12 띄움): 팔레트 실행기(필드 모양, 232×28, `⌘K` 키캡).

### 2.3 레이아웃 B — Codex / macOS 11+식
```
┌──────────┬───────────────────────────────────────────────────┐
│● ● ●  [▯]│ [라이브러리][PDF 탭 ×][영상 탭]                      │ 52
│[검색 ⌘K]  ├──────────────────────────────┬────────────────────┤ 52–80 실행기, 88부터 탭별 내용
│ 사이드바  │ 패널 머리 44                    │ 항목 패널 320       │
│ 전체 높이 │ 표 / 리더                       │                    │
└──────────┴──────────────────────────────┴────────────────────┘
```
- 사이드바가 창 높이 전체. **위 88px은 모든 탭에서 똑같다**: 0–52 신호등(왼쪽)과 사이드바 토글(오른쪽, 12 띄움), 52–80 ⌘K 실행기(왼쪽·오른쪽 끝 8 — 사이드바 행 채움과 같은 선, 돋보기는 행 아이콘 열 x 24), 80–88 여백. 탭별 내용(컬렉션 트리, 썸네일/목차 세그먼트, 대본 세그먼트)은 y 88부터.
- 탭 막대는 내용 열 위 52px(`--bg-window`), 사이드바 끝에서 12 띄우고 시작. 사이드바 폭이 모든 탭에서 같으므로 탭 줄은 탭을 바꿔도 움직이지 않는다.
- **사이드바를 접으면** 제목 막대가 84px 인셋과 사이드바 토글을 넘겨받고, ⌘K 실행기는 탭 줄 오른쪽 끝(12 띄움, 232×28)으로 간다(A와 같은 머리). 목업 `dialogs.html?scene=codec`.
- 사이드바 내용은 탭의 탐색기다: 라이브러리 탭 = 컬렉션·태그, PDF 탭 = 썸네일/목차/필기, 영상 탭 = 대본/시간 메모. A에서는 같은 탐색기가 제목 막대 아래 왼쪽 패널에 들어간다. **오른쪽은 항목 정보(라이브러리)와 장차 튜터(P3) 자리**라 리더의 탐색기는 항상 왼쪽이다.

### 2.4 패널 머리(44)
- 왼쪽 16, 오른쪽 12. 제목 `--type-title3`(15/20 600) + 개수 `--type-footnote` `--text-tertiary` (간격 8). 검색 중이면 개수는 "0개 / 48개".
- 오른쪽: 주요 동작(보조 버튼), 검색 필드(240), 패널 토글(아이콘 버튼, 켜짐은 `--fill-pressed`).
- 빈 라이브러리는 탭이 하나이므로 패널 머리 대신 통합 도구 막대(2.1)이고, 검색 필드와 항목 패널 토글은 없다(동작할 대상이 없다).

## 3. 토큰

원본은 `tokens.ts`, 생성물은 `tokens.css`(CSS 변수)·`tokens.generated.ts`(main용 hex). `pnpm tokens`로 생성, `pnpm tokens:check`와 `tokens.test.ts`가 최신 여부를 확인한다. 화면 코드에서 색·간격·반경·글자 크기를 직접 쓰지 않는다. 목업에서 토큰이 아닌 값은 `/* local */` 주석으로 표시했다(신호등 색, 메뉴 내부 여백 5, 자막 크기 등).

### 3.1 색 (OKLCH, `light-dark()`)
- 중립: hue 250, chroma ≤ 0.01. 라이트에서는 내용(흰색)이 크롬보다 밝고, **다크에서는 내용이 크롬보다 어둡다**(macOS·Xcode·Finder와 같은 방향). 떠 있는 면은 다크에서 더 밝다(테스트로 고정).

| 토큰 | 라이트 | 다크 | 쓰임 |
|---|---|---|---|
| `--bg-window` | 97.6% | 26.5% | 제목 막대·도구 막대·설정 창 본문 |
| `--bg-sidebar` | 95.6% | 24.5% | 사이드바(비브런시의 불투명 대체값) |
| `--bg-content` | 100% | 21.5% | 표·항목 패널·리더 도구 막대 |
| `--bg-content-alt` | 98.4% | 22.8% | 표 줄무늬 |
| `--bg-raised` | 100% | 30% | 메뉴·팝오버·대화상자·토스트 |

- 강조색은 Linear식 base/accent/contrast: `accent`(채움) ↔ `textOnAccent`(흰 글자, 4.5:1 이상) ↔ `accentText`(면 위 글자, 4.5:1 이상). 다크의 채움은 라이트보다 어둡다(흰 글자 대비 때문). 모든 값은 sRGB 색역 안(생성기가 확인).
- **선택 규칙**: 키보드 포커스가 있는 목록의 선택 = `--accent` 채움 + 흰 글자(행 안 보조 글자·아이콘·진행 막대도 흰색). 포커스가 없는 목록의 선택 = `--fill-selected` 중립. 한 화면에 강조 채움 선택은 하나뿐이다.
- 태그·필기 8색(Zotero와 같은 순서·값, 두 테마 동일): 1 노랑 `#ffd400` · 2 빨강 `#ff6666` · 3 초록 `#5fb236` · 4 파랑 `#2ea8e5` · 5 보라 `#a28ae5` · 6 자홍 `#e56eee` · 7 주황 `#f19837` · 8 회색 `#aaaaaa`. 색 점 8px + 0.5px 안쪽 테두리. 선택 행 위에서는 흰 1px 고리.
- 찾기 일치는 **틸**(`--find-match`, 현재 일치는 `--find-match-current` + 1.5px 강조 테두리). 노란 하이라이트 필기와 절대 헷갈리지 않게 하기 위해서다.
- 쪽 테마: 원본(흰색), 세피아, 어둡게. 기본값은 "앱 테마 따르기"(다크 앱 → 어두운 쪽). 하이라이트는 밝은 쪽에서 `multiply` 40%, 어두운 쪽에서는 탁한 올리브가 되지 않게 밝은 노랑 `oklch(88% .16 95)` 26% `normal`. 그림은 반전하지 않는다.
- `prefers-contrast: more`: 구분선·테두리 3:1 이상, 보조·3차 글자 진하게, 선택 채움 진하게(테스트 포함).

### 3.2 간격·반경·그림자·밀도
- 4px 격자: `--space-2/4/6/8/12/16/20/24/32/40/48`(이름이 곧 px). **2와 6은 아이콘-글자 사이의 `gap`에만** 쓴다. 안쪽 여백(padding)은 4의 배수다(예외: 2px 세로 미세 조정, 자료 쪽 안의 조판, 테마 미리보기 같은 축소 그림 — 목업에서 `/* local */`).
- 반경: xs 3(키캡) · sm 4(칩 안 버튼, 작은 컨트롤) · md 6(버튼·필드·행·탭) · lg 8(메뉴·카드·토스트) · xl 12(대화상자·시트) · pill.
- 그림자: e0(활성 탭·세그먼트), e1(메뉴·팝오버·찾기 막대·토스트), e2(대화상자·시트), page(PDF 쪽). 모든 그림자는 0.5px 고리 + (다크) 위쪽 0.5px 안쪽 하이라이트 + 부드러운 그림자의 같은 구조라 `light-dark()` 하나로 테마가 바뀐다.
- 밀도(행 높이): 촘촘하게 24 · **보통 28** · 여유 있게 32. 사이드바 행·표 행·목차 행이 함께 바뀐다(`--row-height`).

- 글꼴: `--font-system` = `-apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Pretendard Variable", system-ui, sans-serif`(Mac은 시스템, Linux는 번들한 Pretendard). `?font=pretendard`/`data-font="pretendard"`면 Pretendard 우선.
- 한국어: UI 전역 `word-break: keep-all; overflow-wrap: anywhere; line-break: strict`. **우리가 쓴 UI 문단**(시트 본문, 빈 상태, 안내)은 `text-wrap: pretty`(한 단어 마지막 줄 방지), 짧은 제목은 `text-wrap: balance`. **사용자·자료 텍스트**(자막·대본, 자료 제목, 노트)에는 `pretty`를 쓰지 않는다 — 두 줄짜리 문장을 균형 배치하며 "수백 배" 같은 단위를 가르고, 사용자 데이터에는 줄바꿈 금지 공백을 넣을 수 없기 때문이다. UI 문구 안의 숫자+단위, 짧은 명사구("새 컬렉션", "어느 쪽", "G 단백질")는 줄바꿈하지 않는 공백(U+00A0)으로 묶는다. **관형사(이·그·저·새·다른·각·모든·어느) + 명사**는 언제나 묶고("이 컬렉션", "다른 낱말", "그 폴더"), 짧은 복합 명사·동사("쪽 번호", "디스크 공간", "끌어 놓다")와 "A와 B" 짝("필기와 태그")도 묶는다. 가운데 정렬된 3줄 이하 설명(빈 상태, 안내, 패널 빈 상태)은 `text-wrap: balance`. 렌더 스크립트의 문구 검사(`copyLint`)가 묶이지 않은 관형사+명사와 목록의 복합어를 찾는다(현재 0건).
- 자료 쪽 안(PDF 렌더)은 UI가 아니라 자료의 조판이다: `word-break: normal`(한국어 책처럼 음절 단위 줄바꿈) + 양쪽 정렬.
- 한글 UI에 700을 쓰지 않는다(600이 최대, 토큰 테스트). 자료 본문(PDF 쪽 안)은 자료의 글꼴이므로 예외.
- 숫자 열·시간·쪽·개수는 `font-variant-numeric: tabular-nums`(`.num`).
- 말줄임: 한 줄 셀은 `text-overflow: ellipsis`, 전체 텍스트는 툴팁(`title`)과 항목 패널에서 보인다. 가운데 생략은 쓰지 않는다(경로는 끝 말줄임 + 전체 경로 툴팁). 예외: 해시는 앞 8자 + `…` + 복사 단추(`9c417a2e…`, 전체 값은 툴팁과 복사).

## 6. 컴포넌트와 상태

공통 상태 표현(목업 `components.html` 1·3부, 토큰은 2부):
- 호버: `--fill-hover`를 면 위에 겹침(보조 버튼은 배경 위 `linear-gradient` 층). 누름: `--fill-pressed`. 기본 버튼 호버/누름: `--accent-hover`/`--accent-pressed`.
- 키보드 포커스: `outline: 2px solid var(--focus); outline-offset: 1px`. 필드는 1px `--focus` 테두리 + 3px 28% 후광. 행·탭·아이콘 버튼은 안쪽 2px 링. **키보드 커서**(화살표가 움직이는 행)는 선택과 별개로 안쪽 2px `--focus` 링이고, 강조 채움 선택 위에서는 흰색 75% 링이다. 마우스 클릭으로는 링을 띄우지 않는다(`:focus-visible`).
- 비활성: 불투명도 45%(아이콘 40%). 비활성 이유는 **툴팁**으로 알리고 레이블에 넣지 않는다.
- 로딩이 300ms 미만이면 아무것도 보이지 않고, 넘으면 해당 영역 가운데 위쪽에 스피너(16, 2px 고리) + "불러오는 중…"/"여는 중…", 1초를 넘는 작업은 진행 토스트.
- 화면 단위 상태는 목업 변형으로 모두 그린다(10절): 항목 패널 무선택·다중 선택, 검색 결과 없음, 불러오는 중, 빈 컬렉션, PDF 여는 중·열기 실패(손상)·암호 PDF·원본 없음·목차 없음, 자막 없음, 대본 검색 결과 없음, 팔레트 결과 없음. 형식: 24px 아이콘(3차색) + 제목 headline + 설명 footnote(최대 280) + 필요하면 동작 하나.
- **잠시 지나가는 상태와 끝난 상태**: 여는 중·불러오는 중처럼 곧 끝나는 상태는 평소 컨트롤을 그대로 두고 비활성으로 보인다. 열기 실패·암호·원본 없음처럼 사용자가 무언가 해야 끝나는 상태는 쓸 수 없는 컨트롤을 그리지 않는다: 리더 도구 막대 대신 44px 제목 줄(제목 + 저자·종류), 사이드바는 한 줄 안내, 동작은 안내 안의 단추뿐(재생 불가 동영상과 같은 구성).
- 오류 문구는 원인 하나에 다음 행동 하나: 손상("파일 내용이 손상되어 … 다른 사본이 있으면 다시 가져오세요")과 암호("암호로 보호된 PDF입니다" + 암호 입력…)를 나눈다(pdf.js가 `PasswordException`으로 구별한다).
- 안내 아이콘 타일은 의미별 세 가지(56px, 반경 12): **중립**(`--bg-raised` + e0, 아이콘 2차색) = 오류·사용 불가(열기 실패, 암호, 재생 불가), **주의**(`--warning-soft`, 주의색 아이콘) = 사용자가 고칠 수 있는 문제(원본 없음), **강조**(`--accent-soft`, 강조 글자색) = 초대(빈 라이브러리). 지금 일어나는 동작(드롭)은 강조 채움(`--accent` + 흰 아이콘).

## 7. 상호작용

### 7.1 선택 모델(표·트리·썸네일 공통)
- 클릭 = 하나 선택, ⇧클릭 = 범위, ⌘클릭 = 토글, ⌘A = 전체, 화살표 = 이동, ⇧화살표 = 확장, Home/End = 처음/끝.
- **오른쪽 클릭은 먼저 선택한다**: 선택되지 않은 행이면 그 행만 선택한 뒤 메뉴, 선택 안의 행이면 선택을 유지(Finder와 같다).
- 더블클릭·↩ = 열기(탭), ⌘↩ = 새 탭에서 열기(같은 자료 탭이 있으면 그 탭으로 이동).
- 컬렉션을 바꾸면 표 선택은 비우고 항목 패널은 "선택한 자료 없음" 빈 상태. 여러 개 선택이면 항목 패널은 "자료 3개" 요약(공통 태그·컬렉션만).
- 입력하며 행으로 건너뛰기(type-ahead)는 하지 않는다(한국어 IME와 충돌). 대신 ⌘F 빠른 검색.

### 7.2 드래그 앤 드롭
- **Finder → 창**: 창 전체 드롭 오버레이(목업 `library-empty.html?state=drop`). 기본은 사본 가져오기, ⌥를 누르고 있으면 외부 연결(오버레이의 두 카드가 즉시 전환). 파일 수·종류를 보여 주고, 지원하지 않는 파일은 놓은 뒤 결과 토스트에서 알린다.
- **Finder → 사이드바 컬렉션 행**: 그 컬렉션으로 가져오기(M5). 행이 드롭 대상 표시.
- **표 행 → 컬렉션**: 추가(자료는 여러 컬렉션에 속할 수 있다). ⌘ = 이동(현재 컬렉션에서 빼고 추가). 끌기 미리보기에 "자료 3개" 배지.
- **컬렉션 → 컬렉션**: 하위로 옮기기. 순환이 되는 대상은 드롭 표시를 하지 않는다.
- **태그 칩 → 표 행**: 태그 붙이기(M5). **탭 → 탭 줄**: 순서 바꾸기(M7).
- 끌기 중 esc = 취소. 드롭이 실패하면 원래 상태 그대로 + 오류 토스트.

## 8. 모션·다크 모드·접근성

### 8.1 모션
- 지속 시간 100(호버·누름) / 160(팝오버·메뉴·토스트 등장) / 240(시트·드롭 오버레이). 곡선 `cubic-bezier(0.2, 0, 0, 1)`. 사라질 때는 0.75배.
- 이동 거리는 작게(팝오버 4px, 토스트 8px). 목록 갱신·정렬·필터에는 모션 없음. 진행 막대 폭 변화만 160.
- `prefers-reduced-motion: reduce`: 이동은 0(`--duration-move`), 불투명도 전환만 남긴다.

### 8.2 다크 모드
- 시스템 설정을 따른다(설정에서 라이트/다크 고정 가능, `nativeTheme.themeSource`). 첫 프레임 배경은 `tokens.generated.ts`의 `windowBackground`.
- 깊이는 그림자보다 **명도와 경계**: 내용 < 사이드바 < 크롬 < 떠 있는 면 순으로 밝아진다. 떠 있는 면에는 0.5px 바깥 고리와 위쪽 0.5px 안쪽 하이라이트.
- 강조 채움은 라이트보다 어둡게(흰 글자 대비), 강조 글자는 밝게. 의미색 글자도 밝은 변형(`-text`).
- 쪽은 기본으로 어둡게(설정 가능), 하이라이트는 불투명도를 낮춘다. 영상 바탕은 두 테마 모두 거의 검정.
- 라이트/다크 대등: 모든 목업을 두 테마로 렌더해 비교한다(대조표 열 1·2 vs 3·4).

### 8.3 접근성 목표(AC18)
- 대비: 본문·보조 글자 4.5:1 이상(모든 면·호버·비포커스 선택 위), 3차 글자·아이콘·포커스 링·강한 테두리 3:1 이상, 강조 채움 위 흰 글자 4.5:1 이상. `tokens.test.ts`가 두 테마와 고대비 모드에서 검사한다.
- 포커스 링이 항상 보인다. 포커스 순서는 화면 왼쪽→오른쪽, 위→아래. F6으로 패널 사이 이동(사이드바 → 표 → 항목 패널).
- 200% 확대에서 가로 스크롤 없이 쓸 수 있다(패널 자동 접힘).
- 키보드만으로: 가져오기 → 자료 열기 → 찾기 → 필기(M9) → 백업까지 완주(E2E로 검증).
- 히트 영역 28 이상(22 작은 버튼은 주변 4 이상 띄움).
- 의미를 색만으로 전하지 않는다(태그 점 옆 이름, 파일 없음은 아이콘+글자).
- VoiceOver: react-aria 시맨틱(grid, tree, tablist, dialog). 실기 확인은 Mac 실기 단계.

## 9. 문체
- 합니다체(결정 대기). 제목은 명사형 또는 완결문("이미 라이브러리에 있는 파일입니다"), 버튼은 짧은 동사형("건너뛰기", "새 자료로 추가", "다시 연결…").
- 오류 = **원인 + 다음 행동**: "필기를 저장하지 못했습니다. 디스크 공간이 부족합니다. 공간을 확보한 뒤 다시 시도하세요."
- 안심 문구는 사실일 때만: "원본 파일은 그대로 보관됩니다", "자동으로 지운 것은 없습니다".
- 숫자와 단위: "48개", "68쪽", "7 / 12", "2.4 GB". 날짜: 오늘·어제는 "오늘 오전 9:24", "어제 오후 8:40", 그 밖은 "2026. 10. 12.". 영어 제목·저자는 원문 그대로.
- **사용자 문장에 내부 용어를 쓰지 않는다**: "SHA-256 일치" → "내용이 완전히 같습니다", "staging" → "가져오다 멈춘 임시 파일", "해시가 맞지 않아" → "내용이 손상되어", "해시 모두 확인" → "손상 없음", "관리형" → "사본", "경로만 기록" → "위치만 기록". 기술 값(SHA-256, 절대 경로)은 항목 패널의 파일 절이나 툴팁 같은 보조 정보에만, 고정폭으로.
- 메뉴 경로는 따옴표 없이 "파일 › 라이브러리 점검"처럼 쓴다. 인용이 필요하면 ‘ ’(곧은 따옴표 금지).
- 키 표기: 메뉴·툴팁은 "찾기 ⌘F", 본문은 키캡.
