# llm-for-zotero 조사 — Learn이 본받을 것과 피할 것 (2026-10-27)

- 대상: https://github.com/yilewang/llm-for-zotero v3.9.14(커밋 28910d7, 2026-10-26). 소유자가 몇 달째 쓰는 Zotero 7 플러그인이다.
- 방법: 저장소를 얕게 받아 읽기만 했다(실행하지 않음). TypeScript 약 43만 줄이라 세 갈래로 나눠 읽었다: 화면·사용 경험, 에이전트 연결, 엔진(문맥·검색·저장·테스트). 가장 중요한 주장(범위 토큰, claude.ai 커넥터 끄기, 충돌 차단기, 사용자 설정 상속, IME 키 분류, 미검증 칩)은 원본 코드에서 다시 확인했다. 줄 번호는 커밋 28910d7 기준이다.
- 이 문서는 T1 계획의 입력이다. 결정이 아니다 — 소유자에게 묻는 것은 마지막 절에 모았다.

## 1. 한눈에

- **구조**: ACP를 쓰지 않는다. Claude는 Claude Agent SDK를 품은 Node "브리지" 프로세스(HTTP + NDJSON), Codex는 `codex app-server`(stdio JSON-RPC)로 직접 붙는다. 두 에이전트 모두 플러그인 **안에서 띄운 MCP 서버**로 Zotero 자료를 읽는다. 자체 에이전트 루프(공급사 어댑터 9개)도 따로 있다.
- **크기의 출처**: 화면 `src/modules/contextPanel` 15.6만 줄, 에이전트 `src/agent` 12.6만 줄. 인용 대조만 약 1.2만 줄, 대화 삭제만 3.4천 줄이다. 대부분 버그를 고치며 자란 방어 코드다.
- **라이선스**: AGPL-3.0-or-later로 Learn과 같다. 법적으로는 출처를 밝히고 가져올 수 있다. 다만 ADR-0011은 "나중에 라이선스를 바꿀 수 있게" 외부 기여에 CLA를 받기로 했다 — 남의 AGPL 코드를 섞으면 그 부분은 바꿀 수 없게 된다. **그래서 코드는 가져오지 않고 생각만 가져온다**(아래 후보는 모두 짧아서 다시 쓰는 비용이 작다).
- **Learn이 이미 앞서는 곳**: 동의 카드와 요청마다의 "보낸 범위" 줄(이 플러그인은 README에 흐름을 적어 둘 뿐이다), 읽기 전용 MCP + 제안 카드(이 플러그인은 쓰기 도구 20여 개를 확인 창·되돌리기로 지킨다), 앵커 허브(ADR-0009), 자료 아래 묶인 세션 목록, 사용자 에이전트 설정 격리.

## 3. T1 — 에이전트 연결 (ADR-0010을 채울 것)

이 플러그인은 ACP를 쓰지 않지만, ACP가 대신 풀어 주지 않는 문제를 모두 겪었다. ADR-0010에 아직 없는 것:

1. **범위는 대화마다 고정된 토큰으로 묶는다.** 에이전트는 세션을 만들 때 받은 MCP 헤더를 세션이 끝날 때까지(이어 갈 때도) 그대로 보낸다. 그래서 턴마다 새 토큰을 주면 다음 턴에 낡는다. 그들의 해법: "누가 부르는가" 베어러 토큰 + 대화 내내 같은 범위 토큰, 실제 범위(지금 자료·선택)는 서버 쪽에서 턴마다 바꾸고, 대화를 지우면 토큰을 거둔다(`src/agent/mcp/server.ts:989–1003` 주석, `registerScopedZoteroMcpScope`). ACP `session/new`의 MCP 목록도 같은 성질이다 — AC11 범위 검사는 서버 한곳에 둔다. MCP 연결 방식(localhost HTTP + 베어러 / stdio)도 이때 정한다.
2. **claude.ai 커넥터를 끈다.** 그들은 `ENABLE_CLAUDEAI_MCP_SERVERS: "false"`를 명시한다(`src/claudeCode/bootstrap.ts:47`). ADR의 `tools: []` + `settingSources: []`만으로 사용자의 claude.ai 커넥터(Gmail·Drive …)가 빠지는지 T1에서 확인한다. 반대로 그들은 사용자 설정을 기본으로 물려받는다(`settingSources ?? ["user","project","local"]`, `claude-agent-sdk-runtime-client.ts:1628`) — Learn은 따르지 않는다(AC11).
3. **실행 파일 찾기.** 설정의 명시 경로 → 로그인 셸의 `command -v`(별칭 출력 거름) → 알려진 폴더(`~/.local/bin`, `~/.claude/local`, nvm 최신순, Volta, asdf, `/opt/homebrew/bin`, `/usr/local/bin`) → 자식 PATH를 다시 만든다(`src/claudeCode/bridgeBinaries.ts`). Dock에서 연 앱은 셸 PATH가 없다. **그들에게 없는 것**: `claude --version`·`codex --version` 최소 버전 검사. Learn은 에이전트·어댑터·ACP `protocolVersion`의 호환 표를 두고, 격리 손잡이를 지원하지 않는 판이면 **튜터를 막고 어떤 손잡이가 없는지 말한다**(조용히 낮춰 돌리면 AC11이 깨진다).
4. **로그인 상태.** 그들도 감지하지 않는다(README: "답이 실패하면 아마 로그인 안 된 것"). Learn은 첫 `session/new`의 인증 오류를 "터미널에서 로그인하세요" 카드(에이전트별 명령, "다시 확인" 단추, 폴링 없음)로 바꾼다.
5. **작업 폴더.** 대화마다 앱이 가진 빈 폴더를 `cwd`로 준다(`..` 탈출 거부, `resolveScopedCwd`). 꺼지지 않고 남은 내장 도구가 있어도 아무것도 못 보게.
6. **프로세스 감독.** 준비 신호를 받은 뒤에야 쓴다(30초 시한), 2분 안에 3번 죽으면 자동 재시작을 멈추고 "다시 시작" 단추(`bridgeProcess.ts:94–95`), stdin이 닫히면 자식이 끝난다(`--exit-on-stdin-close`), 앱 종료를 자식 정리까지 막는다, 오류에 stderr 마지막 몇 줄. 약 35개의 상태 기계 시험(`test/claudeBridgeProcess.test.ts`). Learn은 ACP `initialize` 응답이 준비 신호이자 버전 출처다.
7. **취소는 시한이 있다.** ACP `session/cancel`은 권고일 뿐이다. 그들은 중단 요청에 5초 안에 답이 없으면 프로세스를 끝낸다. 턴 시한은 활동이 있으면 늘어난다. 취소든 오류든 화면의 턴은 **정확히 한 번** 끝난다(정산 시험들).
8. **모르는 요청에는 바로 오류로 답한다.** 에이전트가 보낸 처리하지 않는 요청은 JSON-RPC `-32601`로 즉시 답한다. 권한 요청은 5분 뒤 자동 거부(던지지 않음, `permission-store.ts`). 거부한 시도는 활동 기록에 남긴다.
9. **프록시·VPN.** localhost MCP 연결을 사용자 프록시가 가로채면 HTTP 502가 난다. 자식의 `NO_PROXY`에 루프백을 더하고, 401·502·연결 거부를 따로 분류해 말한다(토큰은 오류 문구에서 가린다, `src/codexAppServer/mcpErrors.ts`).
10. **에이전트 자신의 기록.** 사용자 설정 폴더를 쓰면 튜터 대화가 `~/.claude/projects/…`에 남아 사용자의 `claude --resume` 목록에 보인다. 격리 폴더를 쓰면 로그인을 한 번 더 한다. 어느 쪽이든 **동의 카드가 그 사실을 말해야 한다**(ADR의 "T1에서 정한다" 항목).
11. **도구 목록은 턴마다 같게.** 프롬프트 캐시가 깨지지 않게(공유 사용량 한도에서 비용). 도구 목록과 ADR 표가 어긋나면 실패하는 시험을 처음부터 둔다(`test/mcpSurfaceDrift.test.ts`).
12. **도구 결과의 모양.** 목차부터 읽고(outline → 범위 지정) `returned/total/limited`를 숫자로 돌려준다(모델이 세지 않게). MCP에는 진행 채널이 없으므로 오래 도는 도구를 두지 않는다(긴 일은 짧은 호출로 나눈다). 같은 읽기를 반복하면 `duplicate: true`로 막는다(에이전트가 같은 쪽을 맴도는 것을 막는다).
13. **모델·노력 선택.** 목록은 에이전트가 주는 그대로 쓰고(별칭 포함), 이름으로 능력을 추측하지 않는다. 모르는 값은 "알 수 없음"과 출처를 단다(`src/modelCapabilities/types.ts`의 `provenance`·`stale`).

## 4. T1 — 데이터 모델

1. **읽기 기록**: MCP 서버가 결과를 돌려주는 순간 `message_sources`(또는 그 전 단계 표)에 행을 쓴다 — 자료, 쪽, 파일 해시, 글 해시, 도구 호출 id, 바이트 수. AC10 칩 검증과 "보낸 범위" 줄이 이 행 하나에서 나온다. 기록이 앱 재시작을 넘어 언제까지 남는지 정한다.
2. **대화**: 처음부터 UUID 하나 + `backend`(에이전트) 열 + `agent_session_id`(ACP 세션) + 범위(자료·앵커) 열. 그들은 마이그레이션을 거치며 id 체계가 셋이 됐다(인스턴스 id, 정수 키, 사람용 id) — 피한다.
3. **메시지**: 그들의 메시지 표는 열이 40개, 그중 `*_json`이 15개이고 `ALTER TABLE`로 자랐다(`src/utils/chatStore.ts:1317`). 우리는 `message_sources`·첨부를 행으로. 그들이 나중에 필요해진 열은 처음부터 둔다: 끝난 이유(완료·답 전 취소·도중 취소·에이전트 오류·백엔드 없음·동의 거절), `interrupted`, 모델·백엔드 이름, 보고된 경우에만 토큰(널 허용).
4. **삭제**: 되돌리기 창이 있는 소프트 삭제(`deleted_at`) + 나중의 정리 작업, `message_sources`까지 이어서. 그들의 쓰기 울타리·묘비 기계(3.4천 줄)는 Zotero 동기화와의 경쟁 때문이라 우리는 작게.
5. **마이그레이션**: id가 붙은 마이그레이션 원장 표와 "옛 스키마를 심은 DB → 업그레이드" 시험(`test-isolated/db-upgrade`). Learn의 `.pre-vN.bak`·`migrate.test.ts`와 같은 방향 — 튜터 표에도 같은 시험.

  - 조각마다 출처: 쪽 범위, 절 경로, 종류(본문·그림 설명·표·수식·참고문헌), 원본 파일 해시, 파서 이름·판. 파서 출력은 출처 기록과 함께 파일로(`mineruCache.ts`의 `_llm_source.json`).
  - 검색: SQLite FTS5 + **한글 두 글자 단위** 토큰화를 먼저(그들의 토크나이저는 CJK·한글 바이그램, `retrievalTokenizer.ts:25–27, 268–283`), 임베딩은 선택 사항이고 RRF(k=60)로 합친다. 12단어 미만 조각·참고문헌은 낮춘다. 여러 자료일 때 자료마다 최소 몫.
  - 그림 블록: 쪽·잘라낸 그림·설명·확신도·모호 표시 → 튜터가 실제 그림을 답에 붙일 수 있다(M9).
  - 깨진 선택 글 감지(`isLikelyCorruptedSelectedText`) — 스캔 PDF에서 튜터에 넘기기 전에 알린다.
- **M9 필기 + 제안 카드**
  - 노트를 고칠 때 앵커·인용·하이라이트를 자리표시(`{{citation:…}}`)로 바꿔 넘기고, 그것을 지우는 편집은 사용자가 요청하지 않았으면 거부한다. 앵커 허브와 바로 맞는다(`{{anchor:…}}`).
  - `> ___` 빈칸 → 확인 문제 카드.
  - **정산 규칙**: 제안 카드(노트 쓰기 등)는 Learn이 쓰기 영수증을 가졌을 때만 끝난 것이다. 에이전트가 "썼다"고 말해도 영수증이 없으면 실패로 바꾼다(`execution/externalTurnSettlement.ts`).
  - 답 → 노트 저장, 같은 자료의 노트에 이어 쓰기.
- **M10 기억·복습**
  - 지난 대화를 읽기 전용 MCP 도구(찾기·읽기)로 열면 T1부터 세션을 넘는 기억이 따로 만들지 않아도 생긴다(`tools/read/pastChatSearch.ts`).
  - 자료 요약을 둔다면 키는 (파일 해시, 파서 판, 프롬프트 판, 모델 id), 요약 속 인용은 저장 전에 조각과 대조한다.
  - 사용량 화면: 토큰만, "알 수 없음"과 이유.

## 6. 테스트 — 가져올 생각

1. **가짜 에이전트를 ACP 이음매에.** 그들은 모델을 어댑터 이음매에서 대본으로 흉내 낸다(`test/agentRuntime.test.ts:181 MockAdapter`). Learn의 가짜 백엔드(ADR-0010 4절)는 **ACP를 말하는 대본 재생기**로 만든다 — 글 조각, 우리 실제 MCP 서버로의 도구 호출, 사용량, 끝난 이유, 오류, 지연. 오프라인 초안·데모·단위 시험이 같은 것을 쓴다. 진짜 세션·MCP·저장 코드가 시험 안에서 돈다.
2. **여정 기준선.** 여정마다 백엔드 턴 수, 도구 호출 수, 돌려준 바이트, 기록된 출처, 중복 쓰기를 JSON 고정값으로 두고 시험이 비교한다. 동작을 바꾸면 같은 커밋에서 고정값을 고친다(`test/fixtures/agentFlightBaselines.json`). 도구 이름이 아니라 선언한 단계로 센다.
3. **실제 SQLite**로 저장 시험(메모리 DB) + 옛 스키마를 심은 업그레이드 시험.
4. **인용 말뭉치**: 지어낸 저자, 수식, 조각난 PDF 글로 만든 합성 논문 — 미검증이면 쪽 없는 칩, 검증되면 "N쪽"을 단언(`artificialQuoteCorpus.test.ts`).
5. **검색 재생**: 한국어·영어 논문 몇 편의 질문·정답 쪽 쌍으로 순위 규칙을 직관이 아니라 재생 결과로 정한다(`scripts/qasper-evidence-replay.ts`).
6. **실기 시험은 환경 변수로만**(`LEARN_AGENT_LIVE=1`), 그 밖에는 건너뛴다. 척도: "인용한 주장마다 근거가 있는가", "맞는 쪽을 가져왔는가".
7. **손으로 돌리는 동작 목록**: 고정 id, 실행마다 보고 폴더(전후 DB 스냅샷), 상태 PASS·FAIL·BLOCKED·REVIEW_REQUIRED. 쓰기 전에 버리는 프로필인지 확인한다. macOS 분이 비싼 우리 사정에 맞다.
8. **구조 검사 스크립트**: 계층 순서(렌더러가 main을 가져오지 못함), 가져오기 순환, MCP 도구 이름·스키마 고정 목록.

## 7. 피할 것

1. 땜질로 자란 1.2만 줄 인용 대조. 우리는 쪽 단위 검증 + 작은 정규화, 미검증은 쪽 없는 칩.
2. 수천 줄짜리 명령형 DOM 파일(`assistantCitationLinks.ts` 4.9천 줄, `preferences.xhtml` 3.6천 줄). 작은 React 부품.
3. ACP 에이전트가 이미 가진 것을 다시 만들기: 에이전트 루프, 공급사 어댑터, 프롬프트 예산·압축, 대화 복구, 검색 전 LLM 질의 계획. 우리 쪽에 남길 것은 검증·정산·도구 결과 상한·중복 읽기 차단뿐이다.
4. 에이전트 종류마다 따로 노는 상태·권한·배지, 백엔드마다 다른 대화 목록. ACP로 대화 모델 하나.
5. 사용자 에이전트 설정 상속, 권한 우회 모드, 에이전트 토큰 직접 재사용(`src/codexAuth`), 웹 채팅 DOM 중계, README에만 있는 개인정보 안내.
6. 모델이 쓴 HTML 미리보기와 넓은 SVG 정화기 표면.
