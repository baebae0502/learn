## 1. 목표와 완료 조건

M3의 임시 목록을 Zotero 7·Finder 수준의 자료 표로 바꾸고, 표에서 고른 자료의 정보를 오른쪽 인스펙터에서 보고 고칠 수 있게 한다. 1만 항목에서도 끊기지 않는다.

3. 8절의 M3 잔여 항목이 각자의 확인 방법으로 닫힌다.
4. 키보드만으로 가져오기 → 찾기(⌘F) → 고르기 → 정보 고치기 → 열기 → 라이브러리로 돌아가기를 완주한다(E2E).
5. Linux CI, Mac `all`, 데모 영상, 브랜치 전체 검토를 거쳐 PR을 연다. 병합은 소유자가 정한다.

## 3. 표

### 3.1 열

| id | 머리 | 셀 | 정렬 | 기본 보임 | 기본 폭 / 최소 |
|---|---|---|---|---|---|
| `title` | 제목 | 종류 아이콘 16 + 8 + 제목(검색 일치 강조) + 외부 연결 `link` + 상태 덧표시(파일 없음) | 한국어 콜레이터 | 항상(끌 수 없음) | 나머지 폭 / 200 |
| `creators` | 저자 | 이름을 ", "로 이음 | 첫 저자 | ✓ | 180 / 96 |
| `year` | 연도 | 4자리, tabular | 숫자 | ✓ | 64 / 56 |
| `type` | 종류 | PDF / 동영상 | 종류 순 | ✓ | 88 / 72 |
| `createdAt` | 추가일 | 디자인 명세 9절 날짜 형식 | 시각 | ✓ (기본 정렬, 내림차순) | 132 / 112 |
| `updatedAt` | 수정일 | 같음 | 시각 | | 132 / 112 |
| `storageMode` | 보관 | 사본 / 외부 연결 | 값 순 | | 96 / 80 |
| `size` | 크기 | 10진 단위(디자인 명세 9절), 오른쪽 정렬 | 바이트 | | 80 / 64 |
| `originalName` | 원래 이름 | 끝 말줄임 + 툴팁 | 콜레이터 | | 200 / 120 |

- 머리·행·셀 치수는 디자인 명세 6절 "표"와 M3 임시 목록의 `.table-*` 치수를 그대로 쓴다. 정렬 열 머리는 primary 500 + 12px 화살표(오름 `chevron-up`, 내림 `chevron-down`).
- 제목 칸에는 "재생 불가" 표시가 없다 — 재생 불가는 재생을 시도한 뒤에야 알 수 있고 저장하지 않는다. 저장된 코덱 점검은 M8 입력이다(Q-39).
- 빈 값(저자 없음, 연도 없음)은 셀을 비운다("—"는 진행 열 전용 표기다).
- 정렬 비교: `Intl.Collator('ko', { numeric: true, sensitivity: 'base' })`. 빈 값은 방향과 관계없이 맨 뒤. 같은 값은 추가일 내림차순, 그다음 id로 안정 정렬(구현은 SQL의 `created_at DESC, rowid DESC` 목록 순서를 그대로 둔다, Q-46).
- `LIBRARY_SORT_COLUMNS`에 `updatedAt`·`storageMode`·`size`·`originalName`을 더한다(값을 더하는 것뿐이라 저장된 `library.sort`는 그대로 유효하다). `progress`는 M7 열이 생길 때까지 정렬 대상으로만 남는다. `openedAt`은 M5가 "마지막으로 연 날" 열로 올린다(M5 명세 5.1).

### 3.2 열 구성과 기억

- 새 라이브러리 설정 키 `library.columns`: `{ visible: ColumnId[], order: ColumnId[], widths: Partial<Record<ColumnId, number>> }`(zod, 폭은 각 열의 최소–1200 정수). `title`은 항상 `visible`에 있다. 모르는 열 id는 읽을 때 버린다(이후 마일스톤에서 열이 늘거나 줄어도 깨지지 않는다).
- 열 폭은 머리 경계를 끌어 바꾼다(커서만 바뀌고 선은 그대로 — 디자인 명세 2.1의 패널 경계와 같은 문법). 열 폭은 우리 열 상태가 CSS grid 트랙으로 낸다(Q-35). 경계는 이웃 열과 폭을 주고받고 제목이 남는 폭을 가진다(Q-41). 놓을 때 저장한다(끄는 동안에는 저장하지 않는다). 첫 누르기 정렬 방향은 날짜·크기·진행이 내림차순, 나머지가 오름차순이다(Q-42).
- 열 순서는 M4에서 바꾸지 않는다(머리 끌기는 M5의 DnD와 함께). `order`는 저장 형식에만 있다.
- 키보드만으로 정렬·열 폭을 바꾸는 길은 M4에 없다 — M5 입력("보기 › 정렬 기준" 하위 메뉴 또는 머리 행 진입, Q-49). 정렬 단추·열 경계는 Tab·F6 밖이다.
- **열 머리 컨텍스트 메뉴**(네이티브, 디자인 명세 7.3 "열 머리(M4)"): 열 목록(체크, `title`은 체크된 채 비활성) · — · 열 구성 되돌리기. 열 목록의 이름은 domain의 열 카탈로그(`LIBRARY_COLUMNS`, 3.1 표)에서 main이 만든다. 렌더러는 보이는 열 집합만 보내고, main은 고른 열 id 또는 "되돌리기"를 돌려준다. 메뉴 항목이 열 정의에서만 나오므로 처리기 없는 항목은 생길 수 없다.

### 3.3 선택과 키보드 (디자인 명세 7.1, 3.1)

- 자체 선택 모델(`selectionModel.ts`, 키 `gridKeys.ts`; Finder식, Q-35): 클릭 = 하나, ⇧클릭 = 범위, ⌘클릭 = 토글, ⌘A = 전체, 화살표 = 이동, ⇧화살표 = 확장, Home/End. 포커스는 커서 행의 롤링 `tabindex="0"`이다(Q-48). 표에 포커스가 있을 때 esc는 선택을 비운다(커서는 남는다). 검색 필드의 esc는 필드가 먼저 처리한다(Q-43).
- **오른쪽 클릭은 먼저 선택한다**: 선택 밖의 행이면 그 행만 고른 뒤 메뉴, 선택 안의 행이면 선택을 유지하고 메뉴(선택한 자료 모두가 대상).
- 더블클릭·↩ = 열기(하나를 골랐을 때). 여러 개를 골랐을 때 ↩는 아무것도 하지 않는다(탭 여러 개로 열기는 M7). M3의 "제목 한 번 클릭으로 열기"는 없앤다(C-5).
- type-ahead는 하지 않는다(한국어 IME와 충돌, 디자인 명세 7.1). ⌘F가 그 역할이다.
- 선택 색: 포커스가 표에 있으면 `--accent` 채움 + `--text-on-accent`(행 안의 보조 글자·아이콘·상태 덧표시 포함), 없으면 `--fill-selected`. 키보드 커서는 안쪽 2px `--focus` 링, 강조 채움 위에서는 `--text-on-accent` 75% 링. `:root[data-window-inactive]`이면 중립 선택이고 링을 그리지 않는다. 한 화면에 강조 채움 선택은 하나뿐이다.
- 선택 상태는 렌더러 저장소(zustand) 하나가 가진다: 선택 id 집합, 커서 id, 범위 기준. 목록이 바뀌어 사라진 id와 검색으로 가려진 id는 그 자리에서 선택에서 뺀다. 그래서 명령이 보이지 않는 자료에 실행되지 않고, 사라진 자료로 열기가 켜지지 않는다(M3 Task 2 리뷰 M9).
- 보기가 바뀌면(리더로 갔다 오면) 선택은 유지하고, 돌아왔을 때 마지막으로 연 자료의 행을 보이게 스크롤한다. 컬렉션 전환으로 비우는 규칙은 M5에서 컬렉션과 함께 온다.
- `CommandContextState`에 평평한 수 필드 `libraryCount`·`selectionCount`·`selectionAvailable`·`selectionRelinkable`을 더한다(available = 파일이 있는 자료 수, relinkable = 파일이 없는 외부 연결 자료 수). 맥락 비교가 필드별 `Object.is`로 남도록 객체는 넣지 않는다. 메뉴 막대는 이 수로 만든 대상(`selectionTargets`)으로 판정하고, 실행할 때는 표 순서의 선택 id를 넘긴다(P-2). 하나만 다루는 명령은 `count === 1`일 때만 켜지고, 아니면 이유를 툴팁으로 보인다("자료를 하나만 고르세요").

### 3.4 가상화

- TanStack Virtual 3.14.22 + 자체 `role="grid"`(`rowHeight` = 밀도 행 높이, 머리 28). 행은 절대 위치라 화면 순서는 `data-index`로 읽는다. 밀도가 바뀌면 다시 잰다.
- 행 컴포넌트는 항목 객체와 선택 여부만으로 다시 그려진다(메모). 목록 전체를 다시 받아도 바뀐 행만 다시 그린다.
- **스파이크(첫 작업, 60–90분)**: 1만 행 + 열 크기 조절 + 정렬 머리 + 다중 선택 + 오른쪽 클릭 선택 + 키보드 커서 + 스크롤 프레임을 Linux와 Mac에서 잰다. 통과 기준은 9절 예산과 3.3의 동작 전부. 하나라도 RAC로 안 되면 TanStack Virtual(정확 고정, MIT) + 자체 `role="grid"`로 바꾸고, 3.3의 동작을 직접 만든다. 결과는 ADR-0004에 "M4 표" 절로 남겼다: Mac(run 40034565009)에서 RAC가 정렬 499/100ms, 선택 106.8/100ms, 필터 337.6/50ms로 예산을 넘고 키보드 오류도 있어 탈락했고 TanStack으로 갔다(Q-34).

### 3.5 상태

- 불러오는 중: 300ms가 지나야 "불러오는 중…"(디자인 명세 6절), 표 머리는 그대로.
- 목록 실패: M3의 `ListFailed` 그대로.
- 빈 라이브러리: M3의 `EmptyLibrary` 그대로(검색 필드와 항목 패널 토글은 그리지 않는다, 디자인 명세 2.4).
- 검색 결과 없음: 4.3.

## 4. 빠른 검색

### 4.1 자리와 동작
- 탭이 하나인 동안 통합 도구 막대의 오른쪽: 가져오기 단추 → 검색 필드(240) → 항목 패널 토글(디자인 명세 2.4, 목업 `libraryHeader`). 자리표시는 "제목, 저자 검색"(태그는 M5에서 "제목, 저자, 태그 검색"으로 바꾼다 — 가짜 금지).
- ⌘F(편집 메뉴 "빠른 검색", 레지스트리 명령 — 소유자 문구 "찾기"를 바꿨다, Q-25)는 필드로 포커스를 옮기고 내용을 모두 고른다. esc: 값이 있으면 지우고, 없으면 포커스를 표로 돌려보낸다. ↓는 표의 첫 결과로 간다.
- 입력할 때마다(IME 조합 중 포함) 거른다. 조합 중의 키 입력을 단축키로 해석하지 않는 규칙(디자인 명세 7.4)은 그대로다.
- 검색어는 세션 동안만 남는다(다시 시작하면 빈 검색).
- 개수: "3개 / 48개"(디자인 명세 2.4).

### 4.2 일치 규칙
- 항목마다 검색 문자열을 목록이 바뀔 때 한 번 만든다: 각 필드를 NFC → `toLocaleLowerCase('ko')` → 공백 하나로. 짧은 필드(제목·저자·출판사·원래 이름)는 초성으로도 찾는다(팔레트의 `palette/hangul.ts` `matchKorean`을 함께 쓴다). 긴 필드(초록·메모)는 NFC 소문자 부분 일치만 하고, 질의가 처음 생길 때 `library.searchTexts()`로 받아 온다 — 받기 전에는 짧은 필드로만 거른다. 출판사는 목록(`LibraryItem.publisher`)에 실린다(P-7).
- 질의를 공백으로 나눈 낱말이 모두 어느 필드엔가 있어야 한다(AND). 낱말이 초성으로만 되어 있으면 초성 문자열에서 찾는다. 2글자 한국어 낱말도 부분 일치로 찾는다(FTS 트라이그램의 3글자 제한이 없다).
- 순서는 표의 정렬을 그대로 따른다(관련도 순위는 팔레트에서만).
- 제목 셀에서 일치한 부분을 `<mark>`로 강조한다(팔레트와 같은 모양). 다른 필드에서만 맞았으면 강조는 없다.
- 질의는 `useDeferredValue`로 받아 입력이 표 그리기를 기다리지 않는다.

### 4.3 결과 없음
- 표 몸통 자리의 빈 상태(디자인 명세 6절 형식): `search-x` 아이콘, "‘<질의>’와 일치하는 자료가 없습니다", "제목·저자·출판사·원래 이름·초록·메모에서 찾았습니다." 동작은 "검색어 지우기" 하나(M5에서 "내 라이브러리 전체에서 찾기"가 더해진다).

### 4.4 팔레트 자료 결과 (디자인 명세 10.5, 목업 `palette.html`)
- 질의가 있으면 "자료" 묶음을 명령 묶음 위에 둔다. 최대 5개, 같은 일치 규칙에 순위는 제목 일치(앞일수록 위) → 다른 필드 일치 → 마지막으로 연 시각.
- 행: 종류 아이콘, 제목(일치 강조), 오른쪽 보조 정보 = 저자 · 연도(없으면 종류). 제목에서 맞지 않은 행은 저자 · 연도에서 맞은 곳을 강조한다(그 행이 왜 나왔는지 보이게). ↩ = 열기.
- 명령 묶음 끝에 "라이브러리에서 ‘<질의>’ 검색 ⌘F" 행: 팔레트를 닫고 빠른 검색에 질의를 넣는다(라이브러리 보기가 아니면 라이브러리로 돌아간 뒤).
- 결과가 없을 때도 그 행이 남는다(목업 `?state=none`). 결과 없음 제목은 M4에서 "‘<질의>’와 일치하는 자료·명령이 없습니다"(컬렉션은 M5).
- **최근 실행 가중치**: 질의가 비었을 때 최근 실행한 명령 5개를 위에 둔다. 질의가 있을 때는 같은 점수 안에서 최근 실행이 앞선다. 기록은 라이브러리 설정 키 `palette.recent`(명령 id 최대 20개)에 둔다.
- 실행기와 팔레트 입력의 문구를 "검색 및 명령"으로 되돌리고, 키 힌트 줄의 초성 예를 "ㅅㅎ → 신호"처럼 자료 예로 바꾼다(실제 라이브러리에 맞는 예가 없으면 지금의 "ㅅㅈ → 설정"을 쓴다).
- 키 힌트 줄: "↑ ↓ 이동 · ↩ 열기"(⌘↩ 새 탭은 M7).

## 5. 인스펙터

### 5.1 슬롯과 모드
- 오른쪽 슬롯 컴포넌트 `Inspector`는 모드를 받는다: `type InspectorMode = 'info'`(T1에서 `'tutor'`). 모드 전환 UI는 그리지 않는다(디자인 명세 2.5). 메뉴·툴팁의 이름은 "항목 패널 가리기 / 항목 패널 보기" 그대로다.
- 폭은 모드마다 기억한다: `layout.panes`에 `inspector.info`(260–480, 기본 320)와 `inspectorCollapsed`(0/1). 튜터 폭은 T1이 더한다. 렌더러는 두 패널의 값을 한 기록(`PanesState`)으로 읽고 통째로 쓴다 — 어느 쓰기도 다른 패널의 키를 지우지 않는다(P-10).
- 라이브러리 보기에만 있다(리더의 오른쪽 슬롯은 T1에서 튜터 모드로 생긴다).

### 5.2 크기·접힘
- 경계를 끌어 폭을 바꾼다(사이드바와 같은 핸들). ⌥⌘I(`view.toggleInspector`, 보기 메뉴, `stateLabels.inspector` 가리기/보기 — 개발 빌드의 개발자 도구는 ⌥⌘J, P-1)와 도구 막대의 토글 단추(켜짐 = `--fill-pressed`).
- 자동 접힘(`shell/layout.ts`): 내용 열이 `CONTENT_MIN`(520)보다 좁아지면 먼저 인스펙터, 그다음 사이드바가 접힌다. 사용자가 직접 접은 것만 저장하고, 자동 접힘은 창 폭에서 다시 계산한다(사이드바와 같은 `forceShown` 규칙). 200% 확대에서 가로 스크롤이 없다(E2E).
- F6 순서: 사이드바 → 표 → 인스펙터 → 알림(떠 있을 때만, M3)(디자인 명세 7.4). 접힌 패널은 건너뛰고, 표에서는 표의 포커스 대상(커서 행)에 내린다(P-31).

### 5.3 정보 모드 — 하나를 골랐을 때 (목업 `inspectorItem`)
- **머리**: 종류 아이콘 + "PDF · 68쪽" / "동영상 · 18:20", 제목(title3, 사용자 텍스트라 `text-wrap: pretty` 없음), "저자 · 연도"(있는 것만), 단추 "열기"(기본) · "Finder에서 보기"(보조, 아이콘 `folder-search`). 파일이 없는 외부 연결 자료는 "다시 연결…"(기본) · "열기"(보조 — 원본 없음 안내로 간다), 파일이 없는 사본은 "열기"(기본, 안내로 간다)이고, 두 경우 모두 "Finder에서 보기"는 이유("원본 파일이 있어야 쓸 수 있습니다")와 함께 비활성이다(P-8).
- **쪽수·길이**: 고른 자료의 파일을 렌더러가 읽어 얻는다(PDF는 pdf.js `getDocument`의 `numPages`, 동영상은 `preload="metadata"`의 `duration`). revision별로 메모리에 캐시하고, 300ms 안에 못 얻으면 그 자리를 비워 두었다가 채운다(자리가 흔들리지 않게 글자 자리는 미리 잡는다). 읽지 못하면 쪽수 없이 "PDF"만 쓴다. 파일이 없는 자료는 읽지 않는다.
- **정보 절**(접을 수 있는 절 머리, 오른쪽에 연필 아이콘 단추 "정보 편집"):
  - 보기: 값이 있는 줄만 `dl.kv`로 — 저자, 날짜(연도만 있으면 연도), 출판사, 언어, URL(링크, `shell.openExternal`은 main의 URL 정책을 거친다), 초록(4줄 말줄임 + "더 보기"), 메모, 그리고 늘 보이는 추가일·수정일. 정보가 하나도 없으면 "정보 편집"으로 이끄는 한 줄("저자와 연도를 적어 두면 표에서 정렬하고 찾을 수 있습니다.").
  - 편집(연필 또는 팔레트 "정보 편집"): 같은 자리가 폼이 된다. 필드 = 제목(필수), 저자(이름 + 역할 저자/편집자/강연자/기타, 줄 추가·삭제·순서), 날짜(YYYY, YYYY-MM, YYYY-MM-DD), 출판사, 언어, URL(http/https), 초록, 메모. 아래에 "취소"(esc) · "저장"(기본, ⌘↩, 한 줄 필드에서는 ↩도).
  - 검증은 domain의 `itemMetadataSchema`·`titleSchema`를 그대로 쓴다. 잘못된 필드는 빨간 테두리 + 필드 아래 footnote 문구(원인 + 다음 행동, 예: "날짜는 2024, 2024-03, 2024-03-15처럼 적어 주세요."). 저장 실패(IPC)는 폼을 연 채 오류 토스트.
  - 편집 중에 다른 행을 고르거나 리더로 가거나 창을 닫으면(Zotero처럼 고친 것을 잃지 않는다):
    - 바뀐 것이 없으면 편집을 끝내고 그대로 넘어간다.
    - 바뀐 것이 모두 올바르면 **저장한 뒤** 넘어간다(저장 실패면 넘어가지 않고 오류 토스트).
    - 올바르지 않은 필드가 있으면 넘어가지 않는다: 표 선택을 편집 중인 자료로 되돌리고, 폼 위에 "저장하지 못한 변경이 있습니다. 표시한 칸을 고치거나 변경을 버리세요." 줄과 "버리기" 단추를 보인다(시트는 띄우지 않는다). 창 닫기도 같은 경우에만 막는다.
  - 저장하면 `library.updateMetadata` → `libraryChanged` → 표와 인스펙터가 다시 받는다. 제목이 바뀌면 다음 "기본 앱으로 열기"부터 새 이름의 사본을 쓴다(I1 규칙 그대로).
- **파일 절**: 보관(사본 · 라이브러리 안 / 외부 연결), 크기, 원래 이름, 위치(외부 연결만, 끝 말줄임 + 전체 경로 툴팁, mono), SHA-256(앞 8자 + `…`, mono, 툴팁에 전체 값) + 복사 아이콘 단추("전체 SHA-256 복사"). 복사하면 단추 툴팁이 1.5초 동안 "복사했습니다"로 바뀐다(토스트는 띄우지 않는다). 문구 검사의 내부 용어 규칙은 이 절의 두 문구(`t.inspector.fileSha`, `t.inspector.copySha`)만 허용 목록으로 둔다(P-11).
- 사용자 문장에 내부 용어를 쓰지 않는다(디자인 명세 9절): 보관 값은 "사본", 기술 값은 이 절에서만 mono로.

### 5.4 정보 모드 — 그 밖의 상태
- **선택 없음**(목업 `inspectorNone`): `mouse-pointer-2` 아이콘, "선택한 자료 없음", "표에서 자료를 고르면 정보가 여기에 보입니다."(읽기 진행은 M7에서 문구에 더한다), 그 아래 2차색 통계(12px 글자의 대비 4.5:1 — 3차색은 3.9:1로 못 미친다) "내 라이브러리 · 자료 48개(PDF 35 · 동영상 13) · 1.9 GB".
- **여러 개 선택**(목업 `inspectorMulti`, M4 몫): `files` 아이콘 + "PDF 2개 · 동영상 1개 · 합계 9.8 MB", 제목 "자료 3개 선택", 제목 목록(최대 8줄, 넘으면 "외 N개"). 동작 단추는 M4에 없다(탭 열기 M7, 컬렉션에 추가 M5).
- **불러오는 중**: 300ms 규칙.

## 7. main · IPC · 저장

- **`library.exportCopy({ itemId })`**(새 채널, `createHandle`):
  1. 저장 패널을 메인 창의 시트로(`asSheet`). 기본 이름은 기본 앱으로 열기의 이름 규칙(`openable.ts`의 `safeBaseName` + 확장자). 기본 폴더는 마지막으로 고른 폴더(없으면 다운로드).
  2. 같은 폴더의 임시 이름(`.<이름>.learn-export-<uuid>.part`)으로 `COPYFILE_FICLONE` 복사 → rename. 덮어쓰기는 저장 패널의 확인을 따른다. 실패하면 임시 파일을 지운다.
  3. 결과 `{ saved: false }`(취소) 또는 `{ saved: true }`. 렌더러는 저장했으면 "사본을 저장했습니다" 토스트 + "Finder에서 보기" 동작(main이 저장 경로를 기억해 `library.revealExport()`로 보인다 — 렌더러는 경로를 보지 않는다).
  4. 300ms를 넘는 복사는 바쁨 토스트: 렌더러의 `runFileAction`이 IPC가 300ms 넘게 끝나지 않으면 띄우고 끝나면 거둔다(main 이벤트 없음, P-12·P-29).
- **열 머리 메뉴**: 자기 채널 `ui:showColumnMenu`(`{ visible: ColumnId[], x, y }` → `{ toggle: ColumnId } | { reset: true } | null`). 쓰이지 않던 `ui.showContextMenu`의 `kind: 'column'` 입력은 없앴다(P-9).
- **클립보드**: 두 권한 처리기(확인·요청)에 `clipboard-sanitized-write`를 앱 출처에만 허용한다(읽기는 계속 거부). `navigator.clipboard.writeText`만 쓴다(P-6).
- **설정 키**: `library.columns`(3.2), `palette.recent`(4.4), `library.sort` 열 추가(3.1), `layout.panes`의 `inspector.info`·`inspectorCollapsed`(5.1). 모두 ADR-0007의 판별 규칙 (b) 라이브러리 KV다.
- **새 데이터 객체 없음**: M4는 화면 상태 키만 더한다. 그래서 "새 데이터 객체는 모두 앵커로 주소를 가질 수 있다"(제품 원칙 1.1)에 해당하는 것이 없다. 자료 선택·검색 결과는 저장하지 않는다.

## 11. 계획의 Global Constraints에 들어갈 것

M3 계획의 Global Constraints(버전 고정, IPC `createHandle`, 문체, 가짜 금지, 레이아웃 B, 토큰만, 작업마다 녹색, 긴 실행 백그라운드, 커밋 트레일러)를 그대로 잇고, 다음을 바꾸거나 더한다.
- 라이선스: ADR-0011(AGPL-3.0-or-later). 새 런타임 의존성은 허용 목록 검사(CI)를 통과해야 하고 정확히 고정한다. TanStack Virtual은 스파이크가 실패했을 때만 들인다.
- macOS 실행: 저장소가 공개라 무료다. 작업마다 필요한 suite만 돌리되, 같은 머리에 중복 실행하지 않는다.
- 제품 원칙(디자인 명세 1.1): "새 데이터 객체는 모두 앵커로 주소를 가질 수 있다"(M4는 해당 없음, 7절).
- 주석에는 이유만, 실행·비평 id는 커밋 메시지에(next-session "테스트·문서 보강").
