# M7a — 앵커 스파이크 · PDF 리더 v2 · 위치 기억 · 선택 번역 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 작업마다 아래 "검토 절차"를 따른다.

**Goal:** 소유자의 읽기 흐름(영어 논문 → 글 선택 → 한국어 번역)이 Learn 안에서 되게 하고, PDF 리더를 연속 스크롤·찾기·확대·회전·썸네일·목차·위치 기억을 갖춘 리더로 바꾸며, ADR-0009(앵커 허브)를 스파이크로 검증해 채택한다.

**Architecture:** 렌더러의 `PdfDocumentView` 하나가 pdf.js 뷰어 부품(`PDFViewer`·`EventBus`·`PDFLinkService`·`PDFFindController`)을 소유하고, 도구 막대·찾기 막대·사이드바·선택 팝업은 우리 UI 부품으로 그린다. 앵커는 도메인의 순수 함수(쪽 글 색인·인용 찾기·사각형 ↔ quad)와 DB 저장소(마이그레이션 003)이고 화면 동작은 없다. 번역은 main의 `translation/` 모듈(엔진 인터페이스 + `google-web` 엔진 + 캐시 + 허용 호스트 하나)이 IPC `translation:translate`로만 받고, 동의는 기기 환경설정 `translation.enabled`가 정한다.

**Tech Stack:** Electron 44.9.1, React 19.3.1, TypeScript 7.0.2, electron-vite 6.0.0, react-aria-components 1.22.1 (+ react-aria 3.53.1), lucide-react 1.60.0, @tanstack/react-query 5.104.5, @tanstack/react-virtual 3.14.22, zustand 5.0.15, zod 4.6.7, better-sqlite3 13.0.3, pdfjs-dist 6.4.299, Playwright 1.64.1, vitest, pnpm 10.15.1.

**Spec:** `docs/superpowers/specs/2026-11-03-m7a-reader-design.md`(아래 "명세", 소유자 승인 2026-11-03) + `docs/design/design-spec.md`(아래 "디자인 명세") + Task 1에서 소유자가 승인하는 M7a 목업. 코드 사실은 SDD 작업 공간의 `m7a-context.md`(계획 작성 때의 조사, HEAD ce5fe92 기준)에 있다 — 구현자는 자기 작업에 해당하는 절만 읽는다.

## 사전 판정 (2026-11-03, 계획 작성 전)

한 줄 = 판정 하나 → 반영한 작업.

- **P-0 계획의 모양(토큰 예산)**: M6 계획은 1.85 MB(작업 본문에 구현 코드 전체)였다. 소유자의 절약형 지시(2026-10-31)에 따라 이 계획은 작업마다 **파일, 인터페이스(정확한 이름·타입), 정확한 값, 시험 목록(핵심 시험 코드), 단계**를 적고 구현 코드를 다 옮겨 적지 않는다. 그래서 구현자는 sonnet(산문 명세에서 구현하는 중간 등급), 검토자도 sonnet이고, opus는 디자인 비평과 마지막 브랜치 검토에만 쓴다.
- **P-1 스파이크 순서**(명세 3절 "첫 작업"): 앵커의 순수 부분(도메인 모양·쪽 글 색인·인용 찾기·quad 변환·W3C 변환기)과 마이그레이션 003·저장소를 **Task 2**에서 먼저 한다(DOM 없음). DOM이 필요한 채택 조건 둘(명세 3.1 E2E)은 실제 뷰어가 생긴 뒤 **Task 7**이 한다. 결과가 예상(명세 3.2)과 다르면 Task 7이 ADR-0009를 먼저 고치고 마이그레이션 003을 고친다(병합 전이라 아직 아무 라이브러리에도 적용되지 않았다).
- **P-2 quad 점 순서**: ADR-0002는 `[x1,y1,…,x4,y4]`만 정했다. 순서는 **위왼쪽 · 위오른쪽 · 아래왼쪽 · 아래오른쪽**(회전 전 쪽 기준, PDF 주석 QuadPoints의 실무 순서)으로 정하고 Task 7이 ADR-0009 스파이크 결과 절에 적는다 → Task 2.
- **P-3 번역 요청 형식(컨트롤러가 2026-11-03 직접 확인)**: `POST https://translate.googleapis.com/translate_a/single?client=gtx&sl=<from>&tl=<to>&dt=t`, 본문 `application/x-www-form-urlencoded` `q=<글>`. 응답은 JSON 배열: 번역문 = `r[0]`의 각 조각 `seg[0]`을 이은 것(조각은 원문 문장마다 하나, 원문의 `\n`이 조각 끝에 남는다), 감지 언어 = `r[2]`(예 `"en"`). 한국어를 `tl=ko`로 보내면 같은 글과 `"ko"`가 온다. 시험용 영어 문장으로 받은 응답 셋을 작업 공간에 두었다(`tr-post.json` — en→ko, 두 문장·줄바꿈, `tr-get.json` — 자동 감지 두 문장, `tr-ko.json` — 한국어 입력). Task 4가 `fixtures/translation/`으로 옮긴다(소유자 자료 아님). `sl=auto`는 `from: 'auto'`일 때.
- **P-4 목업 게이트**: Task 1(목업)을 먼저 하고 소유자 승인을 받는다. 승인을 기다리는 동안 화면과 무관한 Task 2·3·4를 진행한다. 화면 작업(Task 5 이후)은 승인 뒤에 시작한다.
- **P-5 번역 캐시의 자리**: 명세 6.5대로 라이브러리 DB(`translation_cache`, 마이그레이션 003). 라이브러리를 바꾸면 캐시도 바뀐다(번역은 다시 받으면 된다) → Task 2(테이블), Task 4(저장소·사용).
- **P-6 가짜 엔진**(명세 6.7 정정): E2E(`LEARN_E2E=1`, `isE2E`)에서는 **언제나** 가짜 엔진을 쓴다 — 환경 변수 `LEARN_TRANSLATION_ENGINE`은 두지 않는다(시험이 실수로 Google을 부를 길을 없앤다). 가짜 엔진은 먼저 내장한 실제 번역 표(`CANNED`, P-3 응답의 원문 문장 → 번역문)를 찾고, 없으면 `{ text: '번역: ' + 정리한 원문, detectedFrom: 'en' }`을 돌려준다. 시험 훅으로 모드를 바꾼다(`ok | offline | rateLimited | blocked | unavailable | badResponse | slow`). 요청 수는 엔진 호출 수(캐시 적중은 세지 않는다). Mac 데모도 이 가짜 엔진의 내장 표를 쓴다(러너에서 Google을 부르지 않는다 — 실패 메일과 바깥 전송을 피한다) → Task 4.
- **P-7 Mac 실행**: 중간 `e2e`는 Task 9 뒤(리더 화면·위치가 다 들어간 때), 끝 `all`은 Task 12. 모두 컨트롤러가 `workflow_dispatch`로.
- **P-8 리더의 인스펙터**: 지금 리더에는 인스펙터가 없다(`MainWindow.tsx`가 `showsTable`일 때만 `<Inspector mode="info"/>`를 넘긴다 — 오른쪽 슬롯은 튜터 자리). 소유자 결정(번역 = 팝업 + 인스펙터 절)에 따라 M7a는 **리더에도 정보 모드 인스펙터**를 둔다: 맨 위 "번역" 절 + 연 자료의 `ItemInfo`. `view.toggleInspector`(⌥⌘I)와 인스펙터 토글 단추가 리더에서도 동작하고, 폭·접힘 상태는 라이브러리와 같은 `useShell.inspector` 하나를 쓴다. 리더의 내용 최소 폭은 디자인 명세 2.5의 리더 값 **440**(`READER_CONTENT_MIN`)이고 `hiddenPanes`가 보기별 최소 폭을 받는다. T1이 튜터 모드를 더할 때 "리더 → 튜터" 기억 규칙(2.5)을 적용한다 → Task 10.
- **P-9 공유 단축키**: ⌘F·⌘+·⌘−·⌘0은 라이브러리와 리더가 다른 일을 하는데, 메뉴 막대는 모든 보기에 하나이고 `commands.test.ts`가 가속기 하나에 명령 하나를 강제한다. 그래서 **명령 하나가 보기에 따라 이름과 동작을 바꾼다**: `stateLabels`에 키 `view?: Record<'library' | 'viewer', string>`를 더하고(한 명령에 키 하나 규칙은 그대로), 기존 id를 유지한다(`palette.recent` 저장값이 깨지지 않게). `library.find` {library '빠른 검색', viewer '찾기'}, `view.textBigger` {'글자 크게', '확대'}, `view.textSmaller` {'글자 작게', '축소'}, `view.textReset` {'기본 글자 크기', '실제 크기'}. 맥락은 `['library','viewer']`, 규칙은 `c.view === 'viewer' ? c.pdfOpen === true : (기존 규칙)` → Task 6(확대), Task 8(찾기).
- **P-10 PDF 맥락**: `CommandContextState`에 평평한 값 `pdfOpen?: boolean`(PDF 문서가 열려 그려질 수 있음)과 `pdfSelection?: boolean`(글 선택 있음)을 더한다(`commandContextInput`, `NO_LIBRARY_VIEW`·main `DEFAULT_CONTEXT`는 false). 동영상 리더도 `view: 'viewer'`이므로 PDF 명령은 `pdfOpen`으로 켠다 → Task 6(`pdfOpen`), Task 10(`pdfSelection`).
- **P-11 마이그레이션 003은 열 더하기만**(명세 3.3 정정): `anchors`를 다시 만들면 `annotations.anchor_id … ON DELETE RESTRICT` 때문에 행이 있는 라이브러리에서 `DROP TABLE`이 막히고, 이 앱의 마이그레이션은 트랜잭션 안(외래 키 켬)에서 돈다. 그래서 M7a는 `ALTER TABLE anchors ADD COLUMN precision TEXT NOT NULL DEFAULT 'span' CHECK (precision IN ('item','span','region'))`와 `ADD COLUMN text_json TEXT`만 한다. `kind` CHECK 변경(`'slide'` → `'slides'`, 새 kind)은 어차피 테이블을 다시 만들어야 하므로 **처음 새 kind를 더하는 M7b(`image`)가 한 번에** 한다(그때도 `annotations`는 비어 있다 — 필기는 M9). 도메인의 `slideAnchor`도 M7b까지 `'slide'`다. ADR-0009 스파이크 결과 절에 적는다 → Task 2, Task 7.
- **P-12 바깥 링크**(명세 4.6·9 정정): 새 IPC `reader:openExternal`을 두지 않는다. pdf.js 링크 서비스를 `externalLinkTarget: LinkTarget.BLANK`로 두면 링크가 `window.open`이 되고, 이미 있는 `M/security.ts`의 `setWindowOpenHandler`가 `http(s)`를 `shell.openExternal`로 연다. 여기에 `mailto:`만 더한다(그 밖의 스킴은 지금처럼 거부). 주소 툴팁은 pdf.js가 `<a title=url>`로 단다 → Task 5.
- **P-13 시험 PDF**: 생성기(`fixtures/generate.mjs`)는 pdf-lib 1.17.1의 표준 14 글꼴(라틴)만 쓸 수 있다. 한국어 쪽은 개발 의존성 `@pdf-lib/fontkit` **1.1.1**(MIT, 정확히 고정)을 더하고 저장소의 `PretendardVariable.woff2`(OFL)를 **부분 넣기 없이**(`subset: false`) 넣는다 — 가변 글꼴의 부분 넣기는 fontkit에서 실패하고, 통째로 넣으면 pdf.js가 글꼴 프로그램을 읽지 못해 캔버스에 한글이 그려지지 않지만 **글 내용과 글 조각 폭은 정확하다**(컨트롤러가 2026-11-03 확인: `getTextContent`가 "주의 메커니즘은 중요합니다. Attention matters."를 돌려준다). 한국어 쪽은 글 레이어(앵커·찾기·번역)를 시험하는 용도이고 투어에서는 캔버스를 가린다. 암호 PDF는 pdf-lib로 만들 수 없으므로 `mutool convert -O encrypt=aes-128,user-password=learn`으로 한 번 만든 작은 파일을 `fixtures/static/locked.pdf`로 커밋하고(README에 만든 명령), 생성기가 `fixtures/generated/`로 복사한다(CI 러너에 mutool이 없어도 된다) → Task 5.
- **P-14 쪽 색 메뉴**: 메뉴 막대 보기 메뉴의 "쪽 색 ▸"는 `SUBMENUS`의 새 묶음 `pageColor`(기존 `colorTags` 묶음 방식 — 멤버 명령 넷은 자리 없이 묶음이 자리를 가진다)로 둔다. 네이티브 메뉴에는 체크 표시를 하지 않고, 지금 값의 체크는 도구 막대의 보기 ▾(웹 메뉴, `MenuButtonItem.checked`)가 보인다 → Task 6.

## Global Constraints

모든 작업의 요구 사항에 아래가 암묵적으로 포함된다. 따옴표 안은 명세 원문이다.

- **버전**: 저장소에 고정된 그대로 쓴다(위 Tech Stack). "런타임 의존성은 정확히 고정하고 새로 더하지 않는다(필요하면 계획에서 근거와 라이선스를 적는다)." `^`·`~` 금지.
- **라이선스**: 저장소는 AGPL-3.0-or-later다(ADR-0011). `LICENSE`와 `package.json`의 `license` 필드는 건드리지 않는다. "AGPL 코드(Zotero reader, zotero-pdf-translate)는 보지도 가져오지도 않는다. pdf.js(Apache-2.0)의 CSS를 옮기면 고지를 단다."
- **앵커 원칙**: "새 데이터 객체는 모두 앵커로 주소를 가질 수 있다(제품 방향 합의)." 번역 캐시는 자료가 아니라 파생 캐시다(앵커 없음, P-5).
- **네트워크**: "원격 요청은 main만, 허용 호스트 하나, 동의 전·끈 상태에서는 0회, 자동 재전송 없음." 렌더러 CSP는 그대로 `connect-src 'self'`.
- **IPC**: 모든 새 채널은 기존 `handle()` 래퍼(발신자 검사 + zod + Result)와 채널 종류 허용 목록을 쓴다. preload는 이름공간 API만 노출한다(범용 invoke/send 금지).
- **가짜 금지**: "메뉴·팔레트·도구 막대는 레지스트리에서만, 핸들러 없는 항목은 그리지 않는다." M7b 항목(탭 줄, 뒤로/앞으로, 스크롤·펼침 모드, 이미지, 본문 검색)은 자리도 남기지 않는다.
- **문체**: "문체는 합니다체, 화면 문구는 `strings/` 영역 파일에. 한국어 조사는 `eulReul` 등 `josa.ts`." 버튼은 동사형, 오류 = 원인 + 다음 행동, 관형사 + 명사는 U+00A0으로 묶는다(디자인 명세 9).
- **토큰만**: 화면 코드에서 색·간격·반경·글자 크기를 직접 쓰지 않는다. 토큰이 아닌 값은 같은 줄에 `/* local: 이유 */`. 한글 UI에 700을 쓰지 않는다. `css-lint.test.ts`가 막는다. 쪽 색 필터(세피아·어둡게)의 값은 `/* local: */` 주석과 함께 한곳에 둔다.
- **macOS 시트**: "시트 뒤 클릭은 `sheetReleased()` 뒤에(macOS 250ms)."
- **역할**: "구현자는 push·CI 실행·하위 에이전트 실행을 하지 않는다(컨트롤러가 한다)." 실제 번역 주소를 부르는 일도 하지 않는다(P-3의 응답을 쓴다).
- **주석**: 새 코드의 주석에는 이유만 쓴다. 판정 번호·실행 id·비평 id는 커밋 메시지에.
- **작업마다 녹색**: 작업을 끝낼 때 `pnpm typecheck`, `pnpm test`, `pnpm tokens:check`, `pnpm e2e:xvfb`, `xvfb-run -a -s "-screen 0 1440x900x24" pnpm exec playwright test -c playwright.evidence.config.ts`가 모두 통과한다. 리더 화면을 바꾼 작업은 기능 E2E 중 리더 spec을 `xvfb-run -a -s "-screen 0 1024x768x24"`로도 한 번 돈다(Mac 러너 화면 크기). 문구를 바꾸면 `strings.test.ts`도.
- **시험 출력은 tmpfs에**: Playwright는 `--output=/tmp/<고유 이름>`으로 돌린다. 프로세스는 `ps`로 보고 정확한 PID만 끝낸다(`pkill -f` 금지).
- **긴 실행**: `pnpm e2e:xvfb`와 증거 전체는 포그라운드에서 나눠 돌리거나 백그라운드로 돌리고 끝날 때까지 직접 기다린다(차례를 끝내지 않는다, 포그라운드 `sleep` 금지). 실패하면 실패한 spec만 다시 돌려 고친 뒤 전체를 한 번 더.
- **git**: `git stash`를 그냥 쓰지 않는다. 임시로 치울 것은 WIP 커밋으로. push한 기록을 고쳐 쓰지 않는다(amend·force-push 금지).
