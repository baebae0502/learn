## 1. 목표와 완료 조건

- 논문 여러 편을 탭으로 오가며 읽고, 인용 링크를 따라갔다가 뒤로 돌아오고, 다시 실행해도 탭이 그대로다.
- PDF 보기가 세로 스크롤 하나에서 가로·한 쪽씩·펼침 보기로 넓어지고, 모든 쪽 이동이 같은 자리 규칙(위 여백·왼쪽 여백·가장 넓은 쪽 맞춤)을 따른다.
- M7a에서 넘긴 리더 결함을 닫는다(8절).
- 완료 조건:
  - Linux CI 녹색, Mac `all` 녹색(증거·기능 E2E·데모 영상), Mac 디자인 비평 blocker/major 0건(라이트와 다크 프레임 모두).
  - 세션 복원: 정상 종료와 SIGKILL 뒤 다시 실행하면 탭·순서·활성 탭이 돌아오고, 활성 탭은 저장된 자리에 있다(E2E).
  - 뒤로/앞으로: 링크·목차·썸네일·쪽 필드 이동이 기록되고, 앞으로가 마지막 자리로 정확히 돌아온다(E2E).
  - 가린 탭이 있을 때 창 크기를 바꿔도 다시 맞춤이 끝나지 않는 일(M7a N-1)이 없다(E2E).
  - 성능 예산(12절) 안.

## 2. 범위

**M7b 안**
1. 탭: 모델, 탭 줄, 여는 규칙, 키·메뉴, 끌기, 세션 저장·복원, 살려 두기와 탭별 리더 상태(3절).
2. 뒤로/앞으로(4절).
3. 보기 모드: 스크롤(세로·가로·한 쪽씩)과 펼침(없음·홀수·짝수)(5절).
4. 쪽 놓기 규칙: R-21 가장 넓은 쪽 맞춤, R-25 쪽 이동 뒤 왼쪽 여백, 쪽 이동 뒤 위 여백(6절).
5. 라이브러리 항목 패널의 '읽기' 절(7절).
6. M7a에서 넘긴 리더 고칠 것(8절).

**M7c로**: 이미지 계열과 `image` 앵커(kind CHECK를 `'slides'`로 맞추는 마이그레이션 포함 — P-11), PDF 본문 검색(FTS5, `spec-amendments.md` 8절), 성능 항목(M5 E2·E6·m-1·m-8·m-9, Mac에서 넘은 줄, 토스트 그리기 p95, 목록 다시 읽기를 유휴로), 비공식 번역 주소 재확인.

**이번에도 하지 않는 것**: 필기(M9), 튜터(T1), 영상 v2(M8 — 영상 자료는 지금 보기 그대로 탭에 든다), 트랙패드 두 손가락 쓸기로 뒤로/앞으로(실기 항목), 창 여러 개·탭을 창으로 떼기, 탭 고정·탭 묶음.

## 3. 탭

### 3.1 모델
- 탭은 `{ id, kind: 'item', itemId }`이고(세션 탭 같은 다른 종류가 들어올 자리를 구조로 연다) 라이브러리 탭(`id: 'library'`)이 늘 첫째다. 같은 `itemId`의 탭은 둘이 될 수 없다.
- 셸 상태(`useShell`의 `view`)를 `tabs: Tab[]`, `activeTabId`, `recent: tabId[]`(최근 본 순서, 살려 둘 탭을 고른다), `closed: itemId[]`(이번 실행에서 닫은 탭, 최근 10개)로 바꾼다. 지금의 `view.kind`는 활성 탭에서 유도한다(라이브러리 탭 → `library`, 리더 탭 → `reader`).
- 탭 수에 상한은 없다. 저장은 50개까지(3.6).

### 3.2 탭 줄 (디자인 명세 2.2 탭 치수 · 2.3 레이아웃 B)
- 탭이 라이브러리 하나뿐이면 지금처럼 탭 줄을 그리지 않는다(통합 도구 막대). 리더 탭이 하나라도 있으면 내용 열 위 52px이 탭 줄이고, 사이드바 끝에서 12 띄워 시작한다. 사이드바를 접으면 디자인 명세 2.2의 규칙대로 신호등 인셋·사이드바 토글·⌘K 실행기가 탭 줄로 온다.
- 탭: 높이 28, 반경 6, 기준 폭 240, 줄이 꽉 차면 최소 120까지 줄어든다, 간격 4. 활성 탭은 `--bg-control` + `--shadow-e0`, 비활성은 투명·`--text-secondary`, 비활성 탭 사이 16px 구분선. 아이콘 16(라이브러리 `library-big`, PDF·영상은 종류 아이콘) + 제목(줄임 "…", 전체 제목은 툴팁). 닫기(18)는 활성·호버 탭에만. 상태: 비활성 · 호버 · 활성 · 포커스(안쪽 링) · 닫기 호버 · 끌기 중(`--bg-raised` + e1).
- 라이브러리 탭은 스크롤하지 않고 줄 맨 앞에 고정한다. 그 뒤 16px 구분선은 늘 그린다. 리더 탭은 자기 영역에서 스크롤하고, 그 영역의 높이는 탭 줄 높이와 같게 한다(활성 탭의 그림자와 끌기 중의 들림이 잘리지 않게). 넘친 쪽 가장자리에는 24px 페이드를 건다.
- 최소 폭에서도 넘치면 리더 탭 영역이 가로로 스크롤되고 활성 탭은 늘 보이게 스크롤한다. 스크롤 막대는 보이지 않는다(트랙패드·휠로 가로 이동).
- M7a의 창 도구 막대(뒤로 · 제목 · 종류와 크기)는 없앤다. 뒤로는 라이브러리 탭이, 제목은 탭이, 종류와 크기는 항목 패널이 맡는다.
- 접근성: RAC `Tabs`의 `TabList`(가로, 화살표 이동, 포커스 링). 탭 패널은 활성 탭의 내용이다.

### 3.3 여는 규칙
- ↩·더블클릭(`item.open`): 그 자료의 탭이 있으면 그 탭으로, 없으면 활성 탭 바로 오른쪽에 새 탭을 열고 그리로 간다.
- ⌘↩(`item.openInBackground`, 이름 "새 탭에서 열기"): 탭이 없으면 맨 끝에 열되 활성 탭은 그대로다. 있으면 아무것도 하지 않는다(탭이 이미 있다는 토스트 없음 — 탭 줄에 보인다).
- 여러 개를 골라 ↩: 고른 순서(표 순서)대로 열고 첫 자료의 탭으로 간다. ⌘↩는 모두 뒤에서 연다. 컨텍스트 메뉴 이름은 "탭 N개로 열기"/"새 탭 N개로 열기". 11개 이상이면 먼저 확인 시트(`ui.confirm`, "자료 N개를 탭으로 열겠습니까?")를 띄운다.
- 휴지통 보기의 자료는 지금처럼 열 수 없다(M6 규칙).

### 3.4 키 · 메뉴 · 컨텍스트 메뉴 (디자인 명세 7.3·7.4)
- ⌘1: 라이브러리 탭(지금의 `nav.back`, 이름 "라이브러리"). ⌘2…⌘8: 2…8번째 탭. ⌘9: 마지막 탭. ⌃⇥ / ⌃⇧⇥: 다음 / 이전 탭(끝에서 처음으로 돈다).
- ⌘W(파일 메뉴 "탭 닫기"): 활성 리더 탭을 닫고 `recent`의 바로 앞 탭으로 간다. 라이브러리 탭에서는 창을 닫는다(지금 동작). ⇧⌘W: 창 닫기.
- ⇧⌘T(파일 메뉴 "닫은 탭 다시 열기"): `closed`의 마지막 자료를 다시 연다(휴지통·영구 삭제된 자료는 건너뛴다). 없으면 꺼짐.
- 윈도우 메뉴: 다음 탭 · 이전 탭 · — · 열린 탭 목록(체크 표시는 활성 탭). 이동 메뉴: 뒤로 ⌘[ · 앞으로 ⌘](4절).
- 탭 컨텍스트 메뉴(네이티브, 포인터 끝에서 열린다): 탭 닫기 ⌘W · 다른 탭 닫기 · — · 라이브러리에서 보기 · Finder에서 보기 ⇧⌘R. 라이브러리 탭에는 메뉴가 없다.
- 오른쪽 클릭은 탭을 바꾸지 않고 그 탭을 대상으로 한다. 단축키 표시는 메뉴가 활성 탭의 것일 때만 하고, 다른 탭의 메뉴에서는 단축키 없이 보인다.
- "라이브러리에서 보기": 라이브러리 탭으로 가서 그 자료 행을 고르고 보이게 스크롤한다(컬렉션 필터가 그 자료를 가리면 "내 라이브러리"로 바꾼다).

### 3.5 끌어서 순서 바꾸기
- 리더 탭만 끈다. 라이브러리 탭 앞으로는 놓을 수 없다. 끄는 동안 다른 탭이 자리를 비켜 준다(움직임 160ms, reduced-motion이면 즉시).
- 키보드로도: 탭에 포커스가 있을 때 ⌥⇧← / ⌥⇧→로 한 칸 옮긴다(명령 레지스트리, 메뉴에는 없음).
- 탭 줄 밖으로 끌어내기(창 떼기)는 하지 않는다.

### 3.6 세션 저장 · 복원
- 설정 `ui.tabs = { items: { kind: 'item', id: uuid }[] (≤ 50), active: uuid | null }`(zod는 모르는 `kind`를 버리고 나머지를 살린다)(DB 설정, 라이브러리마다). 탭을 열고·닫고·옮기고·바꿀 때 300ms 묶어서 쓴다. 정상 종료와 SIGKILL 둘 다에서 마지막 묶음까지 남는다(M7a 위치 저장과 같은 방식).
- 실행할 때: 저장된 자료 가운데 아직 있는 것(휴지통 자료 포함 — 리더의 '휴지통에 있음' 상태로 연다)만 탭으로 되살리고, 영구 삭제된 것은 버린다. 활성 탭만 마운트하고 나머지는 처음 고를 때 저장된 위치로 연다.
- `ui.lastOpenItemId`는 지금 쓰임(라이브러리로 돌아오면 그 행을 보임) 그대로 둔다.
- 라이브러리를 바꾸면(재시작) 그 라이브러리의 탭이 온다 — 설정이 라이브러리마다이므로 따로 할 일이 없다.

### 3.7 살려 두기와 탭별 리더 상태
- 리더 상태(`readerStore`의 `pdf`·`handle`·`noPages`, 찾기 막대, 번역 절의 원문·번역, 뒤로/앞으로 기록)를 탭마다 둔다: 탭마다 store 하나를 만들고 리더 하위 트리에는 React 컨텍스트로 준다. 셸이 그리는 도구 막대·사이드바·항목 패널은 활성 탭의 store를 읽는다.
- 마운트: 활성 탭 + `recent`의 리더 탭 가운데 최근 3개 = 리더 탭 최대 4개. 그 밖의 탭은 뷰를 내리고 store의 가벼운 부분(마지막 locator, 뒤로/앞으로 기록)만 남긴다. 다시 고르면 마지막 locator로 연다.
- 가린 탭: `hidden` + `inert`. 가린 동안 맞춤 관찰자는 크기 변화에 반응하지 않는다. 다시 보일 때 무대 크기가 바뀌었으면 한 번만 다시 맞춘다(M7a N-1 — 자기 스크롤 막대에 반응해 끝없이 맞추던 것 — 이 되살아나지 않게). 가린 PDF 보기는 보이지 않는 쪽의 캔버스를 놓아 메모리를 줄일 수 있는지 첫 탭 작업에서 재고 정한다(12절 메모리 줄).
- 가릴 때: 선택 팝업을 닫고(패널의 원문·번역은 남는다), 영상은 멈춘다. 찾기 막대는 열린 채 남는다.
- `PdfReader`의 `restoredRef`/`latestRef`(M7a Task 9 Minor 4): 탭 하나는 자료 하나만 보이므로 지금처럼 자료마다 새 리더지만, 다시 마운트될 때 둘을 초기화하도록 고친다.

### 3.8 자료 상태가 바뀔 때
- 열린 탭의 자료를 휴지통으로 옮기면 탭은 남고 리더의 '휴지통에 있음' 상태가 된다. 복원하면 다시 쪽이 보인다.
- 영구 삭제하면 그 탭을 닫는다(`closed`에도 넣지 않는다). 활성 탭이었으면 `recent`의 앞 탭으로 간다.
- 원본 파일이 사라졌으면 지금의 '원본 없음' 상태다(다시 연결은 그 상태의 단추).
- 제목을 고치면 탭 이름이 바로 바뀐다(`libraryChanged` 알림).

## 4. 뒤로 / 앞으로 (디자인 명세 7.4 "링크·목차 이동 기록")
- 탭마다 기록이 따로다. 기록에 남는 것은 '뛰는' 이동만이다: 문서 안 링크, 목차, 썸네일(클릭·↩), 쪽 필드 입력(⌥⌘G 포함). 남기지 않는 것: 스크롤, 이전·다음 쪽(셰브런·키), 찾기 결과 이동, 확대·회전·보기 모드.
- 항목은 locator(쪽·쪽 안 위치, M7a `readingLocatorSchema`의 pdf 형태)다. 이동할 때 지금 자리를 현재 항목에 고쳐 쓰고 새 항목을 더한다. 뒤로 가기 직전에도 지금 자리를 현재 항목에 고쳐 쓴다 — 그래서 앞으로는 마지막으로 있던 자리로 돌아온다. 뒤로 간 뒤 새로 이동하면 앞쪽 기록을 지운다. 탭마다 50개.
- 확대·회전이 바뀐 뒤에도 locator는 쪽 기준이라 같은 자리를 가리킨다.
- 조작: ⌘[ / ⌘](이동 메뉴 "뒤로"/"앞으로", 명령 `nav.historyBack`/`nav.historyForward`), 마우스 옆 단추(`MouseEvent.button` 3/4, 리더 무대 위에서), 리더 도구 막대 맨 왼쪽(쪽 필드 앞) ‹ ›(lucide `arrow-left` / `arrow-right`) 아이콘 단추(28, 툴팁 "뒤로 ⌘["/"앞으로 ⌘]", 기록이 없으면 꺼짐).
- 기록은 탭이 내려가도 남고, 다시 실행하면 비어 있다. 영상 탭에는 기록이 없다(단추를 그리지 않는다).

## 5. 보기 모드 (디자인 명세 7.3 보기 ▾)
- 보기 ▾(리더 도구 막대)와 메뉴 막대 보기 메뉴에 "스크롤 ▸"(세로 / 가로 / 한 쪽씩)와 "펼침 ▸"(없음 / 홀수 쪽부터 / 짝수 쪽부터)를 더한다. 하위 메뉴와 체크 표시 규칙은 M7a의 "쪽 색 ▸"와 같다. pdf.js의 `ScrollMode`(VERTICAL·HORIZONTAL·PAGE)와 `SpreadMode`(NONE·ODD·EVEN)를 그대로 쓴다. 줄바꿈(WRAPPED)은 넣지 않는다.
- 가로 스크롤에서는 펼침 하위 메뉴를 끈다(설명 문구 없이 꺼짐만). pdf.js 6.4가 가로와 펼침을 함께 받는지는 첫 보기 모드 작업에서 확인한다 — 받더라도 이 규칙은 지킨다(가로 펼침은 넓은 문서에서 읽기 어렵다).
- 한 쪽씩: ↓·스페이스·PageDown이 쪽 끝에서 다음 쪽으로, ↑·⇧스페이스·PageUp이 쪽 위에서 이전 쪽으로 넘어간다. 트랙패드·휠 스크롤이 쪽을 넘길지는 첫 보기 모드 작업에서 pdf.js 6.4의 동작을 확인하고 판정한다(판정은 원장과 이 절에).
- 자료마다 기억한다: `readingLocatorSchema`의 pdf 형태에 선택 필드 `scroll: 'vertical' | 'horizontal' | 'page'`, `spread: 'none' | 'odd' | 'even'`을 더한다. 옛 값(없음)은 세로·없음이다. DB 마이그레이션은 없다(`locator_json`).
- 진행률(가장 멀리 본 쪽)과 위치 저장은 모드와 상관없이 같은 규칙이다. 맞춤(자동·폭·쪽)은 펼침이면 두 쪽 묶음에 맞춘다(pdf.js 동작).

## 6. 쪽 놓기 규칙 (R-21 · R-25 · 위 여백)
- 쪽으로 가는 모든 이동 — 쪽 필드, 이전·다음, 썸네일, 목차, 링크, 뒤로/앞으로, 다시 열기, 회전 뒤 — 이 함수 하나(`placePage`)를 거친다.
- 위: 쪽 위끝이 무대 맨 위에 놓이면 첫 쪽은 24, 나머지는 12를 위에 남긴다(M7a의 열기·회전 규칙과 같다). 링크·목차의 대상이 쪽 안의 한 점(XYZ의 top)이면 그 점을 지킨다(여백을 더하지 않는다).
- 왼쪽(R-25): 쪽이 무대보다 넓고 이동 뒤 `scrollLeft`가 쪽 왼쪽 끝과 같으면 왼쪽 24를 남긴다. 대상에 left가 있으면 그 점을 지킨다. 다시 열기의 정밀도는 `allowNegativeOffset: true`로 저장된 자리가 여백 안이어도 그대로 놓는다.
- 가로 스크롤·한 쪽씩에서도 같은 여백 규칙을 쓴다(가로 스크롤은 왼쪽 24·쪽 사이 12가 위아래 규칙의 대응).
- 맞춤(R-21): 자동·폭 맞춤의 기준 폭은 지금 쪽이 아니라 문서에서 가장 넓은 쪽이다(회전을 반영한 폭). 모든 쪽 크기를 아는 때(pdf.js `pagesloaded`)에 한 번 다시 맞춘다. 그 전에는 지금처럼 첫 쪽 기준이다. 쪽 맞춤(page-fit)은 지금 쪽 기준 그대로다.

## 7. 라이브러리 항목 패널의 '읽기' 절
- 자리: 라이브러리 항목 패널, 머리(제목·저자) 아래와 정보 절 위(목업 `views.js`의 M7b 표시 자리).
- 내용: 진행 막대(넓은·두꺼운 변형) + 퍼센트, 그 아래 footnote 2차색 한 줄 — PDF "12 / 30쪽에서 멈춤 · 어제", 영상 "12:34에서 멈춤 · 어제". 날짜는 표의 날짜 열과 같은 형식(`오늘 오후 9:40`, `어제`, 날짜).
- 쪽 수는 PDF locator에 선택 필드 `pages`(전체 쪽 수)를 더해 위치를 저장할 때 함께 쓴다. `pages`가 없는 옛 값은 "12쪽에서 멈춤"이다.
- 한 번도 연 적 없으면 절이 없다. 여러 개를 고르면 없다. 휴지통 보기에서도 없다.
- 위치는 `reader:getPosition`으로 읽고, `libraryChanged { reason: 'position' }`이 오면 다시 읽는다.

## 8. 리더 고칠 것 (`next-session.md` "M7a에서 나온 M7b 입력"·"PR 남은 것 (M7a …)")
- 썸네일: 화면 배율(DPR)이 바뀌면 다시 그린다. 그리기 실패는 한 번 다시 시도하고, 그래도 실패하면 실패 모양(쪽 번호 + 경고 아이콘, 회색 칸)을 보인다. 목록(listbox)에 `aria-activedescendant`를 단다(m-9).
- 목차: 큰 목차(200항목 이상)를 가상화한다. `outlinePages`를 한꺼번에(`Promise.all`, 묶음) 푼다. 처음 열 때 옛 내용을 한 번 그리던 것(`useOutline`)을 없앤다.
- 쪽: 그리기에 실패한 쪽을 다시 시도한다(보이게 될 때 한 번).
- 깜빡임: 쪽 색 저장값을 읽기 전 한 프레임(Task 6), PDF를 열 때 오른쪽 패널이 한 프레임 폭 0(Mac 비평).
- 리더 내부: 같은 `ready`에서 PDF 보기가 다시 붙으면 찾기 막대의 스크롤 막대 오프셋 관찰자가 옛 노드를 보던 것, `PdfDocumentView`가 `setHandle`과 정리 사이에서 던지면 낡은 핸들이 남던 것(Task 6), ⌘/ 시트 높이 캐시 키가 보기를 보지 않던 것(Task 6), 종료 시 저장 스로틀 타이머 정리.
- 그 밖: 번역 켜기·사용 안 함이 환경설정 질의 전에 눌리면 기본 설정으로 돌아가던 것(Task 10 Minor 6), 명령 전수 장부를 이름 정확 비교로(Task 12a Minor 3), 앵커 스파이크 탐침을 제품 번들에서 뺀다(Task 7 — `e2e=1`일 때만 동적 import), pagesinit 전 뷰어 실패의 자동 시험(Task 5).
- 그대로 두는 것(이유를 `next-session.md`에 남긴다): 다시 맞출 때 글 선택이 지워짐(pdf.js 동작), 아주 빠른 드래그의 마지막 글자(pdf.js 6 + Chromium 152), `anchors` 저장소의 호출자(M9·T1), `toasts.tsx`의 RAC 비공개 필드(의존성 고정 동안), 이어 붙인 번역이 한 문단(R-20, 소유자가 원하면 바꾼다), 부정 확인의 고정 대기 둘.

## 14. 계획의 Global Constraints에 들어갈 것
- 새 데이터 객체는 모두 앵커로 주소를 가질 수 있다(제품 방향 합의). 탭·기록은 화면 상태라 앵커 대상이 아니다.
- AGPL 코드(Zotero reader, zotero-pdf-translate)는 보지도 가져오지도 않는다. pdf.js(Apache-2.0)의 CSS를 옮기면 고지를 단다. 런타임 의존성은 정확히 고정하고 새로 더하지 않는다(필요하면 계획에서 근거와 라이선스를 적는다).
- 원격 요청은 main만, 허용 호스트 하나, 동의 전·끈 상태에서는 0회, 자동 재전송 없음(M7a 그대로). 실제 번역 주소는 시험에서 부르지 않는다.
- 가짜 컨트롤 금지: 메뉴·팔레트·도구 막대·탭 메뉴는 레지스트리에서만, 핸들러 없는 항목은 그리지 않는다.
- 문체는 합니다체, 화면 문구는 `strings/` 영역 파일에. 한국어 조사는 `josa.ts`.
- 시트 뒤 클릭은 `sheetReleased()` 뒤에(macOS 250ms).
- 가린 탭은 크기 관찰에 반응하지 않는다(M7a N-1).
- 구현자는 push·CI 실행·하위 에이전트 실행을 하지 않는다(컨트롤러가 한다).
- 커밋 꼬리말 두 줄(Co-Authored-By, Claude-Session).

## 15. 디자인 명세 변경 (`spec-amendments.md` 13절로 옮길 것)
1. M7b를 리더 중심으로 줄이고 이미지·본문 검색·성능은 M7c(0절). 로드맵 표의 M7b 줄을 고치고 M7c 줄을 더한다.

3. 2.2 탭 줄: 넘칠 때 가로 스크롤(3.2), M7a 창 도구 막대를 없앰.
4. 7.4: ⌘W의 맥락(리더 탭 닫기 / 라이브러리 탭이면 창 닫기)과 ⇧⌘W 창 닫기, ⌥⇧← / ⌥⇧→ 탭 옮기기, 마우스 옆 단추.

## 16. 위험
- **탭별 리더 store 분리**: `useReader`를 쓰는 파일이 13개다. 첫 작업에서 store 생성과 컨텍스트만 바꾸고 동작은 그대로 둔 채 M7a E2E 전체로 고정한다(리팩터링 작업과 기능 작업을 나눈다).
- **가린 pdf.js 보기**: 크기 0의 무대에서 관찰자·`IntersectionObserver`·맞춤이 엉뚱하게 돌 수 있다(N-1). 가린 동안 관찰을 멈추고 보일 때 한 번 맞춘다. E2E가 지킨다.
- **메모리**: pdf.js 보기 4개의 캔버스. 재고 넘치면 가린 보기의 캔버스를 놓거나 살려 둘 수를 줄인다(판정으로 기록).
- **마우스 옆 단추**: macOS Chromium의 `button` 3/4 전달을 Mac 러너에서 확인할 수 없으면 실기 항목으로 남긴다.
- **한 쪽씩 모드의 스크롤**: pdf.js 동작이 예상과 다르면 5절의 판정대로 정하고 기록한다.
- **세션 복원과 냉시작**: 저장된 탭이 많아도 활성 탭만 마운트해 1.5초 예산을 지킨다.
