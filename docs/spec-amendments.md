## 1. 포맷 추가: 이미지·오디오·Markdown·GitHub 저장소
- 날짜: 2026-10-22 · 근거: 합의 1c, 1c 추가(GitHub 저장소)
- 원본: 01절 확인된 요구 "PDF·EPUB·PPTX·웹·로컬 동영상", 05절 형식 표.
- 변경: 최종 범위는 원본의 포맷 + **이미지**(쪽 계열) + **오디오**(시간 계열, 튜터용 전사) + **Markdown**(가져온 `.md`, 재배치 계열) + **GitHub 저장소**(새 다섯째 계열인 코드 계열)다. 포맷은 계열로 설계하고, 계열마다 viewer 하나와 앵커 형 하나를 공유한다(쪽 / 시간 / 재배치 / 링크 / 코드, ADR-0009 2절).
- 코드 계열(GitHub 저장소):
  - 항목은 commit SHA에 고정한 저장소 스냅샷이다(revision = commit). 새 commit으로 갱신하면 새 revision이 생기고 앵커는 `ok/review/orphan`으로 재앵커된다.
  - 앵커: kind `code` `{commit, path, lineStart, lineEnd}` + 재앵커용 quote. precision은 `item`(저장소) 또는 `span`(파일·줄 범위). W3C 내보내기는 `#line=a,b`(RFC 5147).
  - 가져오기: GitHub URL → 확정한 commit의 tarball(git 불필요), 로컬 git 폴더 → HEAD commit의 스냅샷. 비공개 저장소는 나중에 사용자의 git·gh 자격 증명으로. 큰 저장소는 크기 경고, 바이너리와 LFS는 뺀다.
  - 범위: 읽기·튜터·코드 투어. 사이드바에 파일 트리, 가운데에 구문 강조가 있는 읽기 전용 코드 viewer, 열면 README와 개요(언어, 최상위 구조, 주요 파일), 줄 범위 하이라이트와 노트. 튜터는 저장소 도구 `list_tree`·`read_file(path, lines)`·`search_code`를 쓰고 `file:line` 칩으로 인용한다. 튜터 제안: 코드 투어(설명이 붙은 여러 앵커의 순서 있는 노트, CodeTour처럼 한 단계씩 넘긴다)와 구조 안내(노트). 심볼·의존성·호출 그래프(tree-sitter)는 나중의 확장이다.
  - **경계**: 저장소 코드는 불신 입력이다. 빌드·실행·설치하지 않고 글로만 다룬다. 튜터에게 셸이 없다. 프롬프트 주입은 AC19에 들어간다. 편집·PR·이슈는 없다. 공부 도구이지 GitHub 클라이언트가 아니다.
- 시점: 7절 로드맵 — 이미지 M7, 오디오 M8, 저장소 M11(README용 Markdown 렌더러 포함), Markdown·웹 스냅샷·EPUB M12, PPTX M14.
- 이미지 형식(M7c, 2026-11-08 소유자 Q1): 래스터 5종, HEIC·TIFF는 M14, SVG 제외. 래스터 5종은 PNG · JPEG · WebP · GIF · AVIF이고 파일 머리로 판별한다(확장자는 보지 않는다). 이미지 1장 = 자료 1개(14절 B).

## 2. P3 재정의: ACP 우선 백엔드
- 날짜: 2026-10-22 · 근거: 합의 3a, 3e
- 원본: 07절 "Provider adapters → remote AI / optional local engine", 13절 P3 "provider interface, fake provider, streaming·취소, RAG·인용·대화", 15절 6 "ViewerAdapter, ProviderAdapter, repository 인터페이스를 분리하라", 16절 "AI 공급자·모델 | 교체 가능한 adapter, 사용자가 선택".
- 변경: "provider adapter → 원격 AI"는 **백엔드 인터페이스**가 된다. 첫 구현은 ACP 에이전트(사용자의 구독)이고, API 키 어댑터는 나중에 같은 인터페이스 뒤에 둔다. 가짜 백엔드는 그대로 둔다(fake provider). 맥락 만들기·범위 검사·인용 검증·기억은 백엔드와 무관하게 Learn이 한다. 자세한 것은 ADR-0010.
- 그대로인 것: P3의 나머지 작업(streaming·취소, RAG·인용·대화)과 종료 조건 문구. 여기서 provider는 위의 백엔드를 말한다.
- 명세 12절 "튜터는 파일 삭제·명령 실행·비밀 읽기 도구를 갖지 않는다"는 에이전트의 내장 도구를 끄고 Learn의 읽기 전용 MCP 도구만 여는 것으로 지킨다(ADR-0010 2절).

## 3. AC11 범위 재조정
- 날짜: 2026-10-22 · 근거: 합의 3e
- 원본: "AC11 | 선택 자료 밖의 비공개 자료와 제외 기억은 provider 요청에 없다. | request payload 검증"
- 변경: Learn이 검증할 수 있는 것으로 범위를 다시 잡는다. **Learn이 에이전트에 넘기는 모든 것(프롬프트와 도구 결과)이 허용 범위 안에 있고, 에이전트의 내장 도구와 사용자 설정이 꺼져 있음을 확인한다.**
- 이유: ACP 경로에서는 에이전트가 공급사로 가는 API 요청을 직접 만든다. Learn이 볼 수 있는 경계는 Learn → 에이전트(ACP 프롬프트와 MCP 도구 결과)다.
- 추적: [`acceptance.md`](acceptance.md) AC11 행.

## 4. 키체인은 나중의 API 키 어댑터에만 필요하다
- 날짜: 2026-10-22 · 근거: 합의 3e
- 원본: 08절 "비밀키는 OS keychain에만 저장한다", 12절 "키는 OS keychain", 15절 8 "키는 keychain에 저장하고 채팅·로그·저장소에 넣지 말라".
- 변경: ACP 경로에서는 Learn이 키·토큰을 보지도 저장하지도 않으므로 키체인을 쓰지 않는다. 키체인은 나중의 API 키 어댑터에만 필요하다. 그때도 원본 규칙(키체인에만, 채팅·로그·저장소에 넣지 않음)은 그대로다.
- 관련: ADR-0003("비밀키는 DB에 저장하지 않는다(OS keychain, P3)"), ADR-0007 §6("외부 서비스 키는 P3에서 OS 키체인").

## 5. Chrome 커넥터 (새 범위)
- 날짜: 2026-10-22 · 근거: 합의 4a, 4b, 4d, 4e, 저장소 구성
- 원본: 브라우저 확장·클리퍼·커넥터가 없다. 웹은 "사용자 지정 URL을 정적 스냅샷으로 보관"(05절)과 "로컬 파일과 URL 등록 우선"(16절)뿐이다.
- **연결(4a)**: Native Messaging이 주 경로다. `learn://`는 "Learn에서 열기"만 하는 보조 경로다.
  - 설정에 "브라우저 연결" 토글을 둔다. 켜면 브라우저별 host 매니페스트(Chrome, Edge, Brave, Arc, Chromium)를 쓰고, 앱 경로가 바뀌면 다시 쓴다.
  - 작은 relay host가 꺼져 있는 Learn을 깨운다.
  - `allowed_origins`는 우리 확장 id다. 주고받기는 양방향이고, 큰 자료(PDF, 스냅샷)는 나눠 보낸다: host로 64 MiB, host에서 1 MB 이내.
- **저장소 구성**: `apps/connector`(MV3 + Vite). 메시지 계약은 `packages/domain`의 zod 스키마로 두고 앱과 함께 쓴다.
- **첫 판이 담는 네 가지(4b)**, 우선순위 순:
  1. 웹 스냅샷 + 메타데이터 + 선택한 글의 하이라이트. 스크립트를 뺀 정적 HTML에 자산을 넣는다. 메타데이터는 title / author / date / site / canonical / DOI / `citation_*`. 앱 쪽에는 샌드박스 스냅샷 viewer(스크립트 없음, 원격 로드 없음, 명세 12절 / AC09)와 웹 앵커가 생긴다.
  2. 브라우저 PDF 저장. 확장이 브라우저 세션으로 바이트를 받고, 출처 URL이 있는 보통 PDF 항목이 된다.
  3. GitHub 저장소 가져오기. 확장은 URL과 branch/commit을 보내고 앱이 받아 온다(1절).
  4. 영상 링크 + 시간. 링크 항목 + 시간 앵커이고 내려받지 않는다. 오프라인에서는 "보관 안 됨"으로 표시한다(명세 05절의 표기는 "오프라인 미보관"이다. 화면 문구는 다음 마일스톤에서 정한다).
  - 팝업의 컬렉션·태그·메모 선택은 네 가지 모두에 공통이다.
- **"Learn에서 질문하기"(4d)**: 팝업에서 세션을 시작한다. 맥락은 저장한 항목 + 선택 앵커다. 튜터가 있어야 하므로 M13이다.
- **M13 첫 작업(4e)**: macOS에서 Native Messaging 스파이크 — relay, 브라우저별 매니페스트, 앱 깨우기, 나눠 보내기.
- 배포와 라이선스: ADR-0011(SingleFile·Zotero translators를 쓸 수 있게 됨).

## 6. 오픈소스 배포, AGPL
- 날짜: 2026-10-22 · 근거: 합의 3(배포), 4c
- 원본: Learn 자체의 라이선스는 정하지 않았다. 15절 11 "의존성·변환기의 라이선스와 배포 적합성을 기록하라", 13절 P6 "라이선스".

## 8. 검색: 메타데이터 빠른 검색(M4)과 본문 검색(M7 이후)
- 날짜: 2026-10-23 · 근거: M4 소유자 결정([`superpowers/specs/2026-10-23-m4-library-design.md`](superpowers/specs/2026-10-23-m4-library-design.md) 0절)
- 원본: 07절 "FTS5로 제목·본문·자막·노트를 검색하고 한국어 검색은 정규화·부분 검색 품질을 fixture로 검증한다", 13절 P1 "…컬렉션·검색·휴지통…", 14절 AC16 "10,000개 item 메타데이터 검색 p95 300ms".
- 변경: P1의 검색은 두 단계로 나눈다. **M4는 메타데이터 빠른 검색**이다: 제목·저자·연도·출판사·원래 이름·초록·메모를 렌더러의 메모리 색인으로 찾는다(FTS5가 아니다). 한국어는 NFC·소문자 정규화, 짧은 필드의 초성, 2글자 부분 일치까지 된다 — FTS5 트라이그램의 3글자 제한이 없다(next-session P1 후보 "한국어 2글자 검색"을 이것으로 닫는다). **본문 검색**(PDF 텍스트, 자막, 노트)은 앵커(ADR-0009)와 텍스트 추출이 생기는 M7(PDF)·M8(자막)·M9(노트)에서 FTS5로 한다. 본문 조각의 저장 형식을 앵커 설계보다 먼저 정하지 않기 위해서다.
- 본문 검색(M7c, 2026-11-08 소유자 Q3): M7c: PDF 쪽 글 + FTS5 trigram, 2글자는 부분 일치 훑기, 1글자는 정보만. 빠른 검색의 범위 ▾ '정보 / 정보와 본문'으로 찾고(별도 화면 없음), 쪽 글은 파일 내용(sha) + 쪽 번호로 저장한다 — [ADR-0008](decisions/0008-body-search.md), 14절. 자막(M8)·노트(M9)의 본문과 인용 단위 `extracted_chunks`(T1)는 그대로 뒤로 간다.
- AC16의 "메타데이터 검색 p95 300ms"는 M4의 `@perf` 1만 항목 측정이 맡는다(판정은 원본대로 기준 장비). 첫 PDF 2초·MP4 3초는 그대로 P6.
- 추적: [`acceptance.md`](acceptance.md) AC16 행.
- 3.3·6절의 툴팁 "자료를 하나만 고르세요"는 M4에 자리가 없다. 선택 개수 때문에 꺼지는 앱 안의 컨트롤이 없고(메뉴는 항목을 기본 방식으로 회색 처리한다), 보여 줄 비활성 컨트롤이 없기 때문이다.

## 9. 정리: 컬렉션·태그·끌어 놓기·컨텍스트 메뉴(M5)

  - R22 목차는 모두(명세 8절의 "200항목 이상"만이 아니라) RAC Tree + Virtualizer(ListLayout) 한 길로 간다 — 손으로 쓴 VirtualOutline은 지웠다. 모양과 키보드 모델이 하나다.

  - R38 저장된 세션(`ui.tabs`)은 리더 탭마다 마지막으로 안 `title`과 `type`을 선택 필드 `known`으로 함께 싣는다(제목 300자 상한, 예전 값도 그대로 읽힌다). 탭 줄 · 창 제목 · 탭 패널 이름은 항목을 읽기 전에는 이 값을 쓰고, 읽은 뒤에는 읽은 값이 이긴다. 리더 사이드바의 세그먼트는 저장된 선택을 읽기 전에는 선택 칸 없이 비활성이고(Boot가 첫 그림 전에 읽는다) 기본값 '썸네일'을 먼저 그리지 않는다.
  - R39 PDF를 여는 중(끝난 상태가 아닌 동안)에는 항목 패널이 자리 · 폭 · 접힘 그대로 남아 항목 정보를 보이고 번역 절은 비활성으로 그려진다. 암호 · 열기 실패 · 원본 없음 · 휴지통과 동영상 리더는 패널이 없는 그대로다. 확대 필드는 저장된 자리가 놓이기 전에는 "…"이고 임시 배율을 보이지 않는다.

  - 설계안 0–7절 "너의 '추천안'대로 진행해". 목업 ①–⑧ "목업 추천대로" — 디자인 비평 뒤 컨트롤러 판정 R20–R24를 승인 답에 넣었다: R20 웹 보기 ▾의 "배경"은 펼친 묶음(머리 + 밝게 / 어둡게 / 체크무늬, 체크), 메뉴 막대는 "배경 ▸"; R21 그림에 테두리 없음, 바탕 `--image-bg-light` 93.2% · `--image-bg-dark` 17.5%; R22 이미지 탭의 사이드바는 '쪽 없음' 안내, 자동 접기 없음; R23 검색 필드 폭 240 그대로; R24 '본문 일치'의 개수는 "쪽 34개".
- **C. 소유자가 뒤집을 수 있는 명세의 판정**(J — 동작이나 화면을 고른 것만. 바이트·시험·문서의 판정 J2·J4·J31·J32·J33은 뺐다):
  - 이미지 가져오기: J1 HEIC은 `mif1`을 함께 쓰므로 호환 브랜드의 HEVC 표시로 갈라 거절한다 · J3 크기를 읽지 못해도 가져오고 그릴 수 있는지는 리더가 말한다 · J12 5,000만 화소를 넘는 그림은 항목 패널에서 미리보기 대신 아이콘 칸.
  - 이미지 리더: J5 리더에 정보 인스펙터가 없다 · J6 창에 맞춤은 작은 그림을 키우지 않는다(너비에 맞춤은 키운다) · J7 배율 5–800% · J8 배경을 고르지 않으면 앱 테마를 따른다(네 번째 메뉴 행 없음) · J9 자리는 이미지 좌표의 중심으로 기억한다 · J10 진행 100%는 그림이 한 번 보였을 때(손상 파일은 읽음으로 세지 않음) · J11 `image` 앵커는 영역 하나 · J28 화면 이름 '체크무늬' · J29 `reader.zoomPageFit`는 이미지에서 "창에 맞춤"으로 이름만 바뀐다 · J30 이미지 첫 그림 예산 500ms.
  - 본문 색인: J13 작업 키에 형식(`pdf-text-1`) · J14 최근에 가져온 PDF부터 · J15 첫 유휴 + 5초 뒤에, 작업 줄이 쉴 때만 · J16 일꾼 하나를 살려 두고 50작업마다 새로 · J17 쪽당 평균 10자 미만은 '글자 없음' · J18 한도 숫자(512 MiB · 5,000쪽 · 쪽 10만 자 · 문서 1,000만 자 · 30초 · 15분 · 3번) · J34 외부 내용 FTS 표 · J35 쪽 글의 열쇠는 판본이 아니라 sha.
  - 검색 질의와 화면: J19 낱말 사이 AND는 한 쪽 안에서 · J20 2글자 훑기를 나눠 하고 앞 요청을 취소 · J21 조각 약 50자(48토큰) · J22 본문 질의는 타자가 200ms 멈춘 뒤 · J23 화면 이름 '정보 / 정보와 본문'(승인안의 '메타데이터 / 본문 포함' 대신) · J24 결과 없음의 안심 문구는 사실일 때만 · J25 '본문 일치' 절은 항목 패널 머리 바로 아래 · J26 색인 상태는 완료가 아닐 때만(완료는 조용함).
  - 그 밖: J27 사용자가 목차를 스크롤하면 2초 동안 현재 항목을 따라가지 않는다.
- **D. 사전 판정으로 바뀐 것**(명세 본문을 이렇게 읽는다):
  - P-11 pdf.js 6.4.299는 Node 22의 vitest에서 돌지 않는다(`Promise.try`·`Uint8Array.prototype.toHex` 없음). 그래서 pdf.js를 부르는 코드는 Electron(Node 24) 안에서만 시험한다 — E2E 훅이 앱의 진짜 일꾼을 돌리고, 단위 시험은 순수 부분과 가짜 포트로 본 프로세스 관리다. 명세 17절의 "단위·E2E를 먼저"는 E2E로 읽는다.
  - P-13 `LEARN_E2E=1`이면 본문 색인은 멈춘 채 시작하고 시험이 켠다(1만 개의 가짜 PDF를 심는 성능 시험에 뒤에서 도는 추출이 끼어들지 않게). `LEARN_TEXT_EXTRACTION=run`이면 E2E에서도 켜진 채 시작한다(데모와 냉시작 증거).
  - P-22 이미지의 진행 1은 첫 그림에서 마운트마다 한 번 직접 저장한다 — 위치 저장기는 locator가 같으면 보내지 않고, 기본 locator는 열 때 만든 행과 같다.
  - P-23 '본문 일치' 행은 레지스트리 명령이 아니다(썸네일 누름과 같은 패널 동작). `CommandEnv.openAtPage`가 편집 확인 안에서 탭의 `pendingJump = { pageIndex, query }`를 두고 연다 — 편집 확인을 취소하면 점프도 남지 않는다. 명세 5.8의 "`placePage` 규칙"은 M7b의 `PdfViewHandle.place`와 `restore`의 쪽 놓기다.
- **E. 디자인 명세를 바꾼 것**(본문도 고쳤다, 명세 16절과 구현 중 판정): 1. 로드맵의 M7c 줄과 이 문서 1·8절의 줄(아래). 2. 2.4 · 6 검색 필드 맨 앞의 범위 단추(호버 2차색, 눌림·열림 1차색 — R60)와 범위마다 다른 자리표시. 3. 7.3 검색 범위 ▾, 이미지 확대 ▾, 이미지 보기 ▾(배경 묶음 + 회전), 메뉴 막대의 "배경 ▸", 보기 ▾ 두 개의 폭 232(R51). 4. 7.4 키 표의 '이미지' 범위. 5. 10.1 라이브러리의 M7c 요소 행(R13이 Task 16에 넘긴 비평 m14). 6. 10.10 이미지 리더의 요소 행과 끝 상태 '그릴 수 없음'. 7. 10.2 지원 형식 줄과 드롭 오버레이의 이미지 개수. 8. 3.1 토큰 `--image-bg-light` · `--image-bg-dark` · `--image-checker-a/-b` · `--image-focus-light/-dark/-checker`(R50), 이미지 배치(맞춤 여백 24, 창에 맞춤은 100%를 넘기지 않음). 9. 5 아이콘 `image` · `image-off`. 10. 9 문체: 화면에서 '메타데이터'는 '정보'. 그리고 10.3의 확대 필드 22/13과 비활성 툴팁 "이름 · 이유"(R46).
- **F. 컨트롤러 판정으로 동작이 바뀐 것**(M7c R번호 — 소유자가 뒤집을 수 있는 것만. 시험·측정·과정의 판정은 뺐다):
  - 이미지 리더와 배경:
    - R45 여는 동안 확대 필드와 쪽 필드는 45%로 흐리다(두 리더).
    - R46 확대 필드는 22(`--control-height-small`, 두 리더가 M7a부터 22로 나갔다), 비활성 ▾의 툴팁은 "확대 메뉴 · 이미지를 여는 중입니다"(이름 · 이유).
    - R47 너비에 맞춤은 무대 가운데의 점을 지킨다 — 긴 그림은 위 끝이 아니라 보던 자리에서 보인다(위에서 시작하길 원하면 바꾼다).
    - R50 이미지 무대의 포커스 링은 앱 테마가 아니라 고른 배경을 따른다(모든 바탕에서 3:1).
    - R51 PDF와 이미지의 보기 ▾는 확대 ▾처럼 232 폭이다.
    - R55 항목 패널 '읽기' 절의 "✓ 완료"는 본문 크기(13), "찾을 수"는 한 줄에 묶는다.
  - 검색 화면:
    - R56 결과 없음의 "·PDF 본문"은 `search:body`가 `searched: true`일 때만(범위가 '정보와 본문'이어도 1글자뿐이면 붙지 않는다).
    - R58 포인터로 연 범위 메뉴는 어느 행에도 포커스를 두지 않는다(확대 ▾·보기 ▾와 같음).
    - R59 다른 것이 보이지 않는 채 본문 답이 300ms를 넘으면 표 자리에 "찾는 중…", 질의가 캐시에 있으면 기다리지 않고 그 답을 쓴다.
    - R60 휴지통 보기는 범위와 상관없이 정보만 찾는다 — 자리표시와 결과 없음도 '정보'의 것이고 메뉴는 저장된 범위를 그대로 보인다.
    - R63 휴지통 자료와 원본이 없는 자료에는 본문 상태 줄이 없다("색인하는 중"이 거짓이 되므로).
    - R65 '본문 일치' 절은 표처럼 지금 입력한 질의를 열쇠로 하고 앞 답을 남기지 않는다(타자 한 묶음에 아래 절이 한 번 움직인다).
    - R66 `search:pages`가 실패하면 절을 보이지 않는다(새 문구 없음, J24).
    - R67 열기에 실패한 '본문 일치' 행은 나중에 그 탭을 열 때 쪽을 남기지 않는다.
    - R68 잘린 색인은 '본문 일치'에 "앞 5,000쪽까지 색인했습니다."를 행 아래에, 일치가 없으면 그 줄만 보인다.
  - 본문 색인:
    - R11 쪽 글 정리는 표시 문자와 공백 아닌 제어 문자를 공백으로 바꾸지 않고 지운다(두 낱말 사이의 제어 문자는 두 낱말을 잇는다 — 실제 PDF에서는 드물다).
    - R29 휴지통·영구 삭제가 멈춘 추출은 시도를 세지 않는다(휴지통과 복원을 오가도 `gave-up`이 되지 않는다).
    - R30 진행 알림은 1초에 최대 한 번이고, 대기열이 비거나 작업이 포기될 때 마지막 한 번 — 마지막 알림이 1초까지 늦을 수 있다.
    - R31 정상 종료는 도는 작업을 시도를 돌려준 채 대기열로 되돌린다(SIGKILL은 시도 한 번).

    - R40 링크 뒤 리더의 첫 스크롤이 목적지의 늦은 글 층과 같은 작업에 겹쳐도 끌려가지 않는다.
    - R42 탭을 바꿔도 라이브러리 패널이 다시 마운트되지 않는다(스크롤과 포커스를 지킨다).
    - R44 쪽을 넘긴 바로 뒤의 정상 종료나 ⌘W도 그 쪽을 기억한다.
    - R53 리더에서 돌아온 항목 패널의 '읽기' 절은 위치·열기 알림으로 새로 읽는다(목록 행마다 읽지 않는다).
