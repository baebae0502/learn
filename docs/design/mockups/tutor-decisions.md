# 튜터 목업 — 소유자가 정할 것 (명세 4절 + 1차 비평)

- 목업: `tutor.html`(쿼리는 파일 머리 주석). 렌더: `pnpm mockups:render -- --only tutor` → `docs/design/renders/`(커밋 안 함), 대조표 `docs/design/contact-sheet-tutor.jpg`. 1440×900 @2x, 레이아웃 B. ★ = 디자이너 권장(기본값).
- 렌더 이름은 모두 `tutor--` 다음에 오고 `-light-B.png`로 끝난다(예: `5-width-340` = `tutor--5-width-340-light-B.png`).

**소유자 결정 2026-10-27** — 1: 380 · 2: 말풍선 · 3: 답 없음("42쪽" 잠정) · 4: 패널 카드 · 5: 왼쪽 사이드바 · 6: B. 아래 선택지와 이유는 기록으로 남기고, 각 절 머리에 답을 적는다. 반영은 디자인 명세 2.6.

## 1. 튜터 모드 폭과 범위 (`?width=`)
**결정: 380 (320–560), 모드마다 따로 기억(정보 320 · 튜터 380).**
| 340 | ★ 380 | 440 |
|---|---|---|
| `5-width-340` | `5-conversation` | `5-width-440` |
- 권장: **기본 380, 범위 320–560.** 1440 창에서 리더가 820이라 A4 쪽이 100%로 들어간다(440은 91%). 340은 번호 목록과 인용 칩이 자주 줄을 바꾼다.
- 함께 정할 것: 폭을 모드마다 따로 둘지(★ 2.5대로 정보 320 · 튜터 380 — `1-mode-info`), 하나로 둘지(Xcode 인스펙터). 따로 두면 모드를 바꿀 때 리더가 60 넓어지고, "자동 맞춤"이면 쪽을 다시 맞추고 고정 비율이면 쪽이 옆으로 밀린다.

## 2. 메시지 모양 (`?msg=`)
**결정: 말풍선 — 디자이너 권장(문서식)을 소유자가 바꿨다.** 말풍선이 목업의 기본이고, 문서식은 `?msg=doc`(`5-msg-doc`, `5-msg-doc-top`)로 남는다.
| 문서식(★ 디자이너 권장, 왼쪽 정렬, 사용자 메시지만 옅은 면) | 말풍선(양쪽, 소유자 결정) |
|---|---|
| `5-msg-doc`, 처음부터 `5-msg-doc-top` | `5-conversation`(기본), 처음부터는 `?scroll=top` |
- 권장: **문서식.** 답은 긴 문단·번호 목록·인용 칩이라 380에서 말풍선 여백(폭의 약 14%)이 아깝고, 공부 노트처럼 읽힌다. 말풍선 안의 인용 칩은 바탕을 `--bg-content`로 바꿔야 면 위에서 보인다(사용자 말풍선과 튜터 말풍선 모두).

## 3. 인용 칩 표기 (`?cite=`)
**결정: 답 없음 — 권장 "42쪽"을 잠정 기본으로 둔다.**
| ★ "42쪽" | "p. 42" | 아이콘 + 숫자 |
|---|---|---|
| `6-citation` | `6-cite-p` | `6-cite-icon` |
- 권장: **"42쪽".** 앱의 단위 규칙(명세 9 "68쪽")·도구 칩("41–42쪽 읽음")·쪽 입력과 같은 말이고, 시간 인용 "18:20"과 짝이 된다. 인용은 쪽 단위로만 검증되므로 누르면 그 쪽으로 가서 쪽 둘레를 잠깐 표시한다(문단을 짚지 않는다).

## 4. 동의 화면의 자리 (`?consent=`)
**결정: 튜터 패널 안의 카드.**
| ★ 튜터 패널 안의 카드 | 메인 창의 시트 |
|---|---|
| `2-consent`, 나중에 뒤 `2-consent-later` | `2-consent-sheet` |
- 권장: **패널 안의 카드.** 튜터가 생길 자리에서 묻고, 동의 전에도 리더를 그대로 쓴다(축 A). 내용은 두 안이 같다. 시트는 급하지 않은 선택에 창 전체를 막는다.

## 5. 세션 목록의 자리 (`?sessions=`)
**결정: 왼쪽 사이드바.**
| | ★ 왼쪽 사이드바 | 튜터 패널 머리의 목록 단추 |
|---|---|---|
| 렌더 | `9-sessions`, `library`, `9-sessions-empty`, `9-delete` | `9-sessions-panel` |
| 이 자료 / 모든 자료 | 리더 사이드바 "세션" 칸 / 라이브러리 사이드바 "세션" 묶음(자료 5개 × 3개) | 목록 머리의 세그먼트 |
| 찾기 | ⌘K 팔레트에 세션 결과를 더함(제안) | 목록 안 찾기 필드 |
| 이름 바꾸기 · 삭제 | 제자리 · ⌘⌫와 컨텍스트 메뉴(둘 다 같음) | 같음 |
- 권장: **왼쪽 사이드바.** 명세 2.5와 Codex 스레드 목록의 자리이고, 튜터 패널은 대화 하나에 집중한다. 세션이 자료 아래 묶여 축 B가 보인다.

## 6. 단축키 — 모드와 왼쪽 세그먼트 (1차 비평 minor 8)
**결정: 가안 B.**
- 가안 A(지금 목업): 정보 ⌥⌘1 · 튜터 ⌥⌘2(Xcode 인스펙터 관례). 지금 키 맵과는 부딪치지 않지만, 미리보기는 ⌥⌘1–6을 왼쪽 사이드바 보기(내용만 · 썸네일 · 목차 · 하이라이트 및 메모 …)에 쓴다(macOS 실기 확인 필요).
- 가안 B: 왼쪽 세그먼트를 미리보기처럼 ⌥⌘2 썸네일 · ⌥⌘3 목차 · ⌥⌘4 필기 · ⌥⌘5 세션, 모드는 ⌃⌘1 정보 · ⌃⌘2 튜터.
- 권장: **B** — Learn 리더의 왼쪽이 바로 미리보기의 그 묶음이다(렌더 툴팁은 B: 정보 ⌃⌘1 · 튜터 ⌃⌘2). ⌥⌘I는 모드와 무관하게 "오른쪽 패널 보기/가리기" 하나로 부른다.

## 아직 정하지 않은 것 (T1 계획에서)
소유자가 답하지 않았다. 아래는 목업의 제안일 뿐 결정이 아니다.
- 좁은 창: 명세 2.5의 "튜터 목업 — 승인 전" 표(내용 최소 = 라이브러리 520(M4) · 리더 T1 440 · M9 640, macOS SF에서도 같음. 튜터만 먼저 320으로 줄고 라이브러리 1080 · 리더 T1 1000 · M9 1200 아래에서 접힘 — 정보는 M4대로 줄지 않고 접힘, 나중에 펼친 쪽이 이김, 960에서 리더 720/580). 렌더 `10-narrow`, `10-narrow-open`, `10-narrow-960`.
- 실패: 답 전에 실패하면 질문이 입력창으로 돌아가 ↩ 하나로 다시 보내고, 답 도중 실패만 "다시 보내기"를 둔다. 자동 재전송은 없다.
- 세션: 이름은 첫 질문(T1, 사용자가 바꿈 — 바꾸기 전에는 패널 머리에 날짜만). 삭제는 확인 시트(`showMessageBox`, 기본 단추 취소) 뒤 바로 지움 · ⌥⌘⌫ — 자료처럼 휴지통을 거치게 하면 ⌘⌫ + 되돌리기 토스트로. 세션 내보내기(Markdown)의 마일스톤(지금 "미정").
- 에이전트: 로그인 안내 문구("터미널에서 claude를 실행하고…")는 T1의 설정 격리(`CLAUDE_CONFIG_DIR`·`CODEX_HOME`) 결정에 따라 바뀐다. API 키로 도는 에이전트에 셸 환경 변수를 넘길지(macOS GUI 앱은 셸 환경을 물려받지 않는다)도 T1에서 정한다. 다시 찾는 동안 이미 있는 목록은 지우지 않고 비활성으로 둔다.
- 시간 표기: 세션 행에는 시간을 쓰지 않는다(날 묶음 + 툴팁) — 명세 9의 날짜 형식은 툴팁에.
- "기억 0"과 동의 문구의 "관련 기억": 원 명세 12절대로 T1부터 보일지, 기억이 생기는 M10부터 보일지.
- 가짜 백엔드의 이름(데모 관객 앞의 "가짜"), 확인 문제 카드가 정답을 처음부터 보일지(M9).
