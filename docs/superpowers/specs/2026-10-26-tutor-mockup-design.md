# 튜터 목업 설계 (M5와 병행, T1의 선행 게이트)

- 상태: 초안 (2026-10-26). M5 명세 17절이 정한 별도 명세다. 목업 자체는 소유자가 승인한다.
- 위 문서: [`../../next-session.md`](../../next-session.md) "튜터 목업", [ADR-0010](../../decisions/0010-tutor-backend-acp.md)(튜터 백엔드 ACP, 특히 1·2·3·7절과 "검증 (T1)"), [`../../design/design-spec.md`](../../design/design-spec.md) 2.5(오른쪽 슬롯 [정보 | 튜터]), [`../../spec-amendments.md`](../../spec-amendments.md) 2–4절, 원 명세 `docs/spec.html` 07·10·12·15절, [`2026-10-26-m5-organize-design.md`](2026-10-26-m5-organize-design.md) 17절.
- 이 문서는 무엇을 그릴지와 승인 절차만 정한다. 모양은 목업이 정하고, 승인된 목업의 규칙은 T1 계획 전에 디자인 명세의 새 절(2.6 "튜터")과 6절 부품 표로 옮긴다.

## 1. 목표와 완료 조건

T1(작은 튜터)의 화면을 구현 전에 정한다. M1처럼 실제 토큰 위의 HTML 목업으로 그리고, 내부 디자인 비평 뒤 소유자가 승인한다.

완료 조건:
1. 2절의 화면·상태가 모두 `docs/design/mockups/tutor.html`(라이트·다크)에 있고, `pnpm mockups:render` 렌더(1440×900 @2x)와 Mac `mockups` suite 렌더가 있다.
2. 내부 디자인 비평(opus, `review-rubric.md`)에서 blocker·major가 0건이다.
3. 4절의 결정 목록을 소유자가 정했다(목업을 claude.ai 비공개 Artifact로 게시하고, 대조표 PNG와 함께 보낸다). 수정은 최대 2회.
4. 별도 PR(`tutor-mockup`)로 열고, 병합은 소유자가 정한다. M5 병합의 조건이 아니다.

## 2. 그릴 것 (화면 · 상태)

모든 상태는 라이트·다크 둘 다. 자리는 리더(PDF) 옆 오른쪽 슬롯의 튜터 모드가 기본이고, 라이브러리 보기에서의 모습은 한 장만 그린다.

| # | 화면 · 상태 | 내용 | 근거 |
|---|---|---|---|
| 1 | 모드 전환 | 인스펙터 머리의 [정보 \| 튜터] 전환(이때부터 그린다), 모드마다 단축키 자리, 보기 종류마다 마지막 모드 | 디자인 명세 2.5 |
| 2 | 첫 사용 동의 | 튜터를 처음 켤 때: 에이전트가 사용자의 구독으로 돈다는 것, 보내는 범위(현재 질문 + 고른 구간 + 허용된 검색 근거 + 관련 기억, 라이브러리 전체는 보내지 않음), 에이전트의 파일·셸 도구는 꺼짐, 동의 / 나중에 | 원 명세 12절, ADR-0010 2·3절 |
| 3 | 에이전트 고르기 | 감지된 에이전트 목록과 상태(준비됨 · 로그인 필요 · 설치 안 됨 · 지원하지 않는 판), 로그인은 에이전트 자신의 흐름(터미널 안내 문구), 가짜 백엔드는 개발·데모에서만 다른 표시로 | ADR-0010 1·4절 |
| 4 | 빈 세션 | 지금 자료 이름, 무엇을 물을 수 있는지 한두 줄, 입력창 | — |
| 5 | 대화 | 사용자 메시지(고른 구간 첨부 칩 포함), 튜터 답(본문 + 인용 칩), 스트리밍 중(커서, 중지 단추), 도구 칩("12–14쪽 읽음"), 요청마다 보낸 범위 줄("자료 1 · 발췌 2 · 기억 0") | 원 명세 10·12절, AC10 |

| 7 | 제안 카드 | 노트(M9) · 확인 문제(M9) · 기억(M10) 카드의 모양과 "노트로 저장"·"고치기"·"버리기" — 마일스톤 배지(`?ms=1`)로 T1 밖임을 표시 | ADR-0010 2절 "제안" |
| 8 | 실패 | 오프라인, 에이전트 실패, 로그인 만료: 실패한 요청은 실패로 보이고 초안은 입력창에 남고 자동 재전송은 없다, "다시 보내기" | AC14, ADR-0010 "검증" |
| 9 | 세션 목록 | 왼쪽 사이드바의 "세션" 묶음(Codex 스레드처럼, 자료별·최근), 세션 이름 바꾸기·삭제 자리 | 디자인 명세 2.5 |

- 도구 칩·인용 칩·보낸 범위 줄·제안 카드는 부품 보드(`components.html`의 새 묶음 "튜터")에도 상태별로 놓는다(기본 · 호버 · 포커스 · 비활성 · 검증 안 됨).
- 문구는 실제 문구로 쓴다(합니다체, 원인 + 다음 행동). 에이전트 이름 표기는 ADR-0010 5절의 이름 규칙을 지킨다(우리 기능 이름에 공급사 제품 이름을 쓰지 않는다 — 에이전트 목록은 감지된 프로그램을 그 이름으로 가리킬 뿐이다).

## 3. 형식

- M1과 같다: `docs/design/mockups/tutor.html`이 `assets/{icons,data,mockup,views}.js`와 실제 `tokens.css`를 쓰고, `?theme=dark`, `?state=<2절의 #>`, `?width=<튜터 폭>`, `?ms=1`(마일스톤 배지)을 받는다. Mac 크롬(신호등·비브런시)은 그려 넣고 "simulated"로 표시한다.
- 렌더: `pnpm mockups:render`(→ `docs/design/renders/`, 커밋 안 함)에 `tutor` 페이지를 더하고, Mac `mockups` suite도 돌린다(시스템 글꼴 확인).
- 대화 내용 예시는 목업 데이터(`assets/data.js`)의 기존 자료(분자생물학 · 신호 전달 PDF)를 쓴다.

## 4. 소유자가 목업을 보고 정할 것

| 결정 | 목업이 보이는 안 |
|---|---|
| 튜터 모드 폭과 범위 | 340 · 380 · 440 세 폭의 렌더(`?width=`), 범위 후보 320–560 |
| 메시지 모양 | 말풍선(양쪽) / 문서식(왼쪽 정렬, 사용자 메시지만 옅은 면) |
| 인용 칩 표기 | "12쪽" · "p. 12" · 아이콘 + 숫자 |
| 동의 화면의 자리 | 메인 창의 시트 / 튜터 패널 안의 카드 |
| 세션 목록의 자리 | 왼쪽 사이드바 묶음 / 튜터 패널 머리의 목록 단추 |

## 5. 절차와 일정

- 작업 트리 `.worktrees/tutor-mockup`, 브랜치 `tutor-mockup`(main에서). M5 구현과 나란히 디자인 에이전트(opus) 하나가 만든다. 동시에 도는 무거운 에이전트는 둘(M5 구현 하나 + 목업 하나)이다.
- 순서: 이 명세 → 목업 초안(2절 전부) → 내부 비평과 수정 → Linux·Mac 렌더 → claude.ai 비공개 Artifact 게시 + 대조표 PNG + 4절 결정 목록을 소유자에게 → 소유자 결정 반영(최대 2회) → PR.
- 승인 뒤 할 일(T1 계획의 입력): 디자인 명세 2.6 "튜터"와 6절 부품 표, 튜터 모드 폭(2.5의 "약 380"을 확정 값으로), 모드 단축키, `next-session.md`의 "튜터 목업" 줄 닫기.
