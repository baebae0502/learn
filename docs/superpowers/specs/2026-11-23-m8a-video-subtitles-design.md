## 1. 목표와 완료 조건

- 강의 영상을 우리 재생 컨트롤과 키로 보고, 자막을 붙여 화면에서 읽고, 왼쪽 대본에서 문장을 눌러 그 시각으로 간다.
- 라이브러리 빠른 검색이 자막까지 찾고, 일치한 시각에서 영상을 연다.
- 완료 조건:
  - Linux CI 녹색, Mac `all`(증거·기능 E2E·데모 영상), Mac 디자인 비평 blocker/major 0건(**라이트·다크 프레임 모두** — 처음부터 Mac 증거 suite가 두 테마를 찍는다, T1a 교훈).
  - 재생: 재생·정지·±10초·±5초·한 프레임·속도 0.5–2×·음소거·음량·스크러버 끌기와 호버 시간이 마우스와 키로 되고(E2E, 한글 입력 상태 포함), 속도·음량·음소거는 다시 실행해도 같다(E2E).
  - 자막: 세 길로 붙고(E2E), UTF-8·UTF-8 BOM·UTF-16 LE/BE·CP949 자막이 같은 큐가 되며(단위 + E2E 하나), 깨진 파일은 붙지 않고 이유를 보인다(E2E). 트랙 고르기·끄기(C)·제거와 되돌리기(E2E), 자료마다 고른 트랙과 켬·끔을 다시 실행 뒤에도 기억한다(E2E).
  - 대본: 클릭과 ↩로 그 시각으로 가고(재생 상태 유지), 검색 개수와 ↩·⇧↩ 이동, 현재 위치 따라가기(직접 스크롤하면 꺼짐)가 된다(E2E). 큐 2,000개에서 스크롤 프레임 p95 ≤ 16.7ms(14절).
  - 자막 본문 검색: '정보와 본문' 범위가 자막도 찾고, 항목 패널 '본문 일치'가 시간 행("18:20")을 보이며, 누르면 그 시각에서 영상이 열리고 대본 검색에 질의가 들어간다(E2E). 휴지통 자료는 빠지고, 영구 삭제하면 큐 글도 지워진다(E2E).
  - 전체 화면: F와 단추로 들어가고 나오며, **빠르게 여러 번 눌러도** 창과 화면 상태가 어긋나지 않는다(E2E Linux + Mac — 지금의 darwin `test.fail()` 특성 시험을 대신한다).
  - 마이그레이션 005→006: 실데이터 v5 DB에서 모든 행·rowid가 같고 `foreign_key_check`가 빈다(단위).
  - 성능 예산(14절) 안.

## 3. 자막 해석 (main, 불신 입력)

### 3.1 위치와 모양
- 새 `packages/library/src/subtitles/`: `decode.ts`(바이트 → 글), `parse.ts`(글 → 큐), `index.ts`의 `readSubtitle(bytes: Uint8Array, name: string): SubtitleResult`.
- `SubtitleResult = { ok: true, format: 'srt' | 'vtt', encoding: SubtitleEncoding, language: string | null, cues: Cue[] } | { ok: false, reason: SubtitleFailure }`, `Cue = { startMs: number, endMs: number, text: string }`.
- 순수 함수다(파일 읽기는 부르는 쪽). vitest로 바로 시험한다.

### 3.2 형식 판별
- 내용으로 정한다: 첫 줄(BOM과 공백 뒤)이 `WEBVTT`이면 VTT, 아니면 SRT 문법으로 읽는다. 확장자는 판별에 쓰지 않고, 붙이는 길에서 후보를 거르는 데만 쓴다(`.srt`·`.vtt`, 대소문자 무시).

### 3.3 인코딩 (컨트롤러 판정 J1)
1. BOM: `EF BB BF` → UTF-8, `FF FE` → UTF-16 LE, `FE FF` → UTF-16 BE.
2. BOM이 없으면 `new TextDecoder('utf-8', { fatal: true })`.
3. 실패하면 `new TextDecoder('euc-kr')`(WHATWG `euc-kr` = CP949/UHC).
- **스파이크(계획의 Task 1)**: Electron 44 main에서 `TextDecoder('euc-kr')`가 되는지 시험 훅으로 확인한다(이 서버의 `ELECTRON_RUN_AS_NODE`로는 GTK 라이브러리가 없어 확인하지 못했다). 안 되면 빌드 때 시스템 Node(full ICU)의 `TextDecoder('euc-kr')`로 2바이트 → 코드 포인트 표를 만들어(`scripts/build-cp949.mjs`, 생성물 커밋) 같은 함수 뒤에서 쓴다. 새 런타임 의존성은 없다.
- 디코드한 글은 NFC로 정규화한다.

### 3.4 SRT
- 블록은 빈 줄로 가른다(`\r\n`·`\r`·`\n` 모두). 번호 줄은 있어도 없어도 된다.
- 시간 줄 `HH:MM:SS,mmm --> HH:MM:SS,mmm`. 소수점 `.`도 받고, 밀리초 자릿수 1–3, 시 생략(`MM:SS,mmm`)도 받는다. 뒤의 좌표(`X1:…`)는 버린다.
- 글 줄은 다음 빈 줄까지.

### 3.5 VTT
- 머리 블록의 `Language: xx`는 언어 후보로 쓴다. `NOTE`·`STYLE`·`REGION` 블록은 건너뛴다.
- 큐 식별자 줄은 있어도 없어도 된다. 시간은 `MM:SS.mmm` 또는 `HH:MM:SS.mmm`, 뒤의 큐 설정(`position:` 등)은 버린다 — 오버레이는 늘 아래 가운데다.

### 3.6 글 정리
- 태그를 지우고 글만 남긴다: `<i> <b> <u> <font …> <c.x> <v 이름> <lang> <ruby>/<rt>`(루비 글은 버림), 시각 태그 `<00:00:01.000>`, ASS 덮어쓰기 `{\an8}`류.
- 개체: `&amp; &lt; &gt; &quot; &#39; &nbsp; &lrm; &rlm;`과 숫자 개체. 그 밖의 `&…;`은 그대로 둔다.
- 줄바꿈은 지키고(최대 3줄, 넘는 줄은 마지막 줄에 공백으로 이음), 줄마다 앞뒤 공백을 지우고, 빈 큐는 버린다.
- 화면에는 **글 노드로만** 넣는다(`innerHTML`·`dangerouslySetInnerHTML` 금지).

### 3.7 한도와 실패
| 한도 | 값 | 넘으면 |
|---|---|---|
| 파일 크기 | 5 MiB | `too-large` |
| 큐 수 | 20,000 | `too-many-cues` |
| 큐 글 | 1,000자 | 잘라서 받고 `…` |
| 시각 | 24시간 미만 | 그 큐를 버림 |
| 끝 ≤ 시작 | — | 그 큐를 버림 |
| 남은 큐 0개 | — | `no-cues` |
| 디코드 실패(3.3 모두) | — | `unreadable` |

- 큐는 시작 시각 순으로 정렬한다(같으면 원래 순서). 겹치는 큐는 그대로 둔다(6.4).
- (컨트롤러 판정 J2: 2시간 강의 SRT가 약 150 KB, 큐 약 1,500개다. 5 MiB·2만 개는 그 30배 넘는 여유이고, 이 크기에서 main의 동기 해석은 수십 ms라 일꾼을 두지 않는다. 13절 시험이 상한 파일의 해석 시간을 잰다)

### 3.8 언어
- 파일 이름의 끝에서 둘째 마디가 언어 꼬리이면 쓴다: `강의.ko.srt` → `ko`, `lecture.en-US.vtt` → `en-US`, `강의.kor.srt` → `ko`(ISO 639-2 세 글자 중 `kor`·`eng`·`jpn`·`zho`·`chi`·`deu`·`ger`·`fra`·`fre`·`spa`만 두 글자로 바꿈). 꼬리 규칙은 `^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$`.
- 없으면 VTT 머리의 `Language:`, 그것도 없으면 `null`.
- 화면의 이름은 렌더러가 `Intl.DisplayNames(['ko'], { type: 'language' })`로 만든다("한국어", "영어", "영어(미국)"). 언어가 없으면 "자막 1", "자막 2"(트랙 순서), 같은 이름이 둘이면 뒤 것에 " 2"를 붙인다.

## 4. 데이터 — 스키마 v6

### 4.1 마이그레이션 006 (`migrations/006-subtitles.ts`, 이름 `subtitles`)
새 표만 더하므로 `foreignKeysOff`가 필요 없다.

```sql
CREATE TABLE subtitle_tracks (
  item_id TEXT NOT NULL,
  asset_id TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'subtitle' CHECK (role = 'subtitle'),
  language TEXT CHECK (language IS NULL OR length(language) BETWEEN 2 AND 35),
  position INTEGER NOT NULL CHECK (position >= 0),
  created_at TEXT NOT NULL,
  PRIMARY KEY (item_id, asset_id),
  FOREIGN KEY (item_id, asset_id, role) REFERENCES item_assets(item_id, asset_id, role) ON DELETE CASCADE
);
CREATE INDEX subtitle_tracks_asset ON subtitle_tracks(asset_id);

CREATE TABLE cue_texts (
  id INTEGER PRIMARY KEY,
  sha256 TEXT NOT NULL CHECK (length(sha256) = 64),
  cue_index INTEGER NOT NULL CHECK (cue_index >= 0),
  start_ms INTEGER NOT NULL CHECK (start_ms >= 0),
  end_ms INTEGER NOT NULL CHECK (end_ms > start_ms),
  text TEXT NOT NULL,
  UNIQUE (sha256, cue_index)
);
CREATE INDEX cue_texts_time ON cue_texts(sha256, start_ms);
CREATE VIRTUAL TABLE cue_texts_fts USING fts5(
  text, content = 'cue_texts', content_rowid = 'id', tokenize = 'trigram remove_diacritics 2'
);
-- cue_texts_ai / _ad / _au: page_texts와 같은 세 트리거
```

- 자막과 영상의 연결은 지금 있는 `item_assets(role = 'subtitle')`가 맡고, `subtitle_tracks`는 그 행의 언어·순서를 든다. 연결 행을 지우면 트랙 행이 따라 지워진다(복합 외래 키 — `item_assets`의 기본 키가 `(item_id, asset_id, role)`이다).
- (컨트롤러 판정 J3: 큐를 `page_texts`에 섞지 않고 시간 열쇠의 표를 따로 둔다 — ADR-0008과 `next-session.md`가 M8에 남긴 선택. 쪽 열쇠와 시간 열쇠를 한 표에 넣으면 두 질의가 모두 종류를 가려야 하고, M8b의 `read_transcript`가 시간 범위로 읽기 쉬운 색인 `cue_texts_time`이 따로 필요하다)
- (컨트롤러 판정 J4: 큐는 **붙이는 트랜잭션 안에서** 쓴다. M7c의 추출 작업 길(`jobs`)을 쓰지 않는다 — 자막은 작고, 깨진 파일을 붙이기 전에 거절해야 하며, 작업 줄을 기다릴 이유가 없다. 같은 sha의 큐가 이미 있으면 그대로 쓴다(`INSERT … ON CONFLICT(sha256, cue_index) DO NOTHING`)
- 리더는 큐를 **DB에서** 읽는다. 자막 파일은 붙인 뒤에는 보관·백업·내보내기용이다.
- `LATEST_SCHEMA_VERSION`은 `MIGRATIONS`에서 유도되므로 6이 된다. 열 때 `.pre-v6.bak`을 남긴다(기존 실행기).

### 4.2 자산과 판본
- 자막 자산은 언제나 관리형 사본이다(영상이 외부 연결이어도 — 소유자 결정). 가져오기의 관리형 원본과 같은 길(스테이징 → 해시 → 원자적 rename, `assets` 행 + `source_revisions` 행)로 들이고, `item_assets`에 `role = 'subtitle'`로 잇는다.
- 같은 sha의 자막 자산이 이미 있으면 그 자산을 다시 쓴다(디스크의 파일 하나). 같은 영상에 같은 sha를 또 붙이면 아무것도 하지 않고 "이미 붙어 있는 자막입니다"를 보인다.
- **중복 검사 주의**: `Importer.settle`의 중복 판정(`findAssetsBySha` + `itemIdsForAsset`)은 역할을 가리지 않는다. 중복 판정이 원본 역할의 연결만 보게 해, 자막과 바이트가 같은 파일을 가져올 때 그 영상의 "중복"으로 잡히지 않게 한다(`library-check.ts:148`의 판정도). 자산 재사용(같은 sha의 행 찾기)은 그대로 둔다. 단위 시험으로 지킨다.

### 4.3 휴지통 · 영구 삭제 · 백업
- 영상을 휴지통에 넣어도 자막 행은 그대로다(자료가 있다). 본문 검색은 휴지통 자료를 빼는 기존 조건을 따른다.
- 영구 삭제: `removeItems`가 이미 역할과 상관없이 자산을 모으고, 남은 연결이 없는 자산만 지운다(`trash.ts:125,149`). sha에 자산이 하나도 남지 않으면 `page_texts`를 지우는 줄(`:173-177`) 옆에서 `cue_texts`도 지운다.
- 백업: `allAssets()`가 모든 자산을 복사하므로 자막 사본은 이미 들어간다. 매니페스트 개수에 선택 항목 `subtitleTracks`를 더한다(복원 뒤 일치 확인 — AC15 방식).
- 라이브러리 점검(M6): 자막 사본이 없거나 해시가 다르면 그 영상의 제목으로 보고한다. 큐는 DB에 있으므로 리더는 그대로 동작한다.

### 4.4 자료마다의 자막 상태와 앱 전체 설정
- 고른 트랙과 켬·끔은 **영상의 읽기 위치 locator**에 둔다: `{ kind: 'video', timeMs, captions?: { assetId: string, on: boolean } }`. 옛 값(`captions` 없음)도 유효하다. (컨트롤러 판정 J5: PDF의 확대·회전·보기 모드도 locator에 있다 — 같은 선례. 따로 표를 두지 않는다)
- 기본 트랙: `captions`가 없거나 그 자산이 더는 붙어 있지 않으면, 언어가 `ko`인 첫 트랙, 없으면 순서가 처음인 트랙을 켠다. (컨트롤러 판정 J6: 소유자가 한국어 사용자다 — 영어 + 한국어 자막이면 한국어가 먼저 보인다)
- 트랙을 바꾸거나 C를 누르면 위치 저장을 바로 내보낸다(`flush`).
- 앱 전체 설정(`SETTINGS`, ADR-0007): `video.playbackRate`(0.5 · 0.75 · 1 · 1.25 · 1.5 · 1.75 · 2, 기본 1), `video.volume`(0–1, 기본 1), `video.muted`(기본 false).
- 대본의 "현재 위치 따라가기"는 **저장하지 않는다** — 탭을 열 때마다 켜진다(7.3).

### 4.5 앵커 (ADR-0009 — 새 데이터 객체는 모두 앵커로 주소를 가질 수 있다)
- 큐는 그 영상 판본의 `video` 앵커(`startMs`/`endMs`, ADR-0002)로 가리킬 수 있다. 큐 글의 근거는 자막 자산의 판본이다. M8a는 앵커를 만들지 않고, M8b의 시간 인용이 이 길을 쓴다.

## 5. 자막 붙이기

### 5.1 리더의 "자막 파일 추가…"
- 자막 ▾의 항목과 "자막 없음" 빈 상태의 단추. main이 열기 패널을 시트로 띄운다(`showOpen`과 같은 길, 필터 "자막(SRT · VTT)": `srt`, `vtt` + "모든 파일"). 여러 파일을 한 번에 고를 수 있다.

### 5.2 같이 고른 같은 이름 묶기
- 가져오기 길(`library:pickAndImport`·`library:import`)의 묶음 하나 안에서 짝을 짓는다. `createImportQueue().enqueue(batch)`가 경로를 `Entry`로 바꾸기 전에 짝을 찾는다.
- 짝 규칙: 자막의 줄기(확장자를 뗀 이름)가 영상의 줄기와 같거나, 영상 줄기 + `.` + 언어 꼬리(3.8)다. 비교는 NFC + 대소문자 무시. 자막 후보는 확장자 `.srt`·`.vtt`인 파일이다.
- 영상 항목을 가져온 뒤(새 자료이거나, 중복이면 이미 있는 그 자료) 그 자료에 자막을 붙인다. 영상을 가져오지 못하면 그 짝 자막도 실패 행이 된다("동영상을 가져오지 못해 자막도 붙이지 않았습니다").
- 짝이 없는 자막 파일은 실패 행이다: "자막 파일은 동영상에 붙입니다", 공통 안내 "동영상 탭에 끌어 놓거나 자막 ▾의 '자막 파일 추가…'로 붙이세요." 자막만 끌어 놓은 경우도 같다.
- 가져오기 성공 토스트는 "자료 2개를 가져왔습니다 · 자막 3개"처럼 자막 수를 덧붙인다.
- 열기 패널의 미디어 필터(`IMPORT_FILTERS`)에 `srt`·`vtt`를 더한다(함께 고를 수 있게).
- **500개 나누기**: 렌더러의 `importRunner`가 끌어 놓은 경로를 500개씩 나눌 때, 같은 줄기의 자막을 그 영상과 같은 호출에 넣는다(묶음 순서를 줄기별로 정렬한 뒤 나눔). 그래서 끌어 놓은 수와 상관없이 짝이 유지된다.
- 끌어 놓기 오버레이의 개수 요약(`summarizeDrop`)은 자막을 '기타'가 아니라 '자막'으로 센다: "파일 3개(동영상 1 · 자막 2)".

### 5.3 영상 탭에 끌어 놓기
- 지금은 문서 전체가 끌어 놓기를 막는다(`guardDocumentDrops`). 보이는 탭이 **재생할 수 있는 동영상 리더**일 때만 새 문(`dndOpen` 옆의 두 번째 문)을 연다.
- 끄는 중(`dragover`)에는 파일 이름을 알 수 없으므로 MIME으로 거른다: 모든 항목이 파일이고 MIME이 `text/vtt`, `application/x-subrip`, `text/plain`, 빈 값 가운데 하나이면 받는다. PDF·영상·이미지 MIME이 섞이면 지금처럼 놓을 수 없음 커서다.
- 받을 때 리더 영역(사이드바 오른쪽의 리더 전체)에 오버레이: 56 타일(`captions`) + "자막으로 붙이기" + "SRT · VTT 파일을 이 동영상에 붙입니다". 모양은 창 드롭 오버레이와 같은 문법(목업 게이트 13절 ④).
- 놓으면 확장자로 다시 거르고(`.srt`·`.vtt`만), 나머지 파일은 실패 행으로 보고한다("자막 파일(SRT · VTT)만 붙일 수 있습니다").

### 5.4 붙이는 흐름 (세 길 공통, main)
1. 파일 크기 확인(5 MiB) → 읽기 → `readSubtitle`.
2. 실패면 붙이지 않고 실패 행(이유별 문구, 12절).
3. 성공이면 한 트랜잭션: 자산(또는 같은 sha의 자산 재사용) → `item_assets` → `subtitle_tracks`(순서 = 지금 최댓값 + 1) → `cue_texts`.
4. 커밋 뒤 알림 `subtitles:changed { itemId }`(열린 리더·항목 패널이 다시 읽음).
5. 결과: `{ added: Track[], failed: { name, reason }[] }` → 토스트 "자막 1개를 붙였습니다"(새 트랙을 바로 켬) 또는 실패 토스트(가져오기 실패 토스트와 같은 모양).

### 5.5 제거와 되돌리기
- 자막 ▾의 "이 자막 제거"는 지금 체크된 트랙을 뗀다(`item_assets` 행 삭제 → 트랙 행 따라 삭제). 토스트 "‘한국어’ 자막을 제거했습니다 [실행 취소]".
- 되돌리기는 같은 자산·같은 순서·같은 언어로 다시 잇고, 그 자막을 다시 골라 켠다(큐는 sha로 남아 있다). (목업 비평 뒤 컨트롤러 고침 2026-11-25)
- 어느 자료에도 이어지지 않은 자막 자산은 **다음 실행의 유휴 때** 영구 삭제 길(`removeUnusedAssets` → 커밋 뒤 파일 지우기)로 치운다. (컨트롤러 판정 J7: 토스트가 떠 있는 동안 되돌릴 수 있어야 하므로 즉시 지우지 않는다. 휴지통 표에 넣지 않는다 — 자막은 휴지통의 '자료'가 아니다)

## 6. 영상 리더 v2 (승인된 `reader-video.html` 기준)

### 6.1 배치
- 위에서부터: 리더 도구 막대 44 → 무대(`--video-stage`, 두 테마 모두 거의 검정) → 재생 컨트롤 막대(`--bg-window`, 위 구분선, 목업 `.video-controls`).
- 리더 도구 막대: 오른쪽에 **자막 ▾**만 둔다. 제목은 M7b 규칙대로 탭에만 있다. 목업의 "시간 메모" 단추는 M9다(그리지 않음).
- 왼쪽 사이드바: 대본 칸(7절). 오른쪽 인스펙터는 지금처럼 없다.
- `<video>`에서 `controls` 속성을 뗀다. 무대는 포커스를 받는다(`tabIndex=0`, 접근성 이름 = 자료 제목, `aria-describedby`로 "스페이스로 재생"). F6이 무대에 닿는다(`shell/panes.ts`의 `video[controls]`를 무대로 바꿈, `keyboard.spec.ts:965` 갱신).

### 6.2 재생 컨트롤 (목업 값)
- 스크러버(높이 16, 트랙 4 → 호버·끌기 6, 손잡이 12 → 끌기 14): 재생한 곳(`--meter`), 받아 둔 곳(`buffered`), 호버하면 그 자리 시간 말풍선(`.hover-time`). 슬라이더 역할(`role="slider"`, `aria-valuetext` "18분 20초 / 52분 10초"), 포커스에서 ←/→ 5초, PageUp/PageDown 10초, Home/End.
- 줄(높이 32): 10초 뒤로(`rotate-ccw`, 툴팁 "10초 뒤로 J") · 재생/일시정지(`play`/`pause`, "재생 K · 스페이스") · 10초 앞으로("10초 앞으로 L") · 시간 "**18:20** / 52:10"(`tabular-nums`, 한 시간이 넘으면 `1:02:03`) · (빈 칸) · 속도 단추 "1.25×"(누르면 속도 ▾) · 자막 켜기/끄기(`captions`·`captions-off`, 트랙이 없으면 비활성 + 이유 "자막 없음") · 음량(음소거 단추 `volume-2`/`volume-1`/`volume-x` + 가로 막대) · 전체 화면(`maximize`/`minimize`).
- 속도 ▾(웹 팝업 메뉴, 7.3 문법): 0.5× … 2× 일곱 줄, 지금 값 ✓.
- 좁은 리더(리더 폭 < 560): 음량 막대를 접고 음소거 단추만 남긴다. 호버하면 막대가 단추 위로 뜬다.
- 여는 중(첫 프레임 전)에는 컨트롤을 비활성으로 그린다(잠시 지나가는 상태 규칙).

### 6.3 키 (디자인 명세 7.4 그대로 + J8)
| 키 | 동작 |
|---|---|
| 스페이스, K | 재생/일시정지 |
| J / L | 10초 뒤/앞 |
| ← / → | 5초 뒤/앞 |
| , / . | 한 프레임 뒤/앞(일시정지 중에만 — 재생 중에는 아무것도 안 함) |
| ⇧, / ⇧. | 속도 느리게/빠르게(0.25 단위, 0.5–2×) |
| C | 자막 켜기/끄기(트랙이 없으면 아무것도 안 함) |
| M | 음소거 |
| F | 영상 전체 화면 들어가기/나오기(6.6) |
| esc | 영상 전체 화면에서 나오기 |
| ⌘F | 대본 검색 칸으로(사이드바가 접혀 있으면 편다, 자막이 있을 때) — 기존 `reader.find`가 영상 리더에서는 이 동작을 한다 (컨트롤러 판정 J8: PDF의 ⌘F와 같은 "이 자료 안에서 찾기" — 명령과 메뉴 항목은 하나) |

- 모두 명령 레지스트리(`COMMANDS`)에 `key:` 사양으로 넣는다. 새 맥락 `video`, 새 상황 필드 `videoOpen`(재생할 수 있는 영상 리더가 보임) · `videoCaptions`(트랙 있음)을 `CommandContextState`와 `ui:reportContext`에 더한다.
- 렌더러 키맵(`useKeymap`)이 `event.code`로 비교하므로 한글 입력 상태에서도 동작한다. 입력란·IME 조합 중에는 무시한다(기존).
- **포커스 예외**: 포커스가 단추에 있으면 스페이스·↩는 그 단추의 기본 동작이다. 스크러버·음량 막대에 있으면 화살표는 슬라이더 동작이다(스크러버는 같은 ±5초).
- 메뉴 막대에는 넣지 않는다. 팔레트와 ⌘/ 시트에 키와 함께 보인다. (컨트롤러 판정 J9: Electron 메뉴의 수식 키 없는 가속기는 입력란 안에서도 먼저 잡힌다 — 한 글자 키는 ADR-0005대로 렌더러 키맵만 처리한다)
- 한 프레임 간격: 재생 중 `requestVideoFrameCallback`의 `mediaTime` 차이로 추정한 값, 추정 전에는 1/30초.

### 6.4 자막 오버레이 (목업 `.subtitle`)
- 무대의 영상 상자 안, 아래 6%, 가운데, 최대 폭 78%, 바탕 `oklch(0% 0 0 / 0.72)`, 흰 글, 굵기 500, 반경 `--radius-sm`, `word-break: keep-all`, 가운데 정렬, `text-wrap` 없음(사용자 글 — 디자인 명세 3.3).
- 글 크기는 영상 상자 높이에 비례한다: `clamp(14px, 높이 × 3.1%, 40px)`, 줄 높이 1.45(목업 720 상자의 22/32를 기준으로 한 값).
- 지금 시각에 걸린 큐가 둘 이상이면 시작 순으로 줄을 바꿔 쌓는다(최대 3줄 — 넘치면 마지막 큐들만). 한 큐도 3줄을 넘지 않는다 — 해석기가 줄을 3개로 줄이고 1,000자에서 자른다(3.6). (목업 비평 뒤 컨트롤러 고침 2026-11-25)
- 지금 큐는 재생 중 `requestVideoFrameCallback`마다 이분 탐색으로 고르고, 정지·이동 때는 `seeked`에서 고른다(14절: 큐 전환 ≤ 1프레임).
- 영상 전체 화면에서는 컨트롤이 영상 아래쪽 위에 겹친 어두운 막대(테마와 무관)이고, 오버레이는 컨트롤이 보이는 동안 그 위로 올라갔다가 컨트롤이 숨으면 아래 6%로 내려온다. 영상 상자는 움직이지 않는다. (목업 비평 뒤 컨트롤러 고침 2026-11-25)

### 6.5 자막 ▾ (디자인 명세 7.3 + 제거)
- 단추: `captions` + 지금 트랙 이름("한국어"), 꺼져 있으면 `captions-off` + "자막 끔", 트랙이 없으면 `captions-off` + "자막 없음".
- 메뉴: 트랙 목록(지금 것 ✓, 이름은 3.8) · 끄기 `C`(꺼져 있으면 ✓) · — · 자막 파일 추가… · — · 이 자막 제거(트랙이 켜져 있을 때만 켜짐; 위험 동작이라 맨 아래).
- 트랙이 없으면 메뉴는 "자막 파일 추가…" 하나다.

### 6.6 영상 전체 화면 (HTML 전체 화면 API를 쓰지 않음)
- F·단추·명령 `video.toggleFullScreen`은 main에 창 전체 화면을 요청하고(`BrowserWindow.setFullScreen`), 렌더러는 **무대 모드**로 바뀐다: 탭 줄·사이드바·도구 막대를 숨기고 무대와 컨트롤이 창을 채운다.
- 들어가기 전에 창이 이미 전체 화면(⌃⌘F)이었으면 창은 그대로 두고 무대 모드만 켠다. 나올 때도 그 상태로 돌아간다.
- 나오기: F, esc, 단추, ⌃⌘F, 신호등의 초록 단추(창이 전체 화면에서 나오면 무대 모드도 끝남).
- **전환 직렬화**: main은 전환 중(요청 뒤 `enter-full-screen`/`leave-full-screen` 사건 전)에 온 요청을 하나만 기억했다가 사건 뒤에 처리한다(마지막 요청이 이긴다). 렌더러는 main이 보내는 창 상태(`windowState` 알림)를 따라서만 무대 모드를 바꾼다.
- 컨트롤 숨김: 무대 모드에서 재생 중이고 포인터가 2초 움직이지 않으면 컨트롤과 포인터를 숨긴다. 포인터가 움직이거나, 키를 누르거나, 정지하면 다시 보인다.
- 권한: `APP_PERMISSIONS`에서 `fullscreen`을 뺀다 — 페이지가 HTML 전체 화면에 들어갈 길이 없어진다(9절).

## 8. 자막 본문 검색

### 8.1 질의 (main)
- `search:body`(정보와 본문 범위의 자료 id 집합): 지금의 PDF 쪽 글 일치에 **살아 있는 영상의 자막 큐 일치**를 합친다. 조건: `items.deleted_at IS NULL`, `items.type = 'video'`, `item_assets.role = 'subtitle'`, `subtitle_tracks` 존재.
- 낱말 규칙은 M7c 그대로(`bodyQueryWords`): 3글자 이상은 FTS5 trigram(`cue_texts_fts`), 2글자는 `cue_texts`의 부분 일치 훑기(덩어리 나눔·취소), 1글자는 정보만. 여러 낱말은 **큐 하나 안의 AND**(쪽 단위 AND와 같은 규칙).
- `search:pages` → **`search:matches`**로 이름과 모양을 바꾼다: `{ matches: Array<{ kind: 'page', pageIndex, snippet } | { kind: 'time', startMs, snippet, track: string | null }>, total }`. PDF는 지금과 같은 행, 동영상은 시간 행(시작 순, 트랙이 둘 이상인 자료만 `track` = 언어 코드). 조각 표시 `U+E000`/`U+E001`과 최대 20행 · "외 N개"는 그대로.
- 진행 줄("본문 색인 37 / 120")은 PDF만 센다 — 자막은 붙일 때 색인되므로 기다림이 없다.

### 8.2 화면
- 범위 ▾의 '정보와 본문' 설명: "PDF 본문 포함" → "PDF 본문·자막 포함".
- 결과 없음 덧붙임 "·PDF 본문" → "·PDF 본문·자막".
- 항목 패널 '본문 일치'(`BodyMatchesSection`)가 동영상에도 켜진다. 행은 "18:20" + 조각, 트랙이 둘 이상이면 "18:20 · 영어". 머리 개수는 "문장 3개"("쪽 34개"와 같은 개수 문법). (컨트롤러 판정 J10: 일치 하나가 자막 문장 하나다 — 목업 게이트에서 확인)
- 행 클릭·↩: 그 시각에서 영상을 연다(8.3).

### 8.3 시각으로 열기
- `PendingJump`를 일반화한다: `{ kind: 'page', pageIndex, query }` | `{ kind: 'time', startMs, query, track }`. `env.openAtPage` → `env.openAt(itemId, jump)`.
- 영상 리더는 걸린 이동이 있으면 위치 복원 대신 그 시각으로 가고(정지 상태, 자동 재생 없음), 그 트랙을 고르고, 대본 검색 칸에 질의를 넣어 그 큐를 지금 일치로 둔다. 열린 탭이면 그 탭에서 이동한다.

### 9.1 macOS 전체 화면 빠른 토글 멈춤 (`mac-verification.md` "HTML 전체 화면 해제 멈춤")

## 14. 성능 예산과 측정
지금 예산은 모두 그대로다(AC16: 첫 MP4 프레임 ≤ 3초, seek 오차 ≤ 500ms). 새 줄:

| 줄 | 목표 | 측정 |
|---|---|---|
| 대본 스크롤 프레임(큐 2,000개, 따라가기 꺼짐) | p95 ≤ 16.7ms | 새 `video-perf.evidence.ts`(`@perf`, `video-perf.json`) |
| 재생 중 따라가기 스크롤 + 오버레이 갱신 프레임 | p95 ≤ 16.7ms | 같은 시험, 2배속 재생 20초 |
| 큐 전환 → 오버레이 글 바뀜 | ≤ 1프레임(영상 프레임 콜백의 `mediaTime`이 큐 시작을 넘은 다음 그리기에 바뀜) | 같은 시험, 큐 40개 |
| 자막 붙이기(큐 2만 개 · 5 MiB 가까운 파일) — 해석 + 트랜잭션 | ≤ 500ms(보고값, 단위 상한 1초) | 단위 + 같은 시험 |
| 본문 검색(`search:body`, PDF 1,000 + 동영상 200 × 큐 1,000) | p95 ≤ 300ms(M7c 예산 그대로) | `search-perf.evidence.ts`에 큐 시드 더함 |
| `search:matches`(동영상) | p95 ≤ 100ms | 같은 시험 |
| 대본 검색 입력 → 강조 그리기(큐 2,000개) | p95 ≤ 50ms(빠른 검색 예산과 같음) | `video-perf` |
| 영상 탭 열기 → 첫 프레임 | ≤ 3초(AC16 그대로) | `reader-perf.evidence.ts` 기존 줄 |

- CI는 목표의 2배를 넘을 때만 실패한다(`tests/evidence/budget.ts`). Mac 값은 보고값이고 판정은 기준 장비다.

## 18. 위험
- **CP949 디코드**: Electron main의 ICU에 `euc-kr` 변환기가 없을 수 있다 → Task 1 스파이크, 안 되면 빌드 때 만든 표(3.3). 표 생성은 시스템 Node(full ICU)에 기댄다 — CI의 Node 22 공식 빌드는 full ICU다.
- **끄는 중의 MIME**: `.srt`의 `dragover` MIME이 플랫폼마다 다르다(빈 값·`application/x-subrip`·`text/plain`). 5.3이 그 셋을 받고, 놓을 때 확장자로 다시 거른다. Mac에서 실제 값을 증거로 기록한다.
- **창 전체 화면의 전환**: Linux Xvfb의 창 관리자는 전환 사건 시점이 Mac과 다르다. 직렬화는 사건 기준이고, 사건이 오지 않으면 2초 뒤 `isFullScreen()`으로 확정한다(시험이 두 플랫폼에서 지킨다).
- **`requestVideoFrameCallback`**: Chromium에 있지만 가린 탭·정지 중에는 오지 않는다 — 정지·이동은 `seeked`로 갱신(6.4).
- **한 프레임 이동의 정확도**: 브라우저는 프레임 단위 이동을 보장하지 않는다(키 프레임 사이 디코드). 오차는 보고값으로 남기고 기준 장비에서 본다.
- **SRT 방언**: 실제 파일은 규칙을 자주 어긴다(빈 줄 없는 블록, 시간 줄 앞 공백, 번호 없는 큐). 3.4의 너그러운 규칙과 단위 시험, 실패 이유 문구로 막는다. 못 읽는 파일은 붙지 않는다.
- **대본 가상화와 포커스**: 가상화한 목록에서 포커스 행이 화면 밖으로 나가면 DOM에서 빠진다 — 라이브러리 표와 같은 포커스 유지 규칙을 쓴다.
- **R48류 Mac 간헐 실패**: 새 E2E가 많다 — 조건 기다림만 쓰고 부정 확인은 양성 대조 뒤에만. 영상 재생 시각에 기대는 시험은 `currentTime`을 기다리는 조건으로 쓴다.
