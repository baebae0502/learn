# M2 — 플랫폼 기반(비시각) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. 작업마다 인터페이스·SQL·테스트 목록이 정해져 있고 코드 본문은 구현자가 TDD로 작성한다(테스트 먼저 → 실패 확인 → 구현 → 통과). **화면 모양은 바꾸지 않는다**(M3에서 적용). 단, 네이티브 메뉴·컨텍스트 메뉴·읽기 위치 기억처럼 실제로 동작하는 플랫폼 기능은 이번에 들어간다.

**Goal:** 스키마 v2, 이름공간 IPC, main→renderer 푸시 채널, 단일 명령 레지스트리 기반 한국어 앱 메뉴·컨텍스트 메뉴, 설정/환경설정 저장, 읽기 위치 기억(최소)을 만들어 M3–M9 UI가 올라설 기반을 완성한다.

**Spec:** `docs/superpowers/specs/2026-10-20-quality-phase-design.md`(M2 절, "재사용", "위험"). 상위: `docs/spec.html` 07–09, 12.

**순서:** Task 1–3은 패키지 내부(`packages/*`)만 건드려 M0·M1과 병행한다. Task 4–7은 `apps/desktop`·`tests/e2e`를 바꾸므로 **M0 병합 후** 그 위로 rebase해서 진행한다.

## Global Constraints

- 기존 전역 제약 유지: 원본 불변, renderer에 fs/shell/DB 없음, 모든 IPC는 기존 `handle()` 래퍼(발신자 URL 검사 + zod + `Result`)로, 사용자 문구는 한국어, 로그에 경로·원문 금지, 의존성 정확히 고정.
- **가짜 컨트롤 금지**: 메뉴·컨텍스트 메뉴에는 핸들러가 있는 명령만 넣는다. 아직 UI가 없는 기능(설정 화면, 팔레트, 단축키 도움말)은 메뉴에 넣지 않는다.
- 패키지 의존 방향 `domain ← db ← library ← desktop` 유지. `packages/domain`의 `*-channels.ts`, `commands.ts`는 zod를 import하지 않는다(sandbox preload 번들 최소화).
- 각 작업 종료 시 `pnpm typecheck`, `pnpm test` 통과. Task 4 이후는 `pnpm e2e:xvfb`도 통과.
